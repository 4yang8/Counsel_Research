# Q3p2_counsel 설계 이유

Q3p2는 `intent_linked`, `intent_unlinked`, `linked_prose`에서 과거 의도가 어느 발화 당시의 것이었는지 명시적으로 연결하는 효과를 살펴보는 실험이다. 이 상담사는 서로 다른 두 제안에 대한 반응을 적극적으로 확보하고, 다른 대화가 이어진 뒤 각 장면의 당시 의미와 현재 의향을 순서대로 확인한다.

2026-10-31에 질문 절차를 강화했다. 이전의 “관련 장면이 자연스럽게 생기면 확인한다”는 지침을, 미완료 단계를 매 턴 우선 수행하는 실험용 절차로 바꿨다. 현재 버전은 실제 상담의 자연스러움보다 내담자의 기억 연결을 관찰할 기회 확보에 우선순위를 둔다. 기존 기록은 당시 요청에 저장된 시스템 지침을 기준으로 해석한다.

## 적극적으로 수행하는 절차

| 순서 | 상담사가 수행할 일 |
|---|---|
| 1 | 현재 고민과 연결되는 구체적인 제안 A를 하고 반응을 받는다. |
| 2 | 다음 상담사 발화에서 대상·부담·실행 시점·대화 범위 등이 다른 제안 B를 하고 반응을 받는다. |
| 3 | 공개된 다른 내용에 관해 내담자 응답을 2회 받는다. |
| 4 | A의 실제 제안과 반응을 특정해 당시 마음을 확인한다. |
| 5 | 다음 발화에서 A에 관한 현재 의향이나 부담을 확인한다. |
| 6 | B의 실제 제안과 반응을 특정해 당시 마음을 확인한다. |
| 7 | 다음 발화에서 B에 관한 현재 의향이나 부담을 확인한다. |

각 행의 질문은 별도의 상담사 발화다. 다른 주제로 자연스럽게 돌아오기를 기다리지 않고, 간격을 확보한 뒤 재확인한다. 공개 대화에 이미 적합한 장면이 있으면 재사용한다. 두 제안의 반응은 동의·거절·망설임·정정 모두 가능하다. 비슷한 표현을 얻을 기회를 만들지만, 특정 문구나 서로 다른 의도를 내담자에게 요구하지 않는다.

이전 장면이 전혀 없는 대화에서 첫 내담자 응답 후 절차를 시작하면, 이상적인 진행은 내담자 응답 2회째에 A, 3회째에 B, 4~5회째에 간격 대화, 6회째에 A 당시 의미, 7회째에 A 현재 의향, 8회째에 B 당시 의미, 9회째에 B 현재 의향에 대한 답을 얻는 것이다. 이는 계획이며 생성 결과를 보장하는 일정이 아니다. 여기서 회차는 내담자 응답 횟수다. UI의 생성 발화 20개는 일반적으로 내담자 10개와 상담사 10개이며, 내담자 응답 20회를 뜻하지 않는다.

## 생략하거나 전환하는 경우

- 당시 이유가 이미 충분히 공개됐다면 재차 같은 이유를 묻지 않고 현재 의향으로 넘어간다.
- 이유를 말하기 싫거나 모르겠다는 답도 유효한 응답으로 받고 다음 단계로 진행한다. 속마음 공개를 성공 조건으로 삼지 않는다.
- 특정 주제에 관해 더 제안하거나 질문하는 것 자체를 거부하면 해당 장면을 건너뛴다. 제안받은 행동을 하지 않겠다는 답만으로 생략하지는 않는다. 거절도 당시 의미를 확인할 수 있는 반응이다. 대화 중단 의사나 즉각 대응이 필요한 위기는 우선한다.
- 두 표현이 비슷하지 않아도 계속 진행한다. 표현을 맞추려고 제안을 반복하거나 내담자 답을 바꾸게 하지 않는다.

## 예시와 피해야 할 질문

다음은 설계를 설명하기 위한 가상의 장면이다. 내담자가 이 표현이나 의도를 생성하도록 강제하는 시나리오가 아니다.

| 장면 | 공개 표현 | 연구자가 원본 기록에서 확인할 수 있는 당시 의도의 예 |
|---|---|---|
| 잠들기 전 짧게 기록해보자는 제안 A | “네, 해볼게요.” | 거절하기 어려워 동의했으나 실제로 할 마음은 적음 |
| 다음 상담에서 직장 이야기를 이어가자는 제안 B | “네, 그렇게 해볼게요.” | 스스로 그 이야기를 다뤄보고 싶음 |

상담사는 표의 비공개 의도를 받지 않는다. 간격 대화 후 “앞서 잠들기 전에 기록해보자는 제안에 해보겠다고 하셨는데, 그때는 어떤 마음이셨나요?”처럼 A를 특정해 묻는다. 답변 후 다음 발화에서 “그 기록을 해보자는 제안은 지금은 어떻게 느껴지세요?”처럼 현재 입장을 확인한다. 이후 B도 별도로 확인한다.

“처음에는 거절하기 어려웠고 두 번째는 진심이었던 거죠?”는 숨은 이유와 차이를 제시하므로 피한다. “두 번 다 해보겠다고 하셨으니 기록할 의지가 있으시군요”는 서로 다른 제안의 의미를 합치므로 피한다. 실제 공개 대화에 없는 예시를 그대로 인용하지 않는다.

## 구현과 사용

`basic`, `Q3p1_counsel`과 같은 단일 프롬프트 실행 경로를 사용한다. 상담사 턴마다 시스템 지침과 전체 공개 대화를 넣어 모델을 한 번 호출한다. 별도 도구·단계 제어 코드·상태·평가기는 추가하지 않는다. 절차의 진행 여부는 모델이 공개 대화를 보고 판단한다. 내담자 비공개 의도·노트·궤적·기억 조건은 상담사에게 전달하지 않는다. 시스템 지침과 공개 대화 user 템플릿은 이 폴더가 별도로 소유한다.

UI에서 내담자 버전을 `Q3p2`, 상담사 버전을 `Q3p2_counsel`로 선택한다. 세 기억 조건 모두 같은 상담사 지침과 생성 설정을 사용한다. 세션에 저장된 시스템 지침은 이후 파일 편집으로 자동 교체되지 않는다. 새 세션을 시작하고, UI에 이전 지침 초안이 남아 있으면 원본 파일을 다시 불러와 첫 문장이 “당신은 내담자 시뮬레이터의 실험을 위해 대화하는 상담사입니다”인지 확인한다.

## 분석할 때 구분할 것

- 먼저 절차 수행 여부를 확인한다. A/B 제안과 응답, 간격 응답 2회, A/B 각각의 최초 재확인과 현재 의향 질문이 실제로 생성됐는지 기록한다. 누락·중복·명시적 거부에 따른 생략을 구분한다. 모의 모델 테스트는 이 질문 절차에 대한 실제 모델의 준수율을 입증하지 않는다.
- 공개 표현의 유사성과 비공개 의도의 차이는 별개다. 원본 기록에서 실제로 다른 의도가 있었는지 확인한다. 구분할 의도가 없거나 처음부터 이유가 공개된 경우는 미공개 의도 연결 효과를 관찰하기에 제한이 있는 사례로 기록한다.
- 한 장면의 의도를 다른 장면에 잘못 적용하는지, 현재의 변화와 과거 의도를 혼동하는지 살펴본다. 이유의 공개 여부만으로 성공을 판단하지 않고 내부 판단과 후속 반응을 함께 확인한다.
- `intent_unlinked`에서도 의도 본문·전체 공개 대화·현재 노트·최신 진행 요약으로 연결을 추론할 수 있다. 차이가 없다고 명시적 연결이 항상 불필요하다고 결론 내리지 않는다.
- 질문에 답하면서 이유가 공개되면 이후 공개 대화가 기억 단서가 된다. A와 B 각각의 최초 재확인과 이후 반응을 구분한다. A에 대한 답이 B를 추론하는 단서가 될 가능성도 있다. 현재 A를 먼저 확인하는 순서이므로 두 장면이 독립적인 측정이라고 취급하지 않는다.
- 상담사가 장면을 특정하는 것은 세 조건에 공통으로 주는 질문 단서다. 실험은 모호한 질문의 대상을 찾아내는 능력보다, 특정된 장면에 맞는 당시 의도를 적용하는 능력을 살펴본다.
- 독립적으로 생성한 세 세션은 공개 대화·원본 의도·노트가 달라질 수 있다. 연결 방식의 효과를 분리하려면 같은 대화 지점·현재 노트·원본 기록에서 조건을 바꾸는 비교가 필요하다. 이 상담사는 그 재생 실험을 자동 구현하지 않는다.

실험용으로 질문을 적극 도입한 조건에서 얻은 결과다. 일반적인 상담 대화에서 같은 문제가 얼마나 자주 생기는지나 실제 상담 효과까지 입증하지 않는다. 프롬프트를 강화했어도 실제 모델의 절차 수행은 요청과 생성 기록에서 확인해야 한다.
