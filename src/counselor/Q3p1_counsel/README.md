# Q3p1_counsel 설계 이유

Q3p1은 `summary_only`, `intent_linked`, `linked_prose`에서 과거 발화의 당시 의도가 후속 판단·반응에 어떻게 반영되는지 살펴보는 실험이다. 기존 `basic` 상담사는 주로 직전 발화에 반응하므로, 과거 특정 발화의 의미가 다시 필요한 상황이 충분히 생기지 않을 수 있다. 이를 관찰할 기회를 늘리기 위해 별도 상담사 프롬프트를 만들었다.

## 수정 이유

최초 프롬프트는 과거 표현을 다시 짚을 기회를 찾도록 했지만, 실제 대화에서는 직전 내용 탐색이나 경계 존중 후 마무리로 이어지는 경우가 많았다. 동의·유보 표현이 생겨도 그것의 당시 의미가 이후 상담 방향에 중요해지는 상황으로 충분히 연결되지 않았다. 이번 수정은 단순 회상 질문의 빈도를 늘리기보다, 의미가 불분명한 이전 동의·보류를 다음 방향의 근거로 사용하기 전에 확인하도록 우선순위를 명확히 한다.

## 바꾼 질문과 후속 반응

- 이전 표현의 의미가 아직 명확하지 않다면, 이를 더 깊은 탐색·행동 제안·종결의 근거로 삼기 전에 당시 의미와 허용 범위를 열린 질문으로 확인한다. 다른 대화가 대략 2~4회 오간 뒤에는 이전 표현과 현재 다룰 범위·다음 방향을 연결하되, 필요한 확인을 시간 간격 때문에 미루지는 않는다.
- 당시 의미와 현재 선택을 구분하고, 확인 결과를 실제 후속 반응에 반영한다. 이해에 대한 동의를 실천 약속으로, 특정 내용의 보류를 상담 전체의 거절로 확대하지 않는다.
- 예: 실제로 “그냥 그렇게 두면 되는 거죠”라고 말한 대목이 있다면, 이후 방향을 정할 때 “아까 그렇게 두면 된다고 하신 건, 제가 말씀드린 내용 중 어느 부분을 받아들이신 건가요?”처럼 확인할 수 있다. 필요하면 다음 턴에서 지금 다룰 방향을 따로 제안한다. 숨은 이유를 먼저 제시하거나 특정 답을 고르게 하지 않는다.
- 현재 이야기의 깊이를 유지하려는 뜻과 상담 전체를 끝내려는 뜻을 구분한다. 공개 범위는 존중하면서도, 종결 의사가 명확하지 않은 상태에서 바로 마무리로 넘어가지 않는다. 명확한 종결 의사는 존중한다.

## 구현과 해석

`basic`과 같은 실행 경로를 사용한다. 상담사 턴마다 시스템 지침과 전체 공개 대화를 넣어 모델을 한 번 호출한다. 별도 도구·단계·상태·평가기는 추가하지 않았다. 내담자 비공개 의도·노트·궤적·기억 조건은 상담사에게 전달하지 않는다. 시스템 지침을 새로 설계했고, user 템플릿은 기본 상담사와 같은 공개 대화 형식으로 별도 파일에 두었다. UI의 상담사 버전에서 `Q3p1_counsel`을 선택하면 된다.

이 프롬프트는 기억 방식의 차이를 관찰할 상황을 유도한다. 차이가 반드시 나타나거나, 특정 기억 조건이 우수하다고 전제하지 않는다. 직접적인 당시 의도 질문이나 이유의 공개만을 성공 기준으로 삼지 않고, 과거 동의·보류의 의미가 중요해지는 후속 개입에 대한 내부 판단과 반응도 함께 본다. 질문에 답하면서 이유가 공개되면 이후에는 공개 대화 자체가 기억 단서가 될 수 있으므로, 최초 재확인과 그 이후 반응을 구분해 해석한다. 상담사 프롬프트와 생성 설정은 세 조건에서 동일하게 사용한다. 현재 상태·노트·궤적 요약에 이미 충분한 이유가 남아 있으면 차이가 없을 수도 있다. 상담 진전이나 임상적 효과를 이 프롬프트만으로 입증하는 것은 아니다.

시스템 지침은 새 세션을 만들 때 저장된다. 기존 세션의 지침은 이번 파일 수정으로 바뀌지 않는다. 수정 후 실험은 새 대화에서 최신 기본 지침을 불러와 시작하고, 구버전 실행과 구분한다. 기존 실행 기록에는 당시 지침이 보존되어 있다. 이번 수정의 행동 유도 효과는 후속 대화로 검증해야 한다.
