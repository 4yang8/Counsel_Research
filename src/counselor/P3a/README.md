# P3a · 상세 가이드 선별 서브에이전트

P3의 두 노트·노트 수정 도구·기법 선택 기준을 이어받고, 가이드 원문 조회를 별도 모델의 상황별 선별로 바꾼 비교 버전이다. 기존 P3의 파일과 세션은 유지한다.

## 사용

UI 서버를 재시작하고 브라우저를 새로고침한 뒤 **새 대화 → 실험 설정 → 상담사 → P3a**를 선택한다. 실행 스크립트와 UI 주소는 기존 상담 실습과 같다. 기존 세션의 상담사 버전은 변경하지 않는다.

## 구성

실험 설정 → 상담사 → **Reasoning token budget**에서 메인과 서브에이전트의 추론 한도를 각각 설정한다. 체크 해제는 한도 미지정이며, 서브만 체크하고 512를 입력하면 메인은 제한하지 않고 가이드 서브 요청에만 `thinking_token_budget: 512`를 보낸다. 두 한도는 서로 상속하지 않는다. 값은 세션 시작 시 저장하며, 저장된 대화를 불러오면 당시 값을 표시한다. 기존 세션에 이 설정이 없으면 두 한도 모두 미지정으로 처리한다.

예산은 상담사 모델 호출마다 적용되고 내담자 생성에는 적용하지 않는다. `max_tokens`는 추론과 최종 답변을 합친 기존 전체 출력 한도로 유지한다. C4의 메인 한도는 각 상담사 단계별 모델 호출에 적용한다. 실제 요청값은 시각화 탭의 요청 JSON에서 확인할 수 있다.

| 파일 | 역할 |
|---|---|
| `system.md` | 메인 상담 지침. P3에서 가이드 요청 부분만 변경 |
| `guide_agent.md` | 가이드 선별 담당의 시스템 지침 |
| `guides/routing.md` | 기법 선택·조정에 관한 참고 자료와 실험 적용안 |
| `guides/common.md` | 공통 상담 역량과 수행·조정 예시 |
| `guides/mi.md` | MI의 태도·과정·기술·반응별 고려사항 |
| `guides/cbt.md` | CBT의 기본 작업·특정 기술·조정·적용 범위 |
| 두 `*_template.md` | P3와 같은 초기 노트 양식. 이미 있는 파일은 덮어쓰지 않음 |
| `runtime.py` | 도구 인자 확인·별도 모델 호출·스트리밍·결과 전달 |

가이드는 [원자료 조사](../../docs/counseling_guides/03_detailed_source_review.md)를 바탕으로 한국어로 정리했다. 원자료 전체의 복제나 완전한 임상 매뉴얼은 아니다. 출처·판본·적용 대상과 실습용 가상 예시를 구분한다. 각 본문 항목에 ID가 있어 선택 결과를 원문과 대조할 수 있다.

## 실행 흐름

1. 메인은 공개 대화와 현재 두 노트로 상담 작업을 판단한다.
2. `consult_counseling_guide(guide, request)`를 호출한다. `request`의 상황 설명과 질문은 메인 모델이 작성한다.
3. 서브에이전트는 자체 시스템 지침, 메인의 `guide`·`request`, 네 상세 가이드의 **현재 파일 원문 전체**를 별도 컨텍스트로 받는다. 전체 공개 대화·노트·비공개 내담자 정보는 자동 복사하지 않는다.
4. 같은 vLLM URL·모델·thinking·temperature·top_p·max_tokens·seed 설정으로 스트리밍 호출한다. 서브에이전트에는 도구를 주지 않는다.
5. 서브에이전트가 가이드를 참고해 현재 상황에 맞는 상담 진행 방향과 다음 행동을 간결하게 제안한다. 항목 ID나 항목별 설명 형식은 요구하지 않는다. 이 출력이 메인의 `role: tool` 결과로 들어가며 메인이 노트와 최종 발화를 이어간다.

가이드 종류의 선택은 요청의 중심을 나타낸다. Python은 키워드 검색으로 본문을 줄이거나 적절한 행동을 선택하지 않는다. 네 파일을 매번 읽으며 입력·도구 결과에 문자 수 기반 절단을 적용하지 않는다. 출력 토큰 한도는 UI에서 선택한 모델 생성 설정을 따른다. 가이드 호출의 필수·조건부 기준은 P3처럼 프롬프트 지침이며 Python이 호출 순서를 강제하지 않는다.

## 기록과 UI

- 채팅에는 메인 reasoning → 위임 도구 → 서브에이전트 reasoning·상담 진행 제안 → 메인 후속 reasoning·발화를 표시한다. 서브에이전트 영역은 파란색 배경으로 구분한다.
- Raw 컨텍스트와 Workflow에서 자식 호출을 선택하면 실제 별도 입력·출력·reasoning을 확인한다. 부모 도구 호출 ID와 자식 이벤트를 연결한다.
- 세션 JSON과 이벤트 저널에 서브에이전트 기록을 저장한다. 자식 request 이벤트에는 읽은 파일 경로·SHA-256도 기록하므로 당시 본문과 출처를 대조할 수 있다.
- 최종 토큰 사용량은 메인과 서브에이전트의 합계다. 같은 턴의 메인 reasoning은 기존처럼 보존하고, 다음 턴에는 공개 대화와 최신 노트로 새 컨텍스트를 만든다.
- 실험 설정 → 상담사 → P3a에서 메인 상담 지침과 서브에이전트 프롬프트를 각각 수정·저장할 수 있다. 서브에이전트 편집란의 실행취소는 미저장 편집을 버리고 현재 원본 파일을 다시 불러온다. 저장하면 실제 `guide_agent.md`가 바뀌고 기존 세션에서도 다음 서브에이전트 호출부터 반영된다. 기존 세션의 메인 지침은 시작 당시 값으로 고정된다. 상세 가이드는 위 파일을 직접 수정한다.
- 새 버전은 런타임의 `SUBAGENT_PROMPTS`에 종류·이름·파일을 등록하고 `specification()`의 `subagent_prompts`로 편집 대상을 제공한다. UI는 현재 버전의 목록에 따라 편집란을 표시하며, 여러 서브에이전트가 있으면 선택해서 편집한다.

## 비교 범위와 검증

P3는 짧은 가이드 원문을 반환하고 P3a는 확장된 가이드를 읽는 별도 모델이 관련 내용을 선별한다. 따라서 결과 차이에는 **자료 확장과 서브에이전트 방식의 영향이 함께 포함**된다. 위임 효과만 분리한 통제 실험은 아니다.

모의 모델 테스트는 컨텍스트 경계·도구 연결·스트리밍 기록·턴 간 노트·파일 재조회·오류·중단·사용량·기존 버전 보존을 검증한다. 실제 모델의 가이드 선택 품질과 상담 발화 품질은 사용자 실험으로 별도 관찰해야 한다.
