# Q3sk · 단계별 노트 스킬

Q3를 복제한 독립 비교 버전이다. 프로필·특성/배경/노트 라우터·기억 조회·사전 신뢰 궤적·반응 판단·도구 스키마·실행 한도·저장 절차를 유지한다. Q3a/Q3b의 로컬 작업 계획은 추가하지 않는다.

## 비교하는 변경

Q3 `system.md`의 `내담자 노트 갱신` 상세 절을 원문 그대로 `skills/client-note-update/SKILL.md`로 이동했다. 메인 시스템 지침에는 노트 갱신 단계와 스킬 사용 안내를 남겼다. 상세 지침의 내용은 바꾸지 않고 제공 시점을 비교한다.

- 반응 생성: 기존 핵심 지침과 스킬의 이름·설명만 제공한다. 라우터에 스킬 본문을 주지 않는다.
- 발화 확정 후: 전체 노트를 복원하고 SKILL.md를 읽어 첫 user 입력의 별도 `실행 스킬` 영역에 상세 지침을 제공한다.
- 노트 갱신과 궤적 기록: 같은 스킬 스냅샷을 재사용한다. 재시도 때 중복으로 추가하거나 파일을 다시 읽지 않는다. 같은 턴의 reasoning·도구 호출·결과를 유지한다.
- 다음 턴: 스킬 상세 본문 없이 시작하고 다음 발화 확정 후 파일을 다시 읽는다. 이전 스킬 본문·reasoning을 자동 주입하지 않는다.

스킬은 런타임이 실행 단계에 따라 로딩한다. 모델이 load_skill을 선택하거나 별도 서브에이전트를 호출하는 방식은 아니다. 추가 모델 호출·도구 호출은 없으며 기존 update_client_notes가 실제 변경을 수행한다. System 입력을 비활성화하면 스킬 메타데이터와 본문도 제공하지 않는다.

## 파일과 저장

- `skills_runtime.py`: frontmatter 검증, 메타데이터 조회, 원문 스냅샷과 SHA-256, 모델 입력 조립.
- `skills/client-note-update/SKILL.md`: name, description을 가진 한 줄 텍스트 frontmatter와 Q3의 노트 작성 원문. 이 로더는 두 필드의 단순 형식만 지원한다.
- 완료된 `appraisals/<turn>_<id>.json`: 기존 Q3 기록에 skill_catalog, skill_loads, skill_mode를 추가한다. skill_loads에는 실제 원문·경로·해시·최초 제공 호출 번호가 있다. 실제 요청은 model_requests에 보존한다.
- 이벤트: skills 절의 catalog, loaded, committed, discarded. 실패한 시도의 로딩 내역은 실행 로그에 남고 완료 기록·내면 노트·공개 대화로 확정하지 않는다.

노트와 궤적 저장이 모두 성공해야 턴을 완료한다. 스킬을 읽거나 검증하지 못하면 해당 턴의 변경안을 폐기한다. 기존 기록을 소급 변경하지 않는다.

## UI

내담자 버전에서 **Q3sk · 단계별 노트 스킬**을 선택한다. 기존 메인/라우터 system·user 템플릿과 사전 궤적을 독립 편집하며, 궤적 아래에서 **내담자 노트 작성 스킬 · SKILL.md**를 저장·실행취소할 수 있다. 저장은 다음 내담자 생성부터 적용한다. 메인 시스템 지침은 기존처럼 세션 시작 시 값이 유지된다.

생성 과정과 내담자 노트 탭에서 해당 턴에 사용한 스킬 원문·해시를 확인한다. Raw/Workflow/Activation context는 스킬이 포함된 실제 요청을 보여 준다. 현재 파일을 편집해도 과거 턴의 사용 원문은 바뀌지 않는다.

## 검증

`tests/test_q3sk.py`는 모의 모델로 발화 전 본문 제외·발화 후 로딩, reasoning과 노트 범위 보존, 다음 턴 분리, 동일 스냅샷 재사용, 편집 격리, System 비활성화/prepend_user, 잘못된 파일과 실패 롤백을 확인한다. `tests/browser_q3sk.cjs`는 선택·편집·실행취소·생성·기록·컨텍스트·새로고침·모바일을 확인한다.

입력 토큰 감소와 노트 품질 개선은 실제 모델의 통제 실험으로 평가해야 한다. 후속 호출에는 로딩된 스킬과 같은 턴의 도구 이력이 유지되므로 전체 호출의 토큰·시간·실패와 결과 품질을 함께 비교한다.
