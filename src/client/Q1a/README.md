# Q1a · 초안과 선택적 검토

원본 `versions/Q1`을 기준으로 만든 독립 실험 버전이다. Q1의 프로필 분해 방식, 매 턴 자동 특성 라우팅, 선정 원문과 reason 전달, 공개 대화/최신 내면 노트 제공을 유지한다. Q1_s1·Q1_s2의 의미 단위 묶음·reason 제외·512 기본 예산은 사용하지 않는다.

## 실행
기존 counseling_test/run.sh로 UI를 실행하고 내담자 버전에서 Q1a를 선택한다. 서버가 이미 실행 중이면 Q1a 등록을 읽도록 재시작해야 한다. 상담사 버전은 별도로 선택한다. 추론 예산은 기본 미지정이며 UI의 공통 출력 한도와 메인/서브 추론 예산을 사용한다. 추론 모델은 전체 출력 한도를 충분히 설정한다(예: 4096).

## 행동
- stage_client_update: 발화·appraisal·내면 노트를 새 후보로 저장. revises로 수정 전 후보를 지정한다.
- review_client_draft: 필요한 후보만 별도 LLM으로 검토. 메인과 같은 모델을 사용하고 subagent 추론 예산을 적용한다. 검토 의견은 권고다.
- finalize_client_draft: 특정 후보를 선택하고 종료. 선택한 발화를 그대로 공개하며 대응하는 appraisal·노트를 확정한다. 이후 발화를 다시 생성하지 않는다.

검토 생략과 반복 검토 모두 가능하다. 도구 호출 상한은 기존 delegation.max_calls(기본 8)를 사용한다. 한도 소진·일반 텍스트로 종료·중단·잘못된 후보 ID는 성공으로 처리하지 않는다. 같은 턴의 reasoning은 다음 호출에도 보존하고 이전 턴 reasoning은 자동 주입하지 않는다.

## 기록과 정보 경계
Q1a/<session>/drafts/<turn>/에 후보, reviews/<turn>/에 검토, appraisals/에 확정 기록과 actions·최종 선택 이유를 보존한다. 실제 현재 상태는 inner_notes.md다. 중단된 후보는 조사 기록으로 남지만 현재 내면·공개 대화로 확정되지 않는다. 다음 턴에는 현재 내면과 공개 대화만 이어지고 과거 후보·검토 전체는 자동 주입하지 않는다. 상담사에게는 확정 발화만 전달한다.

UI는 메인/특성 라우터/검토 담당의 reasoning과 입출력, 후보 발화, 노트 diff, 최종 선택 및 원문 요청을 제공한다. 실험설정에서 세 프롬프트를 각각 수정·저장할 수 있다.

## 검증 범위
기능 검증과 생성 품질 평가는 구분한다. 도구 호출·저장·검토 생략/수정·취소·정보 경계·UI 검증이 통과해도 Q1보다 반응 품질이 개선됐다는 증거는 아니다.

## 버전 이름 변경
이 버전은 최초에 Q2로 제작되었으며 Q1a로 이름을 변경했다. 기존 대화는 Q1a로 이어가고, 당시의 요청·추론·도구 로그는 원문을 보존한다. Q2는 별도 후속 구현을 위한 이름으로 비워둔다.
