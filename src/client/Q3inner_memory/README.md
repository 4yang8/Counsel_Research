# Q3inner_memory / inner_memory_no

Q3의 특성·배경 라우터와 `stage_client_update → commit_client_utterance`를 유지한 비교 버전이다. 실행은 `client/memory_access/runtime.py`를 공유한다.

| 입력/절차 | Q3inner_memory | inner_memory_no |
|---|---|---|
| 매 턴 라우터 | 전체 프로필 후보 + 공개 대화 | 동일 |
| 메인 프로필 입력 | 기본 정보 + 라우터가 선택한 특성·배경 원문 | 동일 |
| 과거 내면 | LLM 서브에이전트가 전체 기록에서 최대 3턴 선택, 내면+발화 원문 주입 | 미제공 |
| 현재 턴 | 해석·감정·의도·표현 계획 기록 → 공개 발화 | 동일 |
| 분석용 저장 | 현재 내면·발화·선택 특성·실제 입력 | 동일 |

- 양쪽 특성 라우터는 과거 내면을 읽지 않는다. 초기 프로필에 있는 비공개 배경은 양쪽 모두 사용 가능하다.
- 유지 조건의 별도 기억 선별 담당은 전체 프로필·현재 공개 대화·전체 과거 내면 기록을 읽는다. 단순 주제 유사성보다 현재 반응에 영향을 줄 이유·보류·우려를 기준으로 최대 3턴을 선택한다. 관련 기록이 없으면 0개도 가능하다. 원문은 시간순으로 메인에 전달하며, 선별 실패를 미제공으로 대체하지 않는다.
- 선별은 매 턴 한 번 수행하며 첫 턴처럼 과거 기록이 없으면 생략한다. 메인에 주입되는 기억은 최대 3턴이지만, 선별 담당의 입력은 전체 기록이므로 계속 증가한다. 임베딩/RAG는 사용하지 않는다.
- 현재 턴의 내면은 양쪽 모두 해당 턴의 발화 생성에 사용한다. 미유지 조건도 내면을 저장하지만 다음 턴에 다시 입력하지 않는다.
- Q3의 현재 노트, 노트 선택, 과거 조회 도구, 사전 신뢰 형성 궤적, 궤적 진행 요약은 사용하지 않는다. 과거 reasoning/도구 로그도 재입력하지 않는다.
- 첫 턴에는 과거 기록이 없으므로 두 조건의 정보가 같다. 이후 공개 발화에 드러난 내면 정보는 미유지 조건에서도 공개 대화를 통해 이용할 수 있다.
- 자료가 입력 크기 한도를 넘으면 자동 절삭하지 않고 오류로 남긴다.
- 메인 프롬프트는 기본적으로 양쪽이 같다. 특성 라우터 프롬프트는 `../memory_access/inner_router.md`, 기억 선별 프롬프트는 `../memory_access/inner_selector.md`이며 세션 시작 시 고정한다. 미유지 조건에서는 기억 선별을 호출하지 않는다.
- 전체 주입 방식으로 생성한 기존 유지 세션은 이어 생성하지 말고 새 작업을 만든다. 기억 정책을 설정 서명에 포함하여 기존 기록과 선별 방식이 섞이는 것을 방지한다.

## UI 대량생성

### 실제 바람과 표현 구분 (2026-11-08)

두 버전의 내담자 메인에 동일하게 `private_position` 기록을 추가했다. `actual_wish`는 실제 원하는 것, `intended_message`는 전달하려는 의미, `withheld_content`는 알고 있지만 말하지 않기로 한 내용, `withholding_reason`은 그 보류 이유다. 보류 없음·이유 해당 없음·불확실도 허용하며 속마음과 발화의 불일치나 프로필 간 다양성을 강제하지 않는다. 기존 해석·감정·의도·표현 계획도 유지한다. 기록 정의는 이 두 버전에만 적용한다.

이번 상황 구성에는 상담사 **Q3inner_counsel**을 양쪽에 동일하게 선택한다. 공개 대화 탐색 → 맥락에 맞는 제안·선택 → 관련 대화 후 당시 선택의 의미와 현재 의향 확인을 단일 프롬프트로 진행한다. 고정 턴 스케줄이나 강제 개방은 없으며, 모델이 지침대로 진행하는지는 생성 데이터로 확인해야 한다. 기본 상담사 `basic`은 변경하지 않았다. 특성 라우터·기억 선별·평가 로직도 변경하지 않았다.

서버를 재시작하고 화면을 새로고침한 뒤 **새 작업**으로 시작한다. 기존 배치는 프롬프트가 고정되어 있으며, 기존 내면 스키마로 저장한 세션은 설정 서명이 달라 이어 생성할 수 없다. 기존 결과는 그대로 열람할 수 있다.

서버 재시작 후 메인 상단 **프로필 대량생성** 링크 또는 `/batch`로 접속한다.

1. `resources/001-100` 폴더를 확인하고 프로필을 선택한다. 파일 선택은 서버 폴더 바로 아래 JSON을 대상으로 하며 하위 폴더는 재귀 탐색하지 않는다.
2. 두 버전 또는 한 버전, 내담자 턴 수, 병렬 대화 수, 모델 주소·모델·상담사 프롬프트를 설정한다.
3. **새 작업 생성 후 시작**을 누른다. 20개 프로필 × 두 조건이면 독립 대화 40개이다.
4. 턴 완료율, 처리 종료 대화 수, 성공/오류 수, 개별 단계와 재시도를 확인한다.
5. 중단 후 **미완료 대화 재개**로 저장된 마지막 발화부터 이어간다. 완료된 대화는 다시 생성하지 않는다.

기본값: 대화당 내담자 20턴, 동시 대화 4개, 실패한 발화 재시도 1회. 1턴은 상담사 질문과 내담자 답변 한 쌍이며, 첫 상담사 질문은 고정 입력이다. 초기 예시 대화는 넣지 않는다. 이후 상담사는 해당 대화의 공개 발화만 읽어 반응한다.

병렬 처리는 대화 단위이며 같은 대화의 턴은 순차 처리한다. 창을 닫아도 작업은 서버에서 진행된다. 중단 요청은 진행 중 호출의 응답 또는 제한 시간까지 기다릴 수 있다. 서버 재시작으로 끊긴 작업은 `interrupted`로 표시하고 수동 재개한다. 한 서버에서는 대량 작업 하나만 실행하며 그 안에서 설정한 수만 병렬 실행한다.

프로필·설정·공통 메인/특성 라우터/기억 선별 프롬프트·상담사 시스템 프롬프트는 작업 생성 시 저장한다. 프로필별 저장 공간은 분리한다. 진행 중 파일 변경이 반영되지 않도록 기존 내담자 세션 설정을 재사용한다.

## 저장

- `<저장 루트>/profile_batches/batch_…/job.json`: 프로필 스냅샷, 공통 설정, 프로필별 세션 ID, 진행·오류.
- `<저장 루트>/paired/<세션 ID>/session.json`: 공개 대화, 설정, 시도 목록.
- 각 세션의 `client_storage_dir` 아래 `<버전>/<세션 ID>/memory_state.json`: 완료된 내면·발화, 주입 기록, 선택 특성, 모델 요청.
- `<저장 루트>/paired/logs/<세션 ID>/`: 단계별 원본 호출 로그.

대량 화면의 **대화·내면** 버튼으로 결과를 읽을 수 있다. 일반 세션 목록에서도 확인 가능하며, 대량 작업의 세션은 일반 화면에서 수동으로 이어 생성하지 못하도록 보호한다.

## 해석 범위

다른 프로필의 궤적이 반드시 서로 달라야 한다고 강제하지 않는다. 상담사는 같은 프롬프트를 쓰지만 각 공개 대화가 달라지면 이후 질문도 달라진다. 이 파일럿은 전체 상호작용에서 나타나는 차이를 탐색하며, 고정된 동일 질문에 대한 직접 효과나 통계적 유의성을 자동으로 입증하지 않는다. 지정한 seed는 모든 조건에 같게 적용할 수 있으나 확률적 생성의 동일성을 보장하지 않는다.

선별 방식 변경 후 모의 HTTP 모델로 전체 후보 열람, 최대 3턴 원문만 주입, 미유지 조건 격리, 빈 선택, 없는/중복 턴 선택 시 저장 방지를 검증한다. 실제 모델의 선별 타당성과 발화 효과는 새 생성 데이터로 별도 확인해야 한다.
