# Q3 기록 방식 비교: Q3n · Q3sb · Q3x

목적은 같은 내면 판단을 다음 턴의 노트로 옮길 때 생기는 재해석·왜곡을 비교하는 것이다. Q3의 특성·배경·노트 라우터, 선택 노트 입력, 선택적 과거 조회, 대화 의도와 표현 계획을 공통으로 사용한다. 기존 Q3·Q3a·Q3b·Q3sk의 동작은 변경하지 않는다.

| 버전 | 발화 확정 이후 | 최신 노트 | 기록용 모델 호출 |
|---|---|---|---|
| Q3n | 메인이 원문 ID·줄 범위를 선택, Python이 해당 문자열을 복사 | 선택한 원문과 출처. 필요한 이전 원문도 다시 선택 가능 | 원문 선택 도구 호출 1회, 검증 실패 시 재시도 |
| Q3sb | 실행 코드가 전체 판단·발화 reasoning+출력 쌍을 요약 담당에게 전달 | 반환된 요약문을 그대로 저장 | 별도 요약 호출 1회, 메인 재작성 없음 |
| Q3x | Python이 마지막 확정 필드를 복사 | appraisal·turn_goal·response_plan·실제 발화의 최신 스냅샷 | 없음 |

## 공통 흐름과 궤적

1. 라우터가 관련 특성·배경·이전 노트 항목을 선택한다.
2. 메인이 필요하면 과거 기록을 조회하고 `stage_client_update`에서 appraisal, 현재 진행 판단(`trajectory_assessment`), 앞으로의 방향(`trajectory_plan`), turn_goal, response_plan을 생성한다. 조회 후 수정하면 마지막 성공한 stage가 최종 판단이다.
3. `commit_client_utterance`로 공개 발화를 고정한다. 이 발화 이후의 상대 반응을 입력받는 단계는 없다.
4. 각 버전의 방식으로 노트를 만들고, 발화·노트·진행 기록을 함께 저장한다. 실패·취소하면 전체 턴을 저장하지 않는다.

현재 진행 판단은 position, movement(maintain/advance/retreat), current_experience, grounds, next_condition으로 구성한다. 이번 상담사 말을 받아들인 현재 마음을 판단하며 아직 생성하지 않은 자기 발화의 결과를 예측해 기록하지 않는다. `trajectory_plan`은 표현하려는 방향으로 남긴다. 실제 공개 발화는 원문으로 별도 부착한다. 발화 후 진행을 다시 판단하는 모델 호출은 없다.

- Q3n·Q3x: 현재 진행 판단 전체를 그대로 `trajectory_progress`에 저장한다.
- Q3sb: position·movement는 코드가 원문에서 복사하고, 경험·근거·남은 조건만 요약 담당이 압축한다. 원래 판단 전체도 `trajectory_assessment`에 보존한다. 요약 스키마에는 position·movement를 출력할 권한이 없다.
- 다음 턴에는 라우터가 선택한 현재 노트와 최신 진행 기록이 기존 Q3와 같은 user prompt 위치에 입력된다. 과거 완료 턴은 `episodes`·`trajectory`·`changes`로 조회한다.

## 원문과 요약 입력

`recording_sources.pairs`에는 이번 턴 stage/commit 호출의 reasoning, 원래 assistant 메시지, 인자 JSON 문자열, 도구 결과, 성공 여부를 모두 보존한다. 실패한 출력은 rejected, 수정된 판단은 superseded, 마지막 채택 판단과 확정 발화는 committed로 구분한다. reasoning은 채택된 출력에 동반해도 탐색 과정으로 표시한다. 요약 담당에게 이 쌍 전체를 잘라내지 않고 전달한다. 호출 중 조회 결과는 메인 모델 요청 로그에 보존한다.

Q3n은 마지막 채택된 판단·발화 호출의 reasoning, 확정 판단 필드, 실제 발화, 이전 노트를 선택 가능한 출처로 제공한다. 선택 도구는 본문을 작성할 수 없으며, Python이 출처와 1부터 시작하는 줄 범위를 검증하고 문자열을 복사한다. 실제 원문과 문자 오프셋을 JSON에 보존한다. 다음 턴에도 구조화된 항목을 읽으므로 Markdown 표시 과정에서 공백·줄바꿈이 정규화되지 않는다. 이전 원문을 다시 선택할 때 출처 장식을 중첩하지 않는다.

Q3sb는 이전 노트와 전체 쌍을 별도 컨텍스트로 전달하고 반환 문자열을 재작성 없이 저장한다. 프롬프트는 각 버전 폴더에 독립 파일로 있으며, Q3sb 요약 담당의 system/user도 UI에서 편집한다. 입력·출력·사용량은 메인과 라우터 로그에 섞지 않고 각각 보존한다.

## 비교 조건과 한계

세 버전은 이 파일의 공통 런타임과 버전별 독립 프롬프트를 사용한다. 공통으로 stage에 현재 진행 판단을 추가했으므로 원래 Q3와 비교하면 기록 방식 외에 진행 판단의 시점도 달라진다. 세 새 버전 간에도 기록 방식에 따른 컨텍스트·호출 수·현재 노트의 정보 범위 차이가 있다.

최신 노트는 매번 교체하고 완료 턴 기록은 모두 보존한다. Q3n은 이전 조건의 재선택, Q3sb는 요약 과정의 조건 보존이 필요하다. Q3x는 마지막 판단에서 다시 언급하지 않은 예전 조건을 최신 노트에 자동 누적하지 않는다. 필요하면 과거 원문을 조회한다.

원문 복사는 기록 단계의 문장 재작성만 제거한다. 내용 선택의 누락, 탐색 reasoning의 오독, 내면 판단 자체의 오류는 여전히 가능하다. 요약 담당도 의미를 왜곡할 수 있으며, JSON 검증은 의미 보존을 보장하지 않는다. 대화 품질이나 왜곡 감소의 효과는 실제 비교 실험에서 따로 확인한다.

검증: `tests/test_recording_experiments.py`(원문 정확성·전체 쌍 전달·수정/실패 구분·스냅샷 교체·이력 조회·실패/취소 복구·프롬프트 격리), `tests/browser_recording_experiments.cjs`(버전 선택·프롬프트 편집·생성·노트/컨텍스트/워크플로·재로딩).
