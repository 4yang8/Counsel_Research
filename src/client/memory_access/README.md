# Q3 비공개 기억 접근 실험

핵심 비교는 **과거 발화 당시의 비공개 내면 정보를 후속 생성에 제공하는가**이다. 요약과 원본의 차이는 별도 비교축으로 삼지 않는다.

## 버전

| UI 버전 | 발화 생성 모델에 전달하는 과거 비공개 정보 |
|---|---|
| Q3public | 없음. 이번 턴의 내면은 평가용으로 기록하지만 다음 턴에 자동 입력하지 않음 |
| Q3oracle | 사용자가 지정한 과거 턴의 청크. 자동 추론으로 Oracle을 만들지 않음 |
| Q3full | 현재 대화에 기록된 모든 과거 턴 청크 |
| Q3select | 별도 LLM이 전체 과거 기록에서 최대 3개 턴을 선별. 코드가 선택 원문을 그대로 복사 |
| Q3ragtool | 발화 생성 LLM이 필요할 때 RAG 검색 도구를 최대 1회 호출. 코사인 유사도 상위 3개 청크 반환 |

`Q3select`는 선별의 효과를 먼저 확인하도록 구현했다. 서브에이전트의 재서술·추가 해석은 하지 않는다. 선별 담당은 본 모델과 같은 모델·생성 설정을 쓰며, 별도 서브에이전트 추론 예산을 설정할 수 있다.

## Q3에서 유지·변경한 부분

- Q3의 `appraisal`(해석·감정·근거·불확실성), `turn_goal`(대화 의도), `response_plan`(표현 계획)을 재사용한다.
- 모든 조건: **기억 입력 준비 → 이번 내면 기록 → 공개 발화 확정 → 함께 저장**.
- `Q3ragtool`: 내면 기록 전에 **검색 또는 바로 내면 기록**을 선택한다. 검색 후에는 재검색 도구가 제거된다.
- 전체 프로필과 공개 대화를 공통 입력으로 제공한다. 이번 시리즈에서는 Q3의 특성 라우터, 현재 내면 노트, 사전 궤적·진행 요약, 별도 초기 상태를 자동 입력하지 않는다.
- 현재 노트 등 다른 경로로 과거 비공개 정보가 들어가면 미제공 대조가 깨지므로, 과거 정보 입력 경로를 `private_turns`와 검색 결과로 한정했다.
- 프로필 자체에 실험 대상 비공개 이유를 적어 놓으면 조건 간 차이가 사라진다. 공통 프로필은 인물 특성, 턴별 기록은 발화 당시의 경험·이유로 구분한다.
- 매 턴 새 요청을 구성한다. 이전 턴의 모델 reasoning·도구 메시지는 자동 재사용하지 않는다. 같은 턴의 내면 기록은 그 턴 발화 생성에 사용한다.
- 기록은 모델이 명시적으로 생성한 내면 설명이지, 실제 사람의 심리나 모델 내부 계산의 정답은 아니다.

## UI 사용

1. **새 대화 → 내담자 버전**에서 위 5개 중 선택한다.
2. 실험 설정의 **과거 비공개 기억 실험**을 확인한다.
3. 기존 공개 대화만으로 시작하면 그 대화의 비공개 이유는 없다. 새로 생성된 턴부터 기록이 쌓인다.
4. 동일한 과거로 비교하려면 완료된 세션의 **기억 검색 → 공통 기록 JSON 내보내기**를 사용한다.
5. 다른 조건의 새 대화에서 이 파일을 가져온다. 가져온 공개 대화가 초기 히스토리를 대체하며 내면 기록은 조건별로 제공된다. 프로필·모델·생성 설정·다음 상담사 문장은 동일하게 맞춘다.
6. **Q3oracle**에서는 가져온 기록의 체크박스로 제공할 턴을 고른다. 기본 턴 번호를 직접 적거나 `{"6": [2, 5], "7": [5]}`처럼 생성 턴별 계획을 지정할 수도 있다. 키는 생성할 내담자 턴, 값은 제공할 과거 턴이다.
7. **Q3ragtool**은 로컬 모델 또는 임베딩 서버를 선택한다. 다른 버전에는 임베딩 설정이 표시되지 않는다.
8. **기억 검색** 화면에서 진행 상태, 실제 주입된 원문, 선택된 턴·유사도·검색 횟수·토큰 사용량·지연시간을 확인한다. **Workflow / Raw / Activation context**에서도 실제 모델 요청을 확인할 수 있다.

선택 계획·공통 기록·임베딩 설정은 세션 시작 때 고정된다. 새롭게 생성된 턴을 확인하고 Oracle 선택을 바꾸려면 현재 공통 기록을 내보내고 새 대화로 가져온다. 기본 선택이 비어 있으면 과거 비공개 정보는 0개 제공되며, 없는 턴·현재 턴·미래 턴을 지정하면 오류로 알려 준다.

`example_seed.json`은 가져오기 형식을 확인하는 **수작업 가상 사례**이다. 실험 결과나 검증된 상담 기준이 아니다.

## RAG 설정

- 모델: `/home2/sjyang114/.cache/huggingface/hub/models--Qwen--Qwen3-Embedding-4B`
- 청크: `turn` + `inner` + `utterance`. 한 턴은 상담사 질문에 대한 내담자 응답 한 번이다.
- 기록에는 연결 확인용 `counselor_utterance`도 저장하지만, 임베딩·검색 반환 청크는 내면+실제 발화와 턴 번호로 구성한다. 상담사 발화는 공통 공개 대화에서 확인한다.
- 검색어: 발화 생성 모델이 도구 인자로 작성한다. Qwen 형식의 고정 영문 검색 지시문을 검색어에만 붙인다.
- 코사인 유사도 순위, Top-3, 임계값 없음. 후보가 3개 미만이면 있는 만큼 반환한다.
- 검색 후보는 해당 세션의 완료된 과거 기록으로 제한한다. 다른 세션 또는 미래 기록을 검색하지 않는다.
- 로컬 모델은 첫 실제 검색에 지연 로딩하며, 입력 길이를 검사하여 몰래 절삭하지 않는다. 캐시는 모델 경로·서버·설정·청크 내용 해시로 구분한다. 후보 목록은 세션별로 독립이다.
- vLLM은 필수가 아니다. `local`은 SentenceTransformers를 사용한다. Hugging Face 캐시 루트의 `refs/main` 또는 단일 snapshot을 실제 모델 경로로 해석한다.
- 로컬 기본 장치는 `auto`이며 CUDA를 사용할 수 없으면 CPU를 사용한다. 4B 모델의 CPU 실행·첫 로딩은 오래 걸릴 수 있다. UI에서 `cuda:0` 등 장치를 직접 지정할 수 있다.
- `openai`는 별도 `/v1/embeddings` 서버를 호출한다. 주소와 서버의 모델 이름을 입력한다. 발화 생성 서버 주소와는 다르다. 서버에서도 입력 자동 절삭을 사용하지 않아야 공정하게 비교할 수 있다.
- 선택적 의존성: `python -m pip install -e '.[embedding]'`. 기존 환경에 설치되어 있으면 추가 설치할 필요 없다.
- Qwen 공식 사용법: https://huggingface.co/Qwen/Qwen3-Embedding-4B

## 기록과 실패 처리

- 저장 파일: `<storage>/<버전>/<session_id>/memory_state.json`.
- paired 실행은 기존 앱의 `client_attempts` 디렉터리 안에 보관된다.
- 각 턴에 내면·발화, 실제 기억 입력, 검색어·점수·검색 지연, 선별 결과, 실제 모델 요청, 모델별 토큰 사용량을 저장한다.
- 총 지연은 선별·검색·생성을 포함하며 첫 모델 로딩과 캐시 여부의 영향을 받는다. 검색 기록의 `embedded_documents`, `cache_hits`와 함께 해석한다.
- LLM 토큰 비용과 임베딩 요청 비용은 다르다. 현재 로그의 LLM 사용량에 임베딩 토큰·금액은 포함하지 않는다. 금액을 임의로 환산하지 않는다.
- 임베딩 실패를 미제공 조건으로 조용히 대체하지 않는다. 생성 실패·중단 시 이번 내면·발화를 확정하지 않으며 같은 입력으로 재시도할 수 있다.
- 도구 인자 오류는 제한된 도구 루프 안에서 수정할 수 있다. 네트워크 실패·잘린 생성은 자동으로 성공 처리하지 않는다.
- 기본 입력 한도는 240,000자이며 모델 토큰 한도와 별개다. 전체 기록을 몰래 자르지 않고 명시적으로 오류를 낸다.

## 해석 범위

이 구현은 조건별 데이터 생성과 입력·검색 로그 수집을 제공한다. Oracle 정답 작성, Recall@k/Precision, 이유 왜곡·상담 반응 타당성 평가는 사후 분석 대상이며 자동 판정으로 구현하지 않았다.

서로 독립적으로 길게 생성한 대화는 궤적 차이가 섞인다. 정보 제공 자체의 효과를 볼 때는 같은 공통 기록과 같은 후속 문장으로 한 턴씩 비교한다. 기록 접근으로 더 협조적이거나 더 거부하는 것 자체를 성공으로 정의하지 않는다. 현재의 진짜 심리 변화와 과거 이유의 소급 왜곡을 구분해야 한다.

## 검증

```bash
PYTHONPATH=src:tests python -m unittest test_memory_access -q
```

HTTP 모의 모델로 공개 조건의 정보 차단, 선별 원문 전달, 0/1회 검색, Top-3, 스냅샷 재사용, 잘못된 Oracle 지정, 오류 후 재시도를 검증한다. 실제 모델의 상담 성능이나 연구 가설을 입증하는 테스트는 아니다.
