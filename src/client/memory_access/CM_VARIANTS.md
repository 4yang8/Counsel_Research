# Q3cm — compare memory 내담자 실험군

`Q3cm`은 Q3 계열의 **compare memory**다. 약어 `cm`은 소문자를 유지한다. 기본형은 기존 `Q3compare_memory_private_position`의 프로필·라우팅·내면 스키마·발화 방식을 이어받는다. 기존 버전은 삭제하거나 이름을 바꾸지 않았다.

모든 후보에 기본 프로필, 공개 대화, 같은 공개 정보 기반 특성 라우터를 사용한다. 두 조건 모두 현재 턴 내면을 생성한다. `provided/withheld`는 과거 내면 및 그로부터 만든 사건 상태의 접근만 달라진다. 현재 반응/표현/검토 구조는 후보 안에서 동일하다.

## 구조와 호출 수

정상 내담자 턴 1개 기준. 제공 조건에 과거 기록이 있으면 최대 3턴 선택을 위한 LLM 호출 1회가 있다. 첫 턴에는 선택 호출이 없다. 숫자는 router를 포함한다. 재시도는 별도다.

| 버전 | 라우팅/기억 접근 다음의 처리 | 제공 LLM 호출 | 미제공 LLM 호출 | function tool 호출 |
|---|---|---:|---:|---:|
| Q3cm | 내면 → 발화 확정 | 4 | 3 | 2 |
| Q3cm_split | 실제 반응 → 표현 결정 → 발화 확정 | 5 | 4 | 2 |
| Q3cm_temporal | 과거/현재 구분 → 내면 → 발화 확정 | 5 | 4 | 2 |
| Q3cm_state | 내면 → 발화 → 사건 상태 갱신 → 저장 | 5 | 4 | 2 |
| Q3cm_tools | 자율 과거 조회 → 내면 → 발화 확정 | 3~5 | 3~5 | 2~4 |
| Q3cm_review | 내면 → 발화 초안 → 검토 → 선택적 수정 | 5~6 | 4~5 | 2~3 |
| Q3cm_full | 과거/현재 → 실제 반응 → 표현 → 초안 → 검토 → 선택적 수정 → 사건 갱신 | 8~9 | 7~8 | 2~3 |

`Q3cm_tools`는 자동 선택기를 쓰지 않는다. 같은 조회 도구를 양쪽에 제공하되 미제공에서는 항상 빈 기록을 반환한다. `read_private_turns`는 두 번까지, 요청한 고유 과거 번호는 총 3개까지다. 이 한도는 결과가 비어 있어도 동일하게 적용한다. 현재/미래 번호는 거부한다. 임베딩 서버 없이 공개 대화의 턴 번호로 조회한다.

## 각 후보의 핵심

- split: reaction에는 appraisal/actual_wish/counselor_stance만 있다. expression은 실제 반응 필드를 출력할 수 없고, 코드가 앞 단계의 반응을 그대로 복사한다. 표현하기 좋은 속마음으로 나중에 바꾸는 경로를 차단한다.
- temporal: 제공된 과거 기록의 당시 경험과 현재 공개 맥락을 별도로 정리한다. 기록이 없으면 빈 experiences. 제공되지 않은 과거 턴을 사실로 확정하면 실패한다.
- state: 실제 발화까지 확정한 뒤 사건의 현재 의미/공개 상태를 갱신한다. 원래 반응과 입장은 불변 필드에 보존한다. 상태 갱신 실패 시 발화도 이번 턴에 확정 저장하지 않는다.
- review: 현재 내면과 표현 계획이 초안에 구현됐는지 검토한다. 더 솔직하게/더 숨기게/더 협조적으로 만드는 검토가 아니다. 수정은 한 번까지만.
- full: 위 시간 구분·반응 분리·검토·사건 관리를 함께 실행한다. 복잡성이 이득을 주는지는 생성 후 검증해야 한다.

## 입력 경계

`memory_access(ctx, body)`에서 과거 원본 기록과 파생 `event_state`를 함께 허용/차단한다.

- 제공: 선택된 최대 3개 원본과, state/full에서는 이전 사건 상태를 활용한다. 따라서 state/full의 전체 역사 정보량은 기본형의 원본 3개와 다르다. 이것은 구조 차이로 명시해야 한다.
- 미제공: 모든 생성·시간 구분·검토·상태 갱신에 과거 기록과 파생 상태를 전달하지 않는다. 조회 툴도 과거 내용을 반환하지 않는다.
- 미제공이어도 과거 원본과 사건 기록은 분석을 위해 파일에 보존한다. 저장돼 있다는 것과 입력된다는 것은 다르다.
- 현재 턴의 내면과 생성 단계 출력은 두 조건 모두 이후 현재 턴 단계에 전달한다.
- 상담사에는 이 기록을 전달하지 않는다.

## 저장

기존 `session.client_storage_dir/<version>/<session>/memory_state.json` 형식을 유지한다. 저장 포인터는 기존 `client_attempts` 또는 새 `client_state`일 수 있다.

기존 필드 `turn, inner, utterance, counselor_utterance, memory_input, selection, model_requests, agent_usage, memory_mode`를 유지한다. 새 구조에는 추가로:

- record의 `pipeline.stages`: 단계별 입력/출력, `llm_calls`: 실제 요청 수.
- `state_input`: 해당 턴에 실제 들어간 과거 사건 상태. 미제공은 빈 배열.
- state의 `event_state`: 원래 반응/입장 + 현재 해석/공개 상태/근거 턴/갱신 시점.
- `cm_prompts`: 해당 세션/배치에 고정된 보조 프롬프트.

원본 요청·reasoning·도구 결과는 기존 이벤트 로그에도 저장한다. 실제 반응 생성 이후의 중간 초안은 공개 대화에 추가하지 않는다. 마지막 성공 지점에서만 기존 저장 잠금/원자적 publish 경로로 반영한다.

공통 1~n−1턴과 상담사 n턴을 생성한 후 내담자 n턴부터 분기한다. 원본 내면·사건 상태는 분기 파일에 복사되지만 접근 게이트는 즉시 해당 조건에 맞게 적용된다.

## UI와 평가

대량생성의 **생성 방식 → 공통 생성 후 분기 · Q3cm...**에서 고른다. 상담사는 독립적으로 선택한다. 설정/API 목록은 레지스트리에서 동적으로 가져온다.

`eval/`은 버전명을 하드코딩하지 않고 compare 배치를 읽으므로 새 버전의 완료 배치도 선택한다. 핵심 저장 필드가 같아 현재 파서를 유지할 수 있다. 새 상태/단계 지표를 추가하려면 code metrics 어댑터를 확장하면 된다. 기본 공개/내면 평가에는 파생 메모나 실험 조건을 추가로 노출하지 않는다.

2026-11-12: 신규 생성 이름에 `Q3` 접두사를 적용했다. 기존 `cm`, `cm_*`는 기록 열기와 재개를 위한 호환 이름으로 유지하며 신규 선택 목록에는 표시하지 않는다. 두 이름은 저장 경로와 실행 ID를 공유하지 않는다.
