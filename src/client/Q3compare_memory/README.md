# Q3compare_memory

과거 내면 기록 제공 여부만 다른 두 대화를, 같은 앞부분에서 갈라 생성하는 내담자 버전이다. 내담자 본체는 `Q3inner_memory`와 같고 실행부는 `client/memory_access/runtime.py`를 공유한다. 기존 `Q3inner_memory`, `inner_memory_no`의 동작은 바꾸지 않았다.

## 목적

기존 두 조건은 1턴부터 따로 생성되어 대화가 서로 다르다. 이 버전은 n턴 전까지를 한 번만 생성하고 n턴 내담자 답부터 나눈다. 그래서 두 갈래는 같은 공개 대화와 같은 과거 내면 기록에서 출발하고, 차이는 그 기록을 내담자 입력에 넣는지뿐이다.

## 구조

1턴은 상담사 발화 1개와 그에 대한 내담자 답 1개다. 분기 턴을 n이라고 하면 프로필 하나당 세션이 세 개 생긴다.

| 세션 | 생성하는 범위 | 과거 내면 기록 |
|---|---|---|
| 공통 | 1턴 ~ n턴 상담사 발화 | 제공 (기억 선별 담당이 최대 3턴 선택) |
| 제공 갈래 | n턴 내담자 답 ~ 마지막 턴 | 제공 |
| 미제공 갈래 | n턴 내담자 답 ~ 마지막 턴 | 미제공 |

- 공통 구간은 과거 기록을 제공하는 방식으로 생성한다. 미제공 갈래는 완성된 구성에서 n턴부터 기록만 뺀 것이다.
- n턴 상담사 발화는 공통 세션에서 한 번만 생성하므로 두 갈래가 같은 질문을 받는다.
- 두 갈래 모두 매 턴 현재 내면을 기록하고 그 턴의 발화에 쓴다. 미제공 갈래는 과거 턴의 기록만 입력에 넣지 않는다.
- 미제공 갈래의 저장 파일에도 공통 구간의 내면 기록이 그대로 들어 있다. 분석에서 "당시 속마음"의 기준으로 쓴다.
- n=1이면 공통 세션은 시작 상담사 발화만 가진다.

| 입력/절차 | 제공 갈래 | 미제공 갈래 |
|---|---|---|
| 메인 지침 (`system.md`) | 동일 | 동일 |
| 특성·배경 라우터 | 동일 (공개 대화만 읽음) | 동일 |
| 기본 프로필, 선택 특성, 공개 대화 | 동일 | 동일 |
| 현재 턴 내면 기록 → 발화 | 동일 | 동일 |
| `private_turns` (과거 내면+발화) | 기억 선별 담당이 고른 최대 3턴 | 항상 빈 목록 |
| 기억 선별 담당 호출 | 함 | 안 함 |

## 설정

- 갈래는 세션 설정의 `compare_memory_mode`로 정한다. 값은 `provided` 또는 `withheld`이다. 실험 화면에서 이 버전을 단독으로 쓰면 `provided`로 동작한다.
- 설정 서명에는 `compare_fork_v1`만 들어가고 갈래 값은 들어가지 않는다. 두 갈래가 공통 기록을 이어받아야 하기 때문이다. 대신 각 턴 기록의 `memory_mode`에 그 턴이 어느 방식으로 생성됐는지 남긴다.
- `system.md`는 `Q3inner_memory/system.md`에서 출발했고, 아래 변경 기록대로 달라졌다. 프로필, 설정, 지침은 작업 생성 시 저장하므로 이미 만든 작업에는 변경이 반영되지 않는다.

## 지침 변경 기록

- **변경 (두 갈래 공통):**
  - "기록한 비공개 내용을 자동으로 설명하거나 노출하지 마세요" → 무엇을 말할지는 이번 턴의 판단에 따른다는 문장으로 바꿈

  - "말을 만들기 위해 비공개 이유를 억지로 공개할 필요는 없습니다" 삭제
- **바꾸지 않은 것:** `Q3inner_memory`, `inner_memory_no`의 지침, 내면 기록 형식, 기억 선별, 실행 로직.

### 2026-11-11: 상담사의 말에 대한 반응을 말할지 따를지 판단하게 함

- **이유:** 상담사 `P3rs`로 생성한 `batch_130eab25…`(프로필 5개, 10턴, 분기 턴 5)에서 물러남 표지 기록과 균열 탐색이 상담사 발화 70개 중 0이었다. 내담자가 상담사 개입에 대한 이견을 그대로 말했고, 보류 내용 80턴 중 76턴이 프로필 수준의 내용(핵심 신념, 과거 사건)이었다. 상담사 말에 대한 반응을 숨긴 4턴은 모두 긍정적 반응이었다. 내면 기록에 상담사 말의 해석과 감정을 적는 자리(`appraisal`)는 있지만, 그 반응을 말할지 따를지를 정하게 하는 문장이 없었다.

- **삭제:** "숨은 이유, 거짓 동의, 저항, 사람 간 차이를 만들기 위해 불일치를 꾸며내지 마세요"에서 "거짓 동의"를 뺐다. 말하지 않고 맞춰 줄 수 있다는 새 문단과 방향이 반대였기 때문이다. `Q3compare_memory_private_position`에도 같이 적용했다.

## 대량생성 화면에서 실행

`/batch`에서 **생성 방식**을 "공통 구간 뒤 분기 · Q3compare_memory"로 고르고 **분기 턴 n**을 입력한다(1 이상, 대화당 턴 수 이하). "공통 구간 뒤 분기 · Q3compare_memory_private_position"을 고르면 같은 구조를 그 버전으로 생성한다. 상담사는 기본으로 `P3rs`가 선택되며 `P3q`나 다른 단일 프롬프트 상담사로 바꿀 수 있다.

- 병렬 처리 단위는 프로필이다. 한 프로필 안에서는 공통 → 제공 갈래 → 미제공 갈래 순서로 생성한다.
- 중단 후 재개하면 완료된 공통 세션은 다시 생성하지 않고, 이미 만들어진 갈래 세션을 이어 간다.
- 공통 구간이 실패하거나 중단되면 두 갈래는 시작하지 않는다.

## 저장

```
<저장 루트>/profile_batches/batch_…/job.json   mode=compare, options.fork_turn, 프로필별 행 3개(branch: common/provided/withheld)
<저장 루트>/paired/<공통 세션>/session.json     compare: {branch: common, fork_turn}
<저장 루트>/paired/<갈래 세션>/session.json     compare: {branch, parent_session, fork_turn, common_steps}
<저장 루트>/paired/<세션>/client_state/Q3compare_memory/<세션>/memory_state.json   최신 누적 내면 기록 하나
<저장 루트>/paired/<세션>/state_archive/                                        기존 턴별 사본의 검증된 압축 보관본
<저장 루트>/paired/logs/<세션>/                                                호출별 입력·출력·추론 원본
```

- 갈래 세션은 공통 구간의 공개 대화, 단계 목록, 내면 기록을 복사해 가진다. 복사된 단계에는 `common: true`가 붙고, 그 호출 로그는 공통 세션 쪽에 있다.
- 2026-11-12부터 `memory_state` 계열은 최신 상태 하나만 유지한다. 생성 중 `.client_pending`에 임시 작업본을 만들고, 성공하면 공개 세션과 함께 확정한다. 실패 작업본은 `client_failures`에 압축 보존하고 최신 상태에 반영하지 않는다. 과거 시점 체크포인트를 쓰는 `Q3p6` 등 다른 런타임은 기존 구조를 유지한다.
- 기존 데이터 정리는 `scripts/compact_paired_state.py`로 수행한다. 원본 세션 백업과 SHA-256을 남기며, 이전 `client_attempts`의 모든 파일을 압축본과 바이트 단위로 대조한 뒤 폴더를 정리한다. 상세 절차는 `docs/paired_state_storage.md`를 참고한다.
- 상담사 `P3q`를 쓰면 상담사 단계마다 `revisit`(되짚은 내담자 턴)이 붙는다. 이 표시는 공개 대화에 들어가지 않으므로 내담자 입력에 전달되지 않는다.
- 상담사 `P3rs`를 쓰면 상담사 단계마다 `rupture`(물러남 표지 메모와 균열 탐색 기록)가 붙는다. 공통 세션의 메모는 두 갈래로 복사되고, 마찬가지로 내담자 입력에 전달되지 않는다. 자세한 내용은 `src/counselor/P3rs/README.md`에 있다.

## 해석 범위

- 분기 뒤 상담사는 각 갈래의 공개 대화를 보고 따로 반응한다. n턴 상담사 발화만 두 갈래에서 같고, 그 뒤 질문은 달라질 수 있다.
- 공통 구간의 내면 기록이 두 갈래에서 같다는 것은 구조상 보장된다. 그 기록이 이후 발화를 바꾸는지는 생성 결과로 확인해야 한다.
- 생성은 확률적이다. 한 프로필에서 갈래당 대화는 하나이므로, 차이는 여러 프로필을 모아서 봐야 한다.

## 검증

- `PYTHONPATH=src:tests python3 -m unittest test_compare_branch -q`
- 모의 HTTP 모델로 다음을 확인한다. 공통 구간 공유, 갈래별 입력 격리(미제공 갈래의 메인 입력에 과거 내면 없음), 기록 선별 호출 여부, 상담사 입력에 비공개 정보 없음, n=1, 설정 검증, 중단·재개 시 공통 세션 유지.
