# F · E 기반 개발 버전

버전 ID: `Q2a_agentic_memory_F`. UI의 내담자 버전에서 F를 선택한다.

생성 당시 E의 기능(노트 선택·능동 조회·대화 의도·항목별 노트 갱신)을 그대로 복제했다. A~E의 특성 라우터 범위 정리를 반영한 뒤 복제했으므로, 복제 당시에는 E와 F의 기능·프롬프트가 같았다. 이후 F에 아래 변경을 적용했다. 실제 대화 세션·노트는 복제하지 않고 새 세션으로 시작한다.

## F에서 수정할 위치

- `system.md`, `user.md`: 메인 지침과 입력 템플릿.
- `trait_router.md`, `trait_router_user.md`: 라우터 지침과 입력 템플릿.
- `runtime.py`, `settings.py`: 실행 순서, 도구 정의, 실험 옵션.
- `memory.py`: 기록 조회 대상·검색·한도.
- `states.py`, `note_items.py`, `state_notes_template.md`: 상태 의미·노트 수정·초기 노트.
- `profile_context.py`: 특성·배경 후보와 라우터 출력 스키마.
- `tool_loop.py`: F의 같은 턴 모델·도구 반복 호출.
- `context_view.py`, `context_blocks.py`: F의 Activation context 구성.

위 파일은 F 전용 복사본이다. F 안에서 수정하면 A~E 파일에는 반영되지 않는다. HTTP 서버, UI, 프롬프트 편집기, 사용자 템플릿 렌더러, 공통 파싱·저장·모델 연결 유틸리티는 기존 공통 기반을 사용한다. 실행 로그와 노트는 F 버전 경로로 저장된다.

## 변경 기록

- 시작: E를 복제. 특성 라우터는 현재 대화 단서와 선택 자료의 연결 근거를 1~2문장으로 반환하도록 정리. 추가적인 기능 변경 없음.

## 생성 시 검증

E/F의 초기 도구 정의와 5개 프롬프트·초기 노트 파일 일치를 확인했다. 관련 자동 테스트 20개가 통과했고, 브라우저에서 B~F 선택·생성·프롬프트·노트·세션 복원과 E/F의 단계별 컨텍스트 활성화를 확인했다. 모의 모델 검증이며 실제 모델의 라우터 응답 개선 여부는 별도 실험 대상이다.

## 자유 글머리 노트 실험

- 증상·가설: 고정된 10가지 심리상태와 현재 내면 3영역에 유사한 내용을 반복 배치할 수 있다. 분류 틀 자체를 제거해 기록 양과 중복 경향을 관찰한다.
- 초기 노트: `# 내담자 노트`와 `(내용 없음)`만 제공한다. 상태 정의나 영역별 빈칸은 입력하지 않는다.
- 흐름: 특성·노트 선택 → 필요시 기록 조회 및 내면 판단 → 발화 확정 → 전체 노트를 복원하고 `update_client_notes`로 필요한 항목만 갱신.
- `select_client_states` 제거. 갱신 인자는 `operations` 안의 `action`, `item_id`, `content`, `reason`이며 `section`은 제거했다. 조회 도구도 영역 필터 없이 항목 ID·턴·검색어를 사용한다.
- 기록·추가·수정·삭제·유지 기준, ID 기반 부분 수정, 같은 턴 reasoning, 선택 노트 제공과 현재/변경/과거 턴 조회는 유지한다. 기존 내용을 그대로 두는 선택은 빈 operations로 표현할 수 있다.
- 이전 F 파일은 조회 시 수정하지 않는다. 고정 제목을 가진 노트를 이어서 처리할 때는 기존 ID와 본문을 보존해 평평한 항목 목록으로 읽고, 다음 성공한 저장에서 새 형식으로 기록한다. 이미 저장된 요청·발화·변경 이력은 유지한다. 비교 실험은 새 F 대화로 시작한다.
- F 전용 코드와 공통 UI의 형식별 표시만 변경했으며 A~E의 프롬프트·실행 로직은 유지한다.

검증: 자유 노트 부분 변경·원본 보존·옛 형식 읽기·3단계 실행·연속 턴 조회·실패 시 미저장을 모의 모델과 HTTP 경로로 확인했다. A~E 회귀 테스트와 B~F 브라우저 검증을 통과했다. F의 두 번째 턴에서 미선택 항목이 발화 전에는 비활성이고 노트 갱신 호출에서는 활성화되는 것을 확인했다. 실제 모델의 중복 감소 효과는 이후 생성으로 관찰한다.

## 기록 역할 명확화

- 관찰: 기본 프로필을 노트에 재기록하고, 표현 순서의 망설임을 문제 이해의 불명확성으로 확장하는 사례가 있었다. 라우터에도 자료의 관련성을 사건의 원인으로 단정한 설명이 있었다.
- 수정: 메인 지침과 노트 도구의 description/content/reason에서 노트의 목적, 비교 자료의 의미, 판단의 대상·구체성·확실성 유지 기준을 정리했다. 라우터 지침과 relevance 설명은 현재 대화 단서와 자료 원문을 대응시키도록 구체화했다.
- 범위: F의 지침·설명만 수정. 도구 인자 구조, 실행 순서, 항목 갱신·저장 로직은 유지한다. 실제 개선 효과는 후속 생성에서 확인한다.
