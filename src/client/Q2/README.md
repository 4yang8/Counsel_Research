# Q2 · 자연어 심리상태

원본 Q1 기반. Q1a의 초안 검토·확정 루프와 수치 상태·확률 행동 선택은 사용하지 않는다.

## 턴 순서

1. 전체 특성에서 이번 관련 특성을 선정한다 (Q1 방식 유지).
2. 메인이 기본 정보·선정 특성·공개 대화·최신 심리상태 노트를 읽는다.
3. 첫 메인 호출은 named tool choice로 `stage_client_update`를 지정한다. 유효한 판단 접수 후에는 `auto`로 전환하여 수정·발화 여부를 모델이 선택한다. `stage_client_update`로 appraisal와 반응 방향·근거를 기록하고 공개 발화를 생성한다.
4. 상태 라우터가 이전 상태·특성·대화·최종 판단·완성된 발화를 보고 검토할 상태를 선정한다.
5. 선정이 있으면 상태 갱신 담당이 선택된 항목만 검토한다. 선정되었어도 변경하지 않을 수 있다.
6. 검증에 통과하면 상태 노트·턴 기록을 저장한다. 양방향 세션은 이 단계까지 성공해야 발화가 확정된다.

상태는 `states.py`에 정의된 10개 항목의 자연어 본문이다. 고정 제목과 순서를 Python이 유지한다. 초기 본문은 모두 `현재 판단할 정보가 부족함.`이며 낮은 상태를 뜻하지 않는다. 별도 심리 수준을 임의로 초기화하지 않는다. 순간 감정은 appraisal에 남긴다.

메인은 상태 파일을 미리 수정하지 않는다. 이번 경험은 appraisal를 통해 이번 발화에 반영하고, 지속되는 상태 설명은 발화 뒤에 갱신한다. 과거 reasoning 원문은 다음 턴에 전달하지 않는다. 같은 턴 도구 호출 간 reasoning은 기존 공통 루프대로 유지한다. 상태 담당에는 명시적 판단 기록을 전달하며, 이전 제출본은 최종 판단으로 대체되었다고 표시한다.

## 저장과 조회

`<세션별 저장 루트>/Q2/<session_id>/state_notes.md`가 현재 노트다. `appraisals/*.json`에는 턴별 이전/이후 노트, appraisal, 반응 방향, 검토 대상·근거, 실제 변경·근거, 공개 발화와 diff가 저장된다. 양방향 대화는 기존 세션의 `client_attempts` 아래에서 실행별 사본을 관리한다.

UI의 `심리상태 노트` 화면에서 최신 파일, 턴별 원문, 갱신 전 원문, 변경 내역·근거를 조회한다. 메인·특성 라우터·상태 라우터·상태 갱신 담당의 프롬프트는 실험 설정에서 편집·저장할 수 있다. 각 호출의 reasoning·입출력은 대화/Raw/Workflow에서 확인한다.

상태 갱신 실패·잘림·중단 시 이번 턴은 미완료이며 기존 노트를 유지한다. 실패 과정과 생성된 발화 스트림은 실행 로그에 남는다. 선정하지 않은 항목 변경, 중복 ID, 잘못된 구조와 제목 삽입은 거부한다. 이런 검사는 형식·저장 검증이며 심리적 타당성을 자동 보장하지 않는다.

Q2 전용 도구 루프는 명시적으로 지정한 단일 도구가 완전한 JSON 인자와 `stop`으로 종료되는 vLLM 응답도 허용한다. `length`, 잘못된 JSON, 다른 도구명, 일반 auto 호출의 비정상 종료는 허용하지 않는다. 원본 종료 신호는 로그에 그대로 남는다.
