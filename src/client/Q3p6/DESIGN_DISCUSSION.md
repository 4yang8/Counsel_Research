## 1. 네 항목으로 정리한 최초 설계 답변 원문

**새 버전은 ‘같은 대화 지점에서, 과거 내면 기억만 바꿔 상담 반응을 비교하는 방식’이 좋겠습니다.** 가칭 **Q3p6**로 두고, 우선 하나의 질문에 집중합니다.

> **과거 발화 당시의 내면 기록을 추가로 보존하면, 현재 상태·이유 포함 요약만 제공할 때보다 이후 상담 개입에 대한 반응을 더 타당하게 유지하는가?**

**1. 같은 과거를 공유한 상태에서 분기**

먼저 Q3로 대화를 생성하고, 의미 있는 발화가 나온 시점의 내면을 저장합니다. 몇 턴 뒤를 비교 지점으로 정해 **공개 대화·현재 노트·프로필·상담사 발화를 동일하게 복제**합니다.

이 지점부터 기억 조건만 달리합니다. 처음부터 별도 대화를 생성하면서 비교하는 방식보다, 특정 기록의 영향을 확인하기 쉽습니다.

**2. 기본 비교는 두 조건**

| 조건 | 제공하는 정보 |
|---|---|
| **A: 이유 포함 요약** | 공개 대화 + 현재 상태·목표 + 과거 이유도 담을 수 있는 노트 |
| **B: 당시 기록 추가** | A와 동일한 입력 + 대상 발화에 연결된 당시 내면 원본 |

원본에는 **상황 해석·감정·목표·표현을 선택한 이유**를 포함합니다. 현재 저장 필드가 이 내용을 실제로 담는지도 확인해야 합니다.

A에서 이유를 일부러 지우지 않습니다. **충분한 요약으로도 해결되는지**가 중요한 비교입니다. B의 이득이 나타나더라도, 이 단계에서는 ‘기록 추가의 효과’이며 **발화 연결 자체의 효과**까지 입증한 것은 아닙니다.

**3. 상담 개입도 두 종류로 비교**

설명용 사례입니다.

- 과거 발화: “네, 한번 해볼게요.”
- 당시 내면: “실제로는 부담스럽지만 거절하면 실망시킬까 봐 동의했다.”
- 이후 개입 ①: 당시 동의를 확고한 의지로 전제하고 실행 계획을 묻기.
- 이후 개입 ②: 당시 동의에 부담이나 망설임이 있었는지 확인하기.

두 개입을 A·B 각각에 동일하게 제공하면 **총 네 조건**이 됩니다. 상담사는 비공개 기록을 받지 않습니다.

관찰할 것은 **기억을 추가했을 때 반응이 달라지는지**, 그리고 **그 변화가 개입의 차이를 맥락에 맞게 반영하는지**입니다. ①에는 반드시 저항하고 ②에는 반드시 협조해야 한다고 정하지 않습니다.

**4. 평가 기준을 생성 전에 정하기**

- 당시 발화의 의미를 근거 없이 바꾸는가?
- 그 이후의 경험과 현재 마음의 변화도 반영하는가?
- 상담 개입에 대한 반응이 이 두 정보를 함께 고려했을 때 타당한가?

자동 관찰자의 설명은 보조자료로 사용하고, **가능한 반응 범위와 오류 사례를 먼저 정해** 평가합니다. 각 조건을 여러 번 생성해 우연한 표현 차이와 반복되는 경향도 구분합니다.

**첫 단계는 한 턴의 반응 비교가 적절합니다.** 여기서 신호를 확인한 뒤 짧은 후속 대화로 확장하면, 기억이 반응뿐 아니라 궤적에도 영향을 주는지 볼 수 있습니다. 사후 추론과의 비교는 이후 세 번째 기억 조건으로 추가할 수 있습니다.

## 2. A와 B를 비교하는 목적에 대한 답변 원문

사용자 질문:

> '2. 기본 비교는 두 조건' 여기서 두 조건의 결과를 서로 비교하자는거야? 그 실험이 내 주장을 확인하는데 어떤 역할을 하는거야?

답변:

네. **같은 상황에서 A와 B가 생성한 후속 반응을 비교하자는 뜻**입니다. 그 비교가 확인하는 것은 다음입니다.

> **현재 상태와 요약으로 충분한가, 아니면 발화 당시 내면 원본을 추가로 제공할 실익이 있는가?**

예를 들어 과거에 “네, 해볼게요”라고 말했지만, 실제 이유는 **거절하기 부담스러웠기 때문**이었다고 합시다.

- **A:** 현재 상태와 요약을 보고 후속 반응 생성.
- **B:** 같은 입력에 당시 내면 원본도 추가해서 반응 생성.

이후 상담사가 “하기로 하셨으니 계획을 세워볼까요?”라고 했을 때 비교합니다.

| 결과 | 해석 |
|---|---|
| A는 과거 동의를 확고한 의지로 취급하고, B는 당시 부담을 적절히 반영 | **당시 기록을 추가로 제공하는 효과**를 지지 |
| 둘 다 당시 부담을 적절히 반영 | 이 사례에서는 **요약으로 충분** |
| 표현만 다르고 의미는 같음 | 주장과 관련된 차이가 관찰됐다고 보기 어려움 |

**다만 이 실험만으로 사용자 주장을 전부 확인하지는 못합니다.** B에는 정보량·구체성·반복 강조도 늘어나므로, 개선이 나타나도 곧바로 **“발화와 당시 내면을 연결한 방식 덕분”**이라고 할 수 없습니다.

따라서 제가 제안한 A/B는 **‘현재 요약에 더해 원본 기록을 제공할 가치가 있는가’를 확인하는 실험**입니다. 사용자 주장의 중심이 **‘그때 왜 그렇게 말했는지를 기억하는 것이 상담 반응에 어떤 영향을 주는가’**라면, 이 비교는 그 질문의 일부를 확인하는 역할입니다. 제가 앞서 둘을 충분히 구분해서 설명하지 않았습니다.

## 3. A와 B의 차이가 주장을 뒷받침하는지에 대한 답변 원문

사용자 질문:

> 근데 이 실험에서의 A,B차이는 내 주장을뒷받침할 내용이 아닌건가?

답변:

**맞습니다. A/B 차이는 사용자 주장을 뒷받침할 수 있습니다.** 제가 추가로 구분해야 할 효과를 강조하다 보니, 이 실험의 의미를 지나치게 약하게 설명했습니다.

사용자 주장이 다음이라면:

> **과거 발화 당시의 내면을 기억하는 것이 이후 상담 반응을 더 타당하게 만드는 데 도움이 된다.**

같은 상황에서 **A보다 B가 당시 내면과 이후 경험을 적절히 반영한 반응을 반복적으로 생성한다면**, 이를 지지하는 증거입니다.

다만 결과로 주장할 수 있는 범위가 다릅니다.

| 주장 | A/B 비교로 뒷받침 가능한가? |
|---|---|
| 당시 내면 기록을 추가로 제공하면 상담 반응이 개선된다 | **가능** |
| 현재 상태·요약만으로 충분하지 않은 상황이 있다 | **시험한 조건에서 가능** |
| 개선의 원인은 반드시 발화와 내면을 연결한 구조다 | 추가 비교 필요 |
| 기존 연구와 차별화되는 새로운 기여다 | 선행연구 대조와 함께 판단 |

**추가 정보를 제공한 효과여도 연구적으로 의미가 있습니다.** 그 정보가 *왜 상담 반응에 필요하고, 어떤 오류를 줄이는지* 보여주면 됩니다. 다만 **단순히 반응이 달라졌다는 사실보다, 무엇이 더 타당해졌는지를 입증하는 것이 핵심**입니다.

## 4. 공통 대화의 여러 시점에서 분기하는 설계

사용자 제안:

> 2턴까지 공통생성->분기
> 3턴까지 공통생성->분기
> ...n턴까지 공통생성->분기 이걸 반복하는게 정밀한 실험이 될까?

**검토 의견:** 공통 이력의 여러 시점에서 기억 조건을 비교하면, 특정 한 시점의 우연한 차이를 넘어 기억의 추가 효과가 언제 나타나는지 확인할 수 있다. 다만 분기 시점을 늘리는 것과 각 조건의 생성 변동성을 확인하는 반복은 서로 다르다.

### 공통 대화와 분기 대화의 진행

한 공통 대화를 생성하면서 시점별 상태를 저장한다. 각 저장 시점의 독립 복제본에서 A와 B를 비교하고, 분기 결과를 다음 공통 시점 생성에 반영하지 않는다. 예를 들어 A의 3턴 반응을 공통 경로로 채택하면 이후 시점은 이미 A의 결과에 영향을 받은 상태가 된다.

아래의 턴은 상담사 발화와 내담자 응답 한 쌍이 완료된 단위로 정의한 설계 예시다. 실제 구현 시 기존 UI와 저장 기록의 턴 번호에 대응시켜야 한다.

| 저장 시점 | 고정하는 입력 | 비교하는 결과 |
|---|---|---|
| 공통 2턴 완료 후 | 해당 시점 상태와 동일한 3턴 상담사 발화 | A와 B의 3턴 내담자 반응 |
| 공통 3턴 완료 후 | 해당 시점 상태와 동일한 4턴 상담사 발화 | A와 B의 4턴 내담자 반응 |
| 공통 n턴 완료 후 | 해당 시점 상태와 동일한 n+1턴 상담사 발화 | A와 B의 n+1턴 내담자 반응 |

고정 대상에는 공개 이력, 현재 노트, 프로필, 궤적 진행, 모델·생성 설정을 포함한다. 원본 내면 기록은 공통 경로에서 별도로 보존하고, 분기 시점보다 미래의 기록은 제공하지 않는다. A와 B의 실험상 차이는 당시 내면 원본의 추가 제공 여부다. 공통 경로를 어떤 기억 조건으로 생성할지도 명시해야 하며, 결과는 우선 그 경로에서 만난 상태들에 대한 효과로 해석한다.

상담 개입 두 종류를 비교한다면 각 시점에서 개입별로 A/B를 짝지어 총 네 조건을 구성한다. 서로 다른 상담사 발화를 사용한 A와 B를 직접적인 기억 조건 비교로 취급하지 않는다.

### 정밀도를 위해 추가할 요소

- 각 분기 지점의 각 조건을 여러 번 생성해 한 번의 문장 차이와 반복적인 의미 차이를 구분한다. 반복 횟수는 아직 정하지 않았다.
- 과거 내면이 후속 반응에 관련되는 시점과 관련성이 낮은 시점을 함께 관찰한다. 모든 턴에서 B가 더 좋아져야 한다고 기대하지 않는다.
- 특정 과거 발화의 효과를 추적하려면 대상 발화가 무엇인지와 그로부터 경과한 턴 수를 기록한다. 매 시점 여러 원본을 추가하면 전체 기록 묶음의 효과와 특정 발화 기록의 효과를 구별해야 한다.
- 같은 대화에서 나온 여러 분기 지점은 서로 독립된 여러 내담자 사례가 아니다. 이후 여러 사례·공통 대화로 확장해 결과가 반복되는지 확인한다.
- 이 설계의 첫 결과는 고정된 과거에서 다음 한 턴에 미치는 효과다. 장기 상담 궤적에 미치는 영향은 별도의 후속 대화 비교가 필요하다.

**현재 제안:** 기존 Q3p6의 네 항목을 유지하면서, 첫 단계의 한 턴 비교를 공통 대화의 여러 저장 시점에 반복 적용한다. 분기 지점·원본 제공 범위·반복 횟수는 추가 논의 대상이며 아직 구현하거나 실행하지 않았다.

## 5. Q3p6 분기 실행과 UI 설계

사용자 질문:

> 그럼 p6만들때 이걸 어떻게 구현하지? UI에 분기 관련 툴을 구현해야하나?

**제안:** 서버에 과거 상태를 복원하고 조건별 복제본을 실행하는 분기 기능을 만들고, 현재 실험 UI에는 이를 조작하는 작은 분기 비교 패널을 추가한다. 분기는 실험자가 통제하는 기능이며 내담자 LLM이 호출할 도구가 아니다. UI 없이도 같은 서버 실행기를 호출할 수 있게 구성한다.

### 기존 기능에서 활용할 부분

- Q3의 턴 기록에는 `notes_before`, `notes_after`, `trajectory_before`, `trajectory_progress`, 당시 내면 및 공개 발화가 있다. 과거 시점 복원의 기반으로 활용할 수 있다.
- 기존 대조실험 UI는 여러 탭의 설정 적용과 실행을 조율한다. 확인한 코드에서는 이 기능 자체가 공통 과거 상태의 분기를 보장하지 않는다.
- Q3의 로더는 현재 노트 파일과 저장된 이력을 읽는다. 따라서 화면의 공개 대화만 잘라 복제하면 해당 시점의 내면 상태가 재현되지 않는다. 선택 시점의 노트와 진행 상태, 그 시점까지의 기록을 함께 복원해야 한다.

### 서버의 분기 실행 기능

1. **시점 고정:** 완료된 공통 내담자 턴을 선택하고, 그 시점까지의 공개 이력·내면 원본·현재 노트·궤적 진행·프로필을 저장한다. 프롬프트·모델·생성 설정도 고정한다. 기존 저장 기록만으로 복원할 수 없는 설정이 있다면 명시하고, 최신 설정을 과거 설정으로 조용히 대체하지 않는다.
2. **개입 고정:** 다음 상담사 발화를 한 번 준비해 저장하고 A와 B에 동일하게 사용한다. 두 개입을 비교한다면 각 개입 문장을 따로 고정한다. 상담사에게 비공개 자료는 전달하지 않는다.
3. **독립 복제:** 시점 × 개입 × 기억 조건 × 반복별로 별도 실행 ID와 저장 공간을 만든다. A에는 기본 입력, B에는 동일한 기본 입력과 당시 내면 원본을 제공한다. 특성 선택 등 보조 단계가 기억 조건과 무관한 입력 차이를 만들지 않도록 고정된 기본 문맥을 재사용한다. 조건에 따라 이후 내담자가 생성하는 판단은 비교 결과에 해당한다.
4. **한 턴 실행과 저장:** 각 복제본에서 내담자 한 턴을 생성하고 실제 입력·주입 기록·반응·내면 판단·사용량·실패를 남긴다. 각 반복은 원래 저장 시점에서 다시 시작하며 직전 반복의 반응이나 노트를 이어받지 않는다.
5. **일괄 실행:** 같은 실행기를 여러 시점에 적용한다. 작업 목록과 완료 상태를 저장하여 중단·재개 시 완료 결과를 중복 생성하지 않는다. 분기 결과는 공통 경로와 다른 분기에 반영하지 않는다.

저장된 과거 기록을 복제한다고 A에 모든 비공개 내용이 자동 전달되는 것은 아니다. 저장 공간과 모델에 보이는 기억 입력을 구분하고, A가 다른 조회 경로로 원본을 우회해 읽지 않도록 통제한다. B에 제공할 원본의 대상·범위도 실험 설정으로 기록한다.

### UI의 최소 구성

| 조작 | 내용 |
|---|---|
| 기준 대화 선택 | 분기할 공통 세션 선택 |
| 분기 시점 선택 | 특정 완료 턴 또는 2턴부터 n턴까지의 범위 선택 |
| 개입 설정 | 공통 다음 상담사 발화 또는 준비한 두 개입 확인 |
| 반복 설정 | 조건별 생성 횟수와 예상 실행 건수 표시 |
| 분기 비교 실행 | 선택 시점의 A/B 생성과 중단·재개 |
| 결과 보기 | 같은 시점·개입의 A/B 응답을 나란히 표시하고 당시 노트·원본·실제 전달 입력 확인 |

기존의 발화 수 카운터가 상담사와 내담자 발화를 각각 셀 수 있으므로, 분기 UI에는 내담자 응답이 완료된 시점임을 명확하게 표시한다. 모든 분기를 독립된 채팅 탭으로 늘리기보다 기준 대화 아래의 시점별 결과 목록으로 묶는 방식을 우선 제안한다.

**구현 순서 제안:** 먼저 한 시점에서 A/B 한 턴 비교와 결과 확인을 구현하고, 동일 실행기를 이용해 여러 시점·반복·두 개입의 일괄 실행을 확장한다. Q3p6의 기억 입력 조건과 분기 실행 기능을 함께 설계해야 하며, 프롬프트만 추가하는 것으로는 같은 과거 상태의 비교를 보장할 수 없다. 현재는 설계 기록만 갱신했으며 코드 구현은 시작하지 않았다.

## 6. 공통 경로를 한 턴씩 연장하는 자동 순차 분기

사용자 제안:

> n턴 공통생성->분기 작업을 n을 올리면서 자동화하는게 낫지않나? 2턴 공통생성 후 분기 후 추가생성 완료하면 다시 브랜치로 돌아와서 한턴 추가 공통생성하고 또 분기 반복

**현재 설계 방향:** 공통 대화를 끝까지 만든 뒤 분기 시점을 수동으로 선택하는 흐름에 더해, 공통 경로를 한 턴씩 연장하면서 각 시점의 분기 비교를 자동 실행하는 방식을 기본 사용자 흐름으로 삼는다. 여기서 돌아갈 곳은 A나 B의 끝이 아니라 분기 전에 저장한 공통 경로다. 5절의 한 시점 실행기는 이 자동 반복의 내부 구성 요소로 사용한다.

### 자동 실행 순서

```text
공통 경로 2턴 완료와 상태 저장
  → 같은 상태에서 A/B 각각 추가 k턴 생성과 결과 저장
  → 공통 경로의 2턴 완료 상태에서 재개
공통 경로에 1턴 추가하여 3턴 완료와 상태 저장
  → 같은 상태에서 A/B 각각 추가 k턴 생성과 결과 저장
  → 공통 경로의 3턴 완료 상태에서 재개
공통 경로에 1턴 추가하여 4턴 완료와 상태 저장
  → 반복
설정한 마지막 분기 시점의 A/B 실행 완료 후 종료
```

공통 경로의 처음부터 n턴까지를 매번 재생성하지 않는다. 공통 세션은 이어서 한 턴씩 진행하고, 각 분기는 해당 시점의 독립 복제본에서 진행한다. 분기 결과를 공통 경로의 다음 턴으로 채택하거나 공통 노트에 합치지 않는다. 기술적으로는 공통 저장 공간을 그대로 유지하고 실행 대상을 다시 공통 세션으로 바꾸는 방식이므로, 원본 기록을 덮어썼다가 되돌릴 필요가 없다.

공통 경로의 기억 조건과 생성 규칙은 실행 전에 고정한다. 다음 공통 턴을 어떤 규칙으로 생성할지를 A/B 결과를 보고 바꾸지 않는다. 각 분기의 첫 상담사 발화는 해당 개입별로 한 번 준비해 A/B와 반복 실행에 동일하게 사용한다. 공통 경로에서 사용할 다음 상담사 발화도 비교 결과에 따라 선택하지 않는다. 두 개입 비교를 사용할 경우 시점별로 각 개입의 A/B 실행을 완료한 다음 공통 경로를 한 턴 진행한다.

### 추가 생성 길이의 의미

- `k=1`: 동일한 과거와 상담사 발화에 대한 다음 내담자 반응의 차이를 비교한다. 첫 구현의 기본값으로 제안한다.
- `k>1`: 각 분기에서 후속 상담을 이어가며 대화 전개의 차이를 비교한다. 첫 반응 이후에는 공개 이력·노트가 달라지므로 후속 턴은 동일 입력 비교가 아니다. 상담사가 각 분기의 반응에 맞춰 생성하도록 할지, 준비된 개입을 공통 적용할지도 별도로 명시한다.
- 분기에서 생성한 k턴은 공통 경로의 n에 포함하지 않는다. 마지막 분기 시점이 N이면 해당 분기는 N 이후 k턴까지 생성할 수 있다.

### UI와 실행 상태

UI에서는 분기 시작 턴, 마지막 분기 턴, 분기 후 추가 생성 턴 수, 조건별 반복 횟수, 개입 설정을 지정하고 자동 실행을 시작한다. 기본 진행 간격은 공통 경로 1턴이다. 화면에는 현재 공통 턴, 실행 중인 조건·개입·반복, 완료된 분기 결과를 표시한다.

서버는 공통 세션 ID, 저장 시점, 분기 실행 ID, 완료 여부와 실패 기록을 유지한다. 중단 후에는 미완료 작업에서 재개하고 이미 완료된 비교를 중복 생성하지 않는다. 완료 기준을 충족하지 않은 분기는 완료로 처리하지 않으며, 원본 공통 상태와 다른 분기의 기록은 유지한다.

**현재 상태:** 자동 순차 분기를 중심으로 설계를 구체화했다. 공통 경로의 기준 기억 조건, 반복 횟수, 원본 제공 범위 등은 아직 확정하지 않았으며 코드 구현과 실제 생성은 시작하지 않았다.

## 7. 상담 개입과 상담사 프롬프트 설계

사용자 질문:

> 이번에는 상담개입도 정해보자. 이건 상담사 프롬프트를 건드려야하나?

**제안:** Q3p6용 상담사 지침을 따로 마련하고, 개입 조건과 실행 시점은 분기 실행기가 지정한다. 프롬프트는 발화 내용과 말투를 통제하고, 코드는 같은 시점에 같은 개입 문장을 A/B에 전달하는 것을 보장한다. 기존 Q3p4 상담사에는 유사한 두 개입이 있으므로 설계와 단일 프롬프트 호출 구조를 참고할 수 있지만, 기존 버전의 프롬프트 자체를 변경하지 않는다.

### 공통 경로와 비교 개입의 역할

- **공통 경로 상담사:** 공개된 고민에 맞는 상담을 진행한다. 작은 제안과 반응 등 후속 개입의 대상이 될 장면을 만들 기회는 제공하되, 내담자의 동의·저항이나 특정 비공개 의도를 강제하지 않는다. 분기에서 나온 반응이나 평가를 입력받지 않는다.
- **비교 개입 생성:** 분기 시점의 공개 이력, 미리 지정한 대상 발화, 개입 유형만 받아 다음 상담사 발화 하나를 준비한다. 기억 조건 A/B, 내담자의 비공개 기록, 현재 노트, 평가 결과는 받지 않는다. 두 역할은 같은 모델을 별도의 지침으로 호출해 구현할 수 있다.

### 첫 개입 쌍의 제안

이전에 논의한 수락 장면을 첫 실험 대상으로 삼고, 기억 조건 A/B와 혼동하지 않도록 상담 개입은 I1/I2로 표기한다.

| 개입 | 조작할 차이 | 설명용 예시 |
|---|---|---|
| I1 실행 구체화 | 공개 수락을 현재 실행 의향으로 전제하고 구체적 계획을 묻기 | “앞서 짧게 기록해보겠다고 하셨는데, 언제 해보면 좋을까요?” |
| I2 현재 의향 확인 | 실행 계획을 묻기 전에 현재 의향을 열어두고 확인하기 | “앞서 짧게 기록해보겠다고 하셨는데, 지금은 그 제안이 어떻게 느껴지세요?” |

대상 행동과 인용하는 과거 발화는 동일하게 유지하고, 두 개입 모두 짧고 정중하며 질문은 하나로 제한한다. I1을 공격적이거나 강압적으로 만들지 않고, I2에서 “거절하기 어려우셨죠?”처럼 비공개 이유를 제시하지 않는다. I2가 항상 더 좋은 개입이라는 결론이나 I1에서 반드시 저항해야 한다는 정답을 설정하지 않는다.

이 개입 쌍은 동의와 실행 의향의 차이를 다루는 첫 사례 유형이다. 모든 내면 상태나 보류·거절 장면에 그대로 적용할 수 있는 범용 개입으로 취급하지 않는다. 초기에는 이 쌍으로 비교하고, 다른 발화 유형은 대상에 맞는 개입 쌍을 추가로 설계하는 방안을 제안한다.

### 개입 문장의 고정과 조건 조합

각 분기 시점에서 I1과 I2를 각각 한 번 생성하거나 준비한 문장 틀에 공개된 대상 정보를 넣어 작성한다. 문장을 확인하고 저장한 후, 해당 시점의 모든 기억 조건과 반복에 그대로 재사용한다. A용과 B용 상담사 발화를 별도로 생성하지 않는다.

| 조건 | 내담자 기억 | 상담사 발화 |
|---|---|---|
| A × I1 | 현재 상태와 이유 포함 노트 | 저장된 I1 문장 |
| B × I1 | A의 입력과 당시 내면 원본 | A × I1과 동일한 문장 |
| A × I2 | 현재 상태와 이유 포함 노트 | 저장된 I2 문장 |
| B × I2 | A의 입력과 당시 내면 원본 | A × I2와 동일한 문장 |

기억 효과는 같은 개입 안에서 A/B를 비교한다. A × I1과 B × I2만 비교하면 기억과 상담 개입이 동시에 달라진다. 개입에 따른 기억 효과의 차이를 주장하려면 두 개입 각각의 A/B 차이를 함께 살펴야 한다.

### 매 턴 자동 분기와 개입 적용 가능성

공통 2턴, 3턴, …에서 자동으로 비교를 시도하더라도, 아직 공개 수락 장면이 없거나 이미 철회된 경우에는 이 개입 쌍을 억지로 적용하지 않는다. 비교 대상을 정하는 규칙은 생성 전에 정하며, 적합하지 않은 시점은 사유와 함께 미수행으로 남기고 공통 경로를 진행한다. 중간에 이유가 공개된 경우에도 실제 이력을 그대로 보존하고 공개 여부를 기록한다. 대상 발화 ID와 경과 턴 수를 남겨 시점마다 대상이 달라지는 효과를 구분한다.

개입 적합성은 공개 이력을 기준으로 판단하고, 비공개 의도를 읽어 효과가 잘 나올 대상만 선택하지 않는다. 사용자가 실험 목적상 특정 내면 사례를 별도로 선정할 경우에는 그 선정 조건과 적용 범위를 명시해야 한다.

**현재 상태:** I1/I2는 이전 논의에 맞춘 첫 개입 쌍의 제안이며, 아직 확정된 상담사 프롬프트나 실행 코드가 아니다. 이번 갱신은 설계 문서에 한정한다.

## 8. 프롬프팅과 동일 개입 전달 코드의 역할

사용자 질문:

> 어떻게 구현한다는거야? 프롬프팅으로 상황에 따라 어떻게 말하도록 모두 조절? '개입 문장을 한 번 생성해 A/B에 동일하게 전달하는 코드'는 무슨말?

**설명:** 프롬프트는 상담사가 어떤 종류의 발화를 작성할지 지시한다. 프로그램은 어느 저장 시점에서 어떤 개입 유형을 요청하고, 생성된 문장을 어느 내담자 조건에 전달할지 제어한다. 상담사 LLM이 분기 시점, A/B 배정, 반복 실행까지 스스로 결정하게 하는 설계는 아니다.

예를 들어 공통 5턴까지 완료했고, 공개 이력에 기록하기 제안에 대한 수락이 있다고 가정한다.

1. 프로그램은 공통 5턴의 공개 이력, 대상 발화, I1 지침을 상담사 모델에 전달한다. 지침의 요지는 “해당 수락을 실행 의향으로 받아들이고, 같은 행동의 실행 시점을 정중하게 질문 하나로 물어라”이다. 이는 설명용 지침이며 최종 프롬프트는 아니다.
2. 상담사 모델이 “앞서 기록해보겠다고 하셨는데, 오늘 어느 시간에 해보면 좋을까요?”라는 문장 X를 생성한다. 프로그램은 X를 저장한다.
3. 프로그램은 공통 5턴 상태를 복제한 A에 기본 입력과 X를 전달해 내담자 반응을 생성한다.
4. 프로그램은 동일한 공통 5턴 상태를 복제한 B에 같은 기본 입력과 당시 내면 원본, 그리고 **동일한 X**를 전달해 내담자 반응을 생성한다.
5. I2도 별도로 한 문장 Y를 준비한 뒤, A와 B에 같은 Y를 전달한다. 같은 시점·개입에서 반복 생성할 때도 저장한 X 또는 Y를 재사용한다.

```text
공통 5턴의 공개 이력 + I1 작성 지침
                  ↓ 상담사 모델 한 번 호출
             상담사 문장 X 저장
                  ├─ A 내담자 입력에 X 전달 → A 반응
                  └─ B 내담자 입력에 X 전달 → B 반응
```

“같은 문장을 전달하는 코드”는 모델이 생성한 문자열을 저장하고 두 내담자 요청에 재사용하는 실행 로직이다. A를 위해 상담사 모델을 한 번 호출하고 B를 위해 다시 호출하면 문장 자체가 달라질 수 있으므로, 같은 지침을 사용했다는 것만으로 동일 개입이 보장되지 않는다.

프로그램이 I1이라는 요청을 지정해도 LLM이 의미적으로 그 지침을 지켰다고 자동으로 보장되지는 않는다. 실제 문장이 지정한 대상·개입에 맞는지 확인하고, 미준수는 별도로 기록해야 한다. 공개 이력에서 적합한 대상 장면을 고르는 구체적인 판정 방법은 아직 설계해야 한다.

이 원칙은 같은 과거에서 시작하는 첫 개입에 적용한다. 분기 이후 여러 턴을 생성하면 각 분기의 대화가 달라지므로, 후속 상담사를 어떻게 운영할지는 6절의 다회기 분기 설정과 구분해 정한다. 아직 프롬프트나 분기 코드를 구현한 상태는 아니다.

**판단:** 현재까지의 설계로 구현에 착수할 수 있다. 아래 선택은 실행 설정으로 분리할 수 있으며, 연구 결과나 최종 실험 설계가 확정됐다는 뜻은 아니다. 이 절은 추천 기본값을 기록하며 아직 코드 구현 지시는 아니다.

전체 내면 원본 제공이 모델 입력 한도를 초과하면 기록을 조용히 잘라 동일 조건으로 처리하지 않는다. 초과를 표시하고 실행 범위나 예산을 명시적으로 조정하도록 한다. 전체 기록을 추가하는 비교 결과는 기록 묶음의 추가 효과이며, 특정 한 턴의 효과로 바로 귀속하지 않는다.

첫 구현에서는 공개 이력에 근거한 대상 발화 제안과 생성된 I1/I2 문장을 확인할 수 있게 한다. 적합성 기준은 공개된 실제 수락 여부, 이후 공개 철회 여부, 대상 행동의 일치 여부 등으로 명시한다. 자동 판정의 출력과 근거를 저장하고, 애매한 경우에는 미수행으로 남길 수 있어야 한다. 비공개 기록을 근거로 효과가 잘 나올 장면만 선택하지 않는다. 실행 전에 개입 문장을 점검하는 수동 모드를 제공할 수 있으나 자동 순차 실행을 매번 확인 대기로 막지는 않는다.

완전한 연구 검증에는 반응 타당성 평가 기준과 사례별 가능한 반응 범위를 생성 전에 정하는 작업도 필요하다. 실행기 구현과 의미적 효과 입증은 구분한다. 자동 관찰자만으로 우월성을 확정하지 않는다.

위 기본값에서 모든 시점이 적합하면 19개 분기 시점 × 개입 2종 × 기억 조건 2종 × 반복 3회로 내담자 분기 응답은 228개다. 공통 경로 생성, 상담사 개입 생성, 라우터 등 내부 호출은 별도이므로 모델 총 호출 수와 동일하지 않다. UI에는 실제 선택 설정에 따른 예상 생성 건수를 표시한다.

**구현 범위:** Q3p6 내담자 입력 구성, 공통 경로와 분기 실행기, 상담 개입 생성, 자동 실행·중단·재개 UI, 조건별 결과 비교와 입력 기록을 포함한다. 구현 후 자동으로 실제 모델 실험을 시작하는 것으로 해석하지 않는다.


## 10. Q3p6 구현 결과

사용자 지시: “이제 Q3p6제작시작”

9절의 기본값으로 실행기와 전용 UI를 구현했다. 사용 방법은 [README.md](README.md)에 정리했다. 기존 서버를 재시작하고 작업 공간의 **Q3p6 분기 실험** 링크 또는 `/q3p6`로 접근한다. 설정 저장과 모델 실행은 별도 동작이다.

## 11. 첫 실행 점검 후 수정: revision 2

사용자 요청: 사례 입력·상담사 흐름·분기 조건·후속 개입을 수정하고, 실시간 workflow와 연구 사례 검토를 UI에서 확인할 수 있게 한다.

### 관찰과 변경 이유

첫 실행 `p6_f3903a9bf2324f3f`는 공통 8턴을 완료했지만 4~8턴 모두 명확한 수락 장면이 없다는 이유로 미수행이었다. A/B 반응은 0개였다. 직장인 프로필에 연구실 초기 대화가 남았고 이미 대화 중인데 첫 인사도 추가됐다. 이는 기억 효과가 없다는 증거가 아니라 비교가 성립하지 않은 실행이다. 원본 실행 기록은 유지한다.

### 변경 내용

1. 기본 시작 방식을 프로필 기반 새 상담으로 바꾼다. 기존 초기 대화·출처를 제거한다. 직접 대화를 구성해 이어가는 모드에서는 내담자로 끝나는 대화와 맥락에 맞는 후속 질문을 요구한다.
2. 상담사가 초반 탐색 후 구체적 제안을 하도록 흐름을 명시한다. 수락·거절·보류는 강제하지 않는다.
3. 지정한 턴에서 분기한다. 명확한 수락을 분기 조건으로 삼지 않는다. 애매한 장면도 공개 발화 기반 질문을 준비하고 관련성이 약함을 표시한다. 질문 생성 오류는 중단·오류로 기록한다.
4. 기본 개입은 한 개다. I1은 대상 발화의 맥락을 잇는 질문이며, 선택 가능한 I2는 같은 주제의 부담·선택권·속도를 확인하는 질문이다. 이전 설계의 수락 전제 ‘실행 구체화’ 쌍과 구분한다.
5. 가능하면 현재 턴보다 앞선 발화를 대상으로 하며 경과 턴 수를 표시한다. 질문은 공개 이력만으로 한 번 생성해 동일하게 A/B에 전달한다. 내면 원문은 질문 생성 후 검토 화면용으로 별도 수집한다.
6. UI에서 공통 생성 → 질문 준비 → A → B → 다음 공통 턴, 현재 개입·반복·발화 생성과 저장 상태를 약 1.5초 간격으로 보여준다. 완료 응답과 현재 공통 대화도 확인할 수 있다.
7. 실행 완료와 사례 적합성 검토를 분리한다. 대상 발화·당시 내면·질문·A/B 반응을 함께 확인하고 미검토/분석 후보/부적합 및 메모를 저장한다. LLM의 공개 관련성 표시나 사용자 후보 표시는 가설 입증이 아니다.

### 적용과 한계

수정된 설계는 새 실험에 적용한다. 기존 결과를 재분류하거나 생성된 대화를 수정하지 않는다. 이전 소스로 만든 실험은 소스 변경 검사가 적용되므로 그대로 재개해 서로 다른 설계를 섞지 않는다.

기본 최대 분기 응답은 114개(19시점 × 1개 개입 × A/B × 3회), 두 개입 모드는 228개다. 사례를 늘리는 것만으로 연구가 성립하지 않으며, 실제로 관련 있는 과거 내면이 생성됐는지와 요약에 이미 보존돼 있는지 등을 원문에서 검토해야 한다. 실제 모델 실험은 자동 실행하지 않는다.

검증 결과: Q3p6 모의 테스트 16개, 기존 기능 회귀 테스트 46개, 브라우저 검증 통과. 일시정지 직전에 완료된 응답도 결과에 바로 반영된다. 최초 실제 실험의 이전 형식 기록도 읽기 호환성을 확인했다. 상담사 프롬프트가 실제 모델에서 원하는 궤적을 만드는지와 기억 효과의 의미적 타당성은 이후 새 실행에서 확인해야 한다.


## 12. 자연스러운 후속 질문과 독립 C 대조: revision 3

당시 내면을 명시적으로 생성하지 않는 C를 추가한다. A의 노트·내면을 제거한 체크포인트 복제는 이전 생성 과정의 영향을 남기므로, 같은 초기 사례에서 독립적으로 생성한다. A/B 분기는 유지하고 A/C 전체 경로 비교와 구분한다. A 공통 경로는 A 반복 1로 재사용한다. 독립 경로의 후속 상담사·특성 선택은 각각의 공개 대화에 따라 달라진다.

C는 프로필 라우터 → 직접 발화 생성 → 공개 대화 인용 노트 갱신으로 실행하며, 명시적 내면·발화 의도·표현 계획·궤적 기록을 만들지 않는다. 노트는 C의 실제 발화 인용만 검증하여 남기고, A/B 내면 자료를 전달하지 않는다. 이 비교는 노트 방식도 포함한 전체 과정 비교이며 원본 기억 효과만으로 귀속하지 않는다.

고정 1·3·5턴 후 같은 질문을 의무적으로 주지 않는다. 현재 주제와 자연스럽게 연결되는 시점을 기본 분기 대상으로 삼고, 부자연스러우면 사유를 보존한다. 수락 여부나 예상 효과는 제외 기준이 아니다. 같은 시점의 A/B 질문은 동일하되 다른 시점은 달라질 수 있으므로 순수 시간 효과로 해석하지 않는다. 모든 지정 시점 탐색 옵션도 유지한다.

기본 반복은 5회, 분기는 1턴이며 별도 3턴 실행으로 후속 궤적을 관찰할 수 있다. C 비교는 선택 가능하고 독립 A/C도 기본 5회다. 기본 20턴 설정의 최대 내담자 응답은 A/B 분기 190개 + 독립 A/C 200개(공통 A 포함)로 390개다. 설정 저장과 모델 실행은 분리한다.

상담사에게 변화·개선을 유도하는 질문을 반복하지 않도록 하고, 현재 선택·필요·의향과 보류·거절을 열어둔다. 균형 잡힌 욕구를 포함한 연구실 사례는 사용자가 선택해 불러오며 기존 프로필을 강제 교체하지 않는다.

UI는 독립 경로 진행과 A/B 분기를 구분한다. 원본 분석 자료와 조건 이름을 가린 공개 대화 자료를 내보낸다. 평가 기준은 생성 전에 정하되 사후 분석에 적용하며, 생성 로직에서 contribution 지지 여부를 판정하지 않는다. 현재 작업에서는 실제 모델 실험을 자동 실행하지 않는다.

검증: 모의 P6 테스트 19개, 기존 기능 회귀 테스트 46개, 브라우저 확인 통과. C는 원본 내면뿐 아니라 그 내용을 옮긴 A 노트도 받지 않는 것을 검사했다. C 노트 생성 실패 후 재개해도 완료된 A/B 응답은 유지된다. 자연스러운 재연결 판정 자체의 타당성은 이후 실제 대화에서 확인해야 한다.

## 추가 논의: 당시 의도 재질문 모드

사용자 제안: 공통 대화에서 분기한 뒤, 과거 발화를 왜 했는지 같은 상담사 문장으로 다시 물어 반응을 비교한다.

revision 4는 UI에서 기존 맥락 질문과 고정 재질문을 선택한다. 공개 이력으로 과거 발화만 선택하고, 인용 검증 후 사용자 편집 가능한 템플릿으로 질문을 한 번 확정한다. 숨은 정답을 질문에 넣지 않는다. 모든 지정 시점·단일 개입으로 동작하며 최신 턴은 대상에서 제외한다. 실제 질문과 선택 요청은 저장하고 A/B 반복에 공유한다. 자연스러운 상담을 재현했다는 주장이 아니라 회상·일관성의 탐색이다.

C는 기존 독립 경로이며 같은 체크포인트 C가 아니다. 기존 C 실패는 실제 인용의 메시지 번호 불일치였다. 입력에 번호를 명시하고, 잘못된 번호에 한해 원문이 한 메시지에만 정확히 일치하면 보정한다. 원래 출력과 보정 내역을 보존하며, 없는 인용·모호한 위치는 계속 오류로 처리한다. 기존 실험 파일을 소급 수정하거나 실제 모델로 재개하지 않았다.

## 추가 논의: C에도 재질문 적용 (revision 5)

사용자는 C에도 과거 특정 발화를 재질문하여 A와 반응을 비교하기를 요청했다. 당시 의도 확인 모드에서 C를 포함하면 모든 독립 A/C 경로에 같은 템플릿·지정 분기 시점·응답 반복 수를 적용한다. A의 첫 경로는 기존 A/B 분기 중 A를 재사용하고, 나머지 경로는 자기 과거 발화를 공개 이력만으로 선택한다. 질문은 시점별 한 번만 확정하며 각 응답 반복에 공유한다.

재질문은 본 경로의 복사본에서 실행하며, 응답을 본 경로에 반영하지 않는다. C에는 자기 공개 노트와 기록만 복사한다. UI에 별도 A/C 재질문 비교 표·진행 수를 표시하고 상세 입력·내보내기·오류 재개를 지원한다. A/C는 대화와 대상 발화가 다르므로 이 비교로 역사적 기억만의 효과를 분리했다고 주장하지 않는다. C의 당시 비공개 의도는 정답 기록이 없으므로 공개 이력에 대한 설명의 타당성으로 평가한다.
