# Q3p1–Q3p5 — 주장별 기억 대조실험

> 구현된 실험 장치입니다. 다섯 주장의 효과나 신규성이 입증됐다는 뜻은 아닙니다.

## 버전과 기본 조건

| 버전 | 주장 | 기본 기억 조건 | 선택 가능한 대조 조건 | 추가 모델 호출 |
|---|---|---|---|---|
| Q3p1 | C1: 현재 상태·의도 포함 요약의 실패 조건 | `summary_only` | `intent_linked`, `linked_prose` | 없음 |
| Q3p2 | C2: 발화–의도 연결의 효과 | `intent_linked` | `intent_unlinked`, `linked_prose` | 없음 |
| Q3p3 | C3: 당시 기록과 사후 해석 | `retrospective` | `intent_linked` | 대상 과거 턴이 있는 사후 해석 조건에서 턴당 1회 |
| Q3p4 | C4: 상담 개입에 대한 반응 | `intent_linked` | `summary_only` | 발화 생성 후 개입 반응 관찰자 1회 |
| Q3p5 | C5: 상담 진전 평가에 대한 영향 | `intent_linked` | `summary_only` | 발화 생성 후 공개 자료/의도 포함 자료로 진전 관찰자 각각 1회 |

실험 UI에서 버전을 선택하면 **의도 기억 대조 조건** 선택기가 나타납니다. 조건은 세션 시작 시 저장·고정됩니다. 동일 버전을 여러 탭에 두고 조건을 달리할 수 있습니다. 기존 대조실험 컨트롤러로 각 탭을 실행할 수 있습니다. 생성할 모델·상담사·초기 사례·시드·개입은 사용자가 정합니다. 이 구현 작업에서는 실제 모델 실험을 실행하지 않았습니다.

API 요청에서는 다음과 같이 지정합니다. 생략하면 버전별 기본값을 사용합니다.

```json
{
  "experiment_version": "Q3p2",
  "claim_memory_condition": "intent_unlinked"
}
```

## Q3에서 유지한 부분과 공통으로 달라지는 부분

- Q3의 기존 소스·프롬프트를 수정하지 않습니다. Q3 런타임을 버전별 독립 모듈로 로드하고 어댑터를 적용합니다. 각 버전은 별도의 도구 객체·잠금·프롬프트·궤적·저장 경로를 가집니다.
- `stage_client_update → commit_client_utterance → update_client_notes → update_trajectory_progress` 순서, 같은 턴의 reasoning·도구 기록, 전체 성공 후 상태 확정은 Q3를 재사용합니다.
- 다섯 버전 모두 현재 노트를 **전체 제공**합니다. 현재 노트 선택 누락이 과거 의도 기억 효과와 섞이지 않도록 공통으로 고정한 조건입니다. 특성·배경 라우터는 유지하되 노트 ID를 선택하지 않습니다. 따라서 기존 Q3와의 비교에는 이 공통 차이도 있습니다.
- `retrieve_client_memory`는 다섯 버전 모두 `current`만 제공합니다. `episodes/changes/trajectory` 원본 이력으로 기억 조건을 우회하는 조회는 코드에서 차단합니다. 과거 기록 자체는 삭제하지 않습니다.
- 과거 의도 자료는 선택적 검색 대신 **자동 주입**합니다. 기억 내용·연결 비교와 검색 정책 효과를 우선 분리하기 위한 통제입니다. 관련 턴을 정답처럼 골라주는 의미의 oracle retrieval은 아닙니다.
- 최초 입력용 공개 대화에 원래 비공개 기록이 없는 경우 그 의도를 만들어 원본으로 취급하지 않습니다. 이 버전에서 완료·저장한 과거 턴이 있어야 당시 기록을 제공할 수 있습니다.

## 기억 조건의 정확한 의미

| 조건 | 메인에 추가되는 자료 |
|---|---|
| `summary_only` | 과거 의도 자료 추가 없음. 공개 대화·현재 노트·최신 궤적 진행은 유지 |
| `intent_linked` | 과거 턴 ID·상담사 발화·내담자 발화 + 해당 턴의 최종 appraisal/turn_goal/response_plan |
| `intent_unlinked` | 같은 appraisal/turn_goal/response_plan 객체들의 집합. 명시적인 턴 ID·공개 발화 연결과 원래 순서는 제거 |
| `linked_prose` | 동일한 기록과 연결 관계를 서술형 문장으로 직렬화. 별도의 LLM 압축·요약 호출은 하지 않음 |
| `retrospective` | 기본 프로필과 공개 대화만 본 보조 모델이 대상 턴별로 재구성한 의도 가설·근거·불확실성 |

`summary_only`의 요약은 Q3의 현재 노트 갱신으로 유지합니다. 의도 포함을 금지하거나 일부러 이유를 삭제하지 않습니다. 다만 요약이 실제로 무엇을 보존했는지는 결과에서 확인해야 합니다.

`linked_prose`는 연결된 정보가 자연어 표현으로도 충분한지 보는 **내용 보존 표현 대조군**입니다. 학습된 강한 요약기나 압축률을 통제한 요약 기준선까지 구현했다고 해석하지 않습니다.

`intent_unlinked`도 본문의 의미나 공개 대화로 원래 연결을 추론할 수 있습니다. 이 조건은 명시적 연결 제거이며, 연결을 완전히 식별 불가능하게 만드는 익명화가 아닙니다.

최근 완료 턴 최대 12개를 대상으로, 원본 행 JSON의 합계 18,000자까지 **완전한 턴 단위**로 선택합니다. 큰 턴은 중간을 잘라 의미를 바꾸지 않고 제외하며 제외된 턴을 기록합니다. 이 선택은 표현 변경 전에 하므로 조건별로 같은 대상 턴을 사용합니다. 전체 세션의 모든 턴을 제공하는 실험이 아닙니다. 토큰 수가 자동 일치하지 않으므로 실제 문자 수와 요청·사용량을 함께 확인해야 합니다.

사후 해석 담당은 현재 노트·원래 비공개 의도·과거 평가 기록을 받지 않습니다. 그러나 메인 내담자는 모든 조건에서 현재 노트를 받으므로, 그 노트에 남아 있는 과거 의도를 활용할 수 있습니다. 당시 기록 보존과 사후 추론의 비교에는 **관찰 가능한 정보의 차이 및 추가 호출 비용**이 포함됩니다.

## Q3p4·Q3p5 관찰자의 역할

Q3p4는 확정된 발화에 대해 현재 개입, 반응, 과거 의도와의 연결, 현재 변화, 불확실성을 서술합니다. 다른 개입에 대한 반사실적 반응을 자동 생성하지 않습니다. 같은 공개 맥락에서 개입을 달리한 실험을 별도로 구성해야 합니다.

Q3p5는 같은 확정 발화를 두 번 독립 호출로 관찰합니다.

1. **public_only:** 공개 대화와 이번 상담사·내담자 발화만 제공합니다.
2. **intent_informed:** 위 자료에 선택된 과거 원본 의도와 이번에 확정한 내면 판단을 추가합니다.

두 관찰자는 같은 지침과 스키마를 사용하며, 앞 관찰자의 출력은 뒤 관찰자에게 전달하지 않습니다. 두 결과의 차이는 정보 접근에 따른 판단 차이이며, 어느 평가가 정확한지나 상담 진전이 실제로 왜곡됐는지를 자동 판정하지 않습니다.

관찰자는 클라이언트와 같은 설정의 모델을 별도 호출합니다. 이 결과는 독립적인 전문가 평가나 임상 점수가 아닙니다. 전체 입력과 판단 근거를 읽고 해석해야 합니다. 관찰자 결과는 다음 턴의 내담자·상담사 입력이나 현재 노트에 주입하지 않습니다. 상담사에게는 기존처럼 공개 발화만 전달합니다.

## 기록과 실패 처리

기존 Q3 턴 기록에 `claim_experiment`를 추가합니다.

- `claim`, `memory_condition`: 주장 ID와 해당 세션의 기억 조건.
- `memory_view`: 대상 턴, 제외 턴, 한도, 실제 주입 자료와 출처·문자 수.
- `auxiliary_calls`: 재구성·관찰자별 실제 요청, 지침 원문, 결과, 사용량.
- `note_policy`, `archive_lookup`, `observer_policy`: 전체 노트·원본 조회 차단·관찰자 비환류 조건.

재구성·관찰자 호출은 생성 과정 화면의 별도 보조 호출로 표시됩니다. 사용량은 저장 기록과 최종 응답에 합산합니다. 보조 호출도 정상 종료와 스키마를 검사합니다. 실패·중단 시 전체 턴을 실패로 남기고 공개 발화·현재 노트는 확정하지 않습니다. 이미 스트림으로 남은 실패 응답과 요청은 기존 시도 기록에서 보존합니다.

## 대조실험 해석 원칙

- 주장 하나를 검증하려면 해당 버전 안에서 필요한 대조 조건을 비교합니다. 다섯 버전의 기본값만 서로 비교해서 다섯 주장을 입증할 수는 없습니다.
- 먼저 같은 공개 맥락·현재 노트·프로필에서 조건을 바꿔 비교하는 재생 실험을 설계해야 합니다. 장기 폐루프에서 별도 세션을 생성하면 공개 대화·현재 노트도 점차 달라집니다.
- 의도 정보가 추가된 효과, 발화 연결의 효과, 형식·토큰 길이의 효과를 구분합니다.
- 과거 당시 의도와 현재 의도를 구별합니다. 당시 의도는 시뮬레이션의 확정 기록이며 인간의 숨은 마음에 대한 정답이 아닙니다.
- 회상·역사적 일관성·개입 반응·진전 평가를 별도 결과로 취급합니다. 일관성이 좋아졌다고 실제 상담 효과까지 입증되지 않습니다.
- 다섯 후보는 모두 열어둡니다. 이 구현은 후보의 선별이나 연구 결과를 대신하지 않습니다.

## 검증

`tests/test_claim_experiments.py`는 실제 모델 대신 모의 HTTP 모델로 등록·조건별 입력·조회 우회 차단·다섯 버전의 2턴 실행·보조 호출 분리·사용량·실패 롤백을 검증합니다. 실행 예:

```bash
PYTHONPATH=src:tests:experiments PYTHONDONTWRITEBYTECODE=1 \
  python3 -m unittest test_claim_experiments
```

브라우저 검증은 `node tests/browser_claim_experiments.cjs`로 실행합니다. 기존 프로젝트의 Puppeteer 설치를 사용하며, 다른 경로에서는 `PUPPETEER_MODULE`을 지정할 수 있습니다. 모의 서버로 조건 선택·탭 초안 복원·세션 조건 고정·내담자 2턴 생성·관찰 결과·노트 화면·새로고침 복원을 확인합니다.

2026-10-31 구현 검증: Q3 계열·기억 실험·프롬프트·노트 API 회귀 61개 통과, 최종 주장 실험 테스트 11개 통과, Q3p1–Q3p5 브라우저 검증 모두 통과. 실제 모델 응답의 의미적 품질이나 연구 가설의 효과를 검증한 결과는 아닙니다.
