# 실험 질문

매 응답에서 내면상태와 근거를 기록하고 다음 턴에 누적 기록 전체의 통합 trajectory를 제공하면, 공개된 발화와 내면상태의 관계를 더 일관되게 이어갈 수 있는가? 전체 공개 히스토리는 메인에게 제공하고, 요약 담당에게는 누적 내면 기록과 각 반응을 촉발한 상담사 발화만 제공한다.
요약에서 빠진 이유를 확인해야 할 때 명시된 기준에 따라 원문 조회가 이루어지는가?

## 이번 변경의 범위

상담사 발화와 모델 실행 지침을 구분하고, 저장된 공개 발화로 매 턴 새 프롬프트를 구성한다. 내면 조회는 턴 번호 대신 상담사의 말·받아들인 의미·반응 이유를 질문으로 찾으며, 같은 Gemma 조회 담당이 관련 원문 하나를 선택한다. 요약은 공개 대화 전체를 다시 요약하지 않고 누적 내면 기록의 인과 흐름을 통합한다. 기존 basic과 실험 원문은 보존한다. 내담자 최종 JSON 출력 보정, 조회 메모 추가, 자동 정정·평가 루프는 이번 변경에 포함하지 않는다.

도구 사용 지시를 상담사 발화에 넣었던 이전 10회 실험의 7~10회는 자연스러운 상담에서의 도구 선택·반응 평가 근거에서 제외한다.

# 관찰할 내용

- 현재 상담사 발화에 따른 상태 유지·변화의 근거가 있는가?
- 공개된 발화와 내면상태의 차이를 설명할 수 있는가?
- 다음 턴의 요약이 누적 기록 전체의 인과 흐름과 남은 걱정을 보존하는가? 턴별 나열 대신 통합적인 흐름을 만드는가?
- 상태 수준의 유지를 상승·하락으로 바꾸거나 초기 히스토리의 미기록 속마음을 만들지 않는가?
- 조회가 필요한 조건에서 호출하고, 충분한 정보가 있을 때 불필요한 조회를 피하는가?

호출 수만으로 효과를 판단하지 않는다. 실패·미완료 출력도 실행 로그에 남긴다. 현재 단계에서는 대량 생성이나 조건별 성능 비교를 하지 않는다.
