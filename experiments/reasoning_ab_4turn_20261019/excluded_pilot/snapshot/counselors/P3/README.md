# P3: 상담 접근 선택과 작업 연속성

P2를 비교 기준으로 유지하고, 단일 상담사 모델이 두 노트와 공개 대화로 현재 상황을 파악하며 Common / MI / CBT를 선택·조정하는 실습 버전입니다.

## 실행과 UI

기존 `gemma_test/run_counseling.sh`로 UI 서버를 재시작하고 브라우저를 새로고침합니다. **새 대화 → 실험 설정 → 상담사 → P3**에서 선택하세요. P3 시스템 지침은 같은 설정 화면에서 편집할 수 있으며, 생성한 세션은 당시 버전과 지침을 유지합니다. 별도 vLLM 설정이나 실행 스크립트는 필요하지 않습니다.

기존 UI에서 reasoning 원문 → 도구 호출·진행 상태 → 해당 호출의 노트 추가·삭제 → 다음 reasoning → 실제 발화 순서로 표시합니다. 기본 펼침과 최근 압축 스타일을 유지합니다. 전체 노트는 **전체 노트 보기**, 도구 인자·반환은 **호출 상세**, 실제 입력은 Raw 컨텍스트에서 확인합니다. 기법은 별도 Python 상태로 파싱하지 않으며 모델이 노트에 기록한 내용으로 확인합니다.

## 노트와 도구

- `paired/<session_id>/notes.md`: 현재 고민(presenting_concern), 원하는 도움(desired_help), 초점의 확인·협의 여부(focus_status), 확인된 내담자 정보.
- `paired/<session_id>/counselor_notes.md`: 현재 이해와 미확인 내용, 작업 상태, 적용 기법과 선택·변경 이유, 내담자 공개 발화 근거, 이전 대응에 대한 실제 반응, 보류 작업과 재개 고려 조건.

새 세션은 [내담자 노트 양식](notes_template.md)과 [상담사 생각 노트 양식](counselor_notes_template.md)의 제목만 있는 Markdown 파일에서 시작합니다. 기존 파일은 빈 파일을 포함해 덮어쓰지 않습니다. P1·P2의 초기화 방식은 유지합니다.

모델은 고정 제목과 순서를 유지하고 각 제목 아래의 내용만 추가·수정·삭제하도록 지시받습니다. 제목 보존과 기록의 의미는 프롬프트 지침이며 Python이 강제하는 스키마나 상태 머신은 아닙니다. 내담자 노트는 사실관계의 기준으로, 상담사 노트는 작업 가설·기법·진행 상황·다음 대응 중심으로 관리합니다. 정정은 두 노트의 관련 기록과 해석에 반영하고, 실제 수행·확인과 향후 계획, 방향 전환과 목표 달성에 따른 완료를 구분하도록 안내합니다. 판단·상태가 바뀌면 새 내담자 사실이 없어도 상담사 노트를 갱신할 수 있습니다. 매 턴 두 번의 수정을 강제하지 않습니다.

노트 수정 도구는 `update_notes(target, edits)`입니다. P3 전용 description과 target 설명을 제공하며, target은 client / counselor, edits는 old_text / new_text 목록으로 P2와 동일합니다. 파일 편집·원문 일치·revision·원자적 저장 등 기술적 처리는 공유 런타임을 사용합니다. 실제 경로는 모델이 지정하지 않습니다.

가이드 조회 도구는 `read_counseling_guide(guide)`입니다. `guide`는 `routing`, `common`, `mi`, `cbt` 중 하나이며, Python이 아래 Markdown 파일을 호출할 때마다 읽고 원문 전체를 `role: tool`로 반환합니다. 별도 LLM을 호출하거나 내용을 추출·요약하지 않습니다.

| guide | 파일 | 용도 |
|---|---|---|
| routing | [routing.md](../../docs/counseling_guides/routing.md) | 기법 선택 기준과 적용 조건 비교 |
| common | [common.md](../../docs/counseling_guides/common.md) | Common에서 다음 행동 선택·수행·재평가 |
| mi | [mi.md](../../docs/counseling_guides/mi.md) | MI에서 다음 행동 선택·수행·재평가 |
| cbt | [cbt.md](../../docs/counseling_guides/cbt.md) | CBT에서 다음 행동 선택·수행·재평가 |

조회는 노트를 수정하지 않습니다. UI 생성 과정에는 조회한 가이드 이름과 실행 상태가 표시되며, 원문은 **호출 상세**, Raw 컨텍스트, Workflow에서 확인합니다. 호출과 반환 내용은 세션 로그·재생 기록에도 남습니다.

## 선택과 연속성

모델이 매 턴 재평가합니다. Common은 탐색·지지·명료화, MI는 변화 동기·양가감정, CBT는 합의된 인지·행동 작업을 중심으로 판단합니다. 매 턴 다른 기법을 선택할 필요는 없습니다.

지침은 유지(Continue), 기존 작업을 보류한 일시 전환(Temporary Shift), 이후 재개·현재 접근 지속·완전 전환(Switch)을 구분합니다. 기존 기법으로의 복귀는 강제하지 않습니다. Python은 노트의 기법이나 작업 상태를 읽어 라우팅하지 않습니다. 별도 라우터·관찰자·평가 모델은 사용하지 않습니다.

선택·유지·전환 판단이 애매하면 `routing`을 조회하고, 기법을 선택한 뒤에는 매 턴 해당 활용 가이드를 조회해 다음 행동을 정하도록 명시합니다. 단순하거나 익숙한 상황을 생략 조건으로 삼지 않으며 같은 턴에 읽은 결과는 재사용합니다. 가이드 조회 후 상담사 생각 노트에 반영할 판단·계획을 검토하고 필요하면 수정합니다. 이는 프롬프트 지침이며 Python이 강제하는 상태 머신은 아닙니다.

시스템 지침은 기본 원칙·두 노트의 역할·기법 선택·가이드 조회·작업 연속성·진행 순서·최종 응답으로 정리했습니다. 모델 입력에서는 버전명과 상태의 영문 별칭을 제거하고, 파일 수정의 세부 사용법은 도구 설명에 둡니다.

시스템 지침의 큰 항목은 `#`, 하위 항목은 `##`로 구분합니다. 노트 이름은 내담자 상태 노트와 상담사 생각 노트로 설명하고, `target`의 client/counselor 값은 도구 정의에서 연결합니다. 노트는 일반 텍스트로 읽고 수정하므로 본문 전체에 Markdown 문법을 강제할 필요는 없습니다. 고정 제목만 양식으로 유지하고 본문은 간결하게 기록하도록 안내합니다.

## 컨텍스트와 저장 시점

P2와 동일하게 전체 공개 대화와 턴 시작 시 디스크에서 읽은 두 노트를 입력합니다. 같은 턴 도구 후속 호출에서는 기본 노트 원문을 유지하고 수정 인자·저장 결과를 role: tool로 전달합니다. 같은 턴 reasoning은 유지하고, 이전 턴 raw reasoning은 재입력하지 않습니다. 다음 상담사 턴은 수정된 파일을 새로 읽습니다. 후속 생성 실패·중단 시 이미 저장한 파일 변경은 유지합니다.

가이드 원문은 처음부터 기본 입력에 넣지 않고, 조회한 결과만 같은 턴의 후속 호출에 누적합니다. 다음 상담사 턴에는 이전 조회 결과를 자동 재주입하지 않습니다. 가이드와 노트 호출은 기존의 턴당 도구 호출 한도를 함께 사용합니다. 기존 세션은 저장된 시스템 지침을 유지하므로, 새 기본 조회 지침을 시험하려면 UI 서버 재시작·새로고침 후 새 P3 대화를 만드세요.

## 검증 범위

Python 테스트는 독립 버전·지침 보존, 도구 스키마, 여러 턴의 파일 갱신·전달, reasoning 경계, 호출 생략, 실패 시 저장 동작을 모의 모델로 검증합니다. 가이드 이름 검증·원문 전체 반환·16,000자를 넘는 결과의 보존·파일 변경 반영·도구 오류 복구도 확인합니다. 브라우저 검증은 다음처럼 P2와 같은 테스트를 P3 설정으로 실행하며, P3에서는 가이드 호출·Raw 결과·Workflow·저장 후 복원을 추가로 확인합니다.

```bash
COUNSELOR_TEST_VERSION=P3 node gemma_test/counseling_test/tests/browser_p2.cjs
```

모의 모델의 기법 선택은 테스트 입력이며 실제 모델의 선택 정확성·상담 품질 검증이 아닙니다. 실제 대화 비교 실험은 별도로 진행해야 합니다.
