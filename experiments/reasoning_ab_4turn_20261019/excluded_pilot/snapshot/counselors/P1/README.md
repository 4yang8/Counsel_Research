# P1: 파일 기반 상담 노트

매 상담사 턴을 시작할 때 `notes.md` 파일을 한 번 읽어 공개 대화와 시스템 지침에 결합하고, 기본 입력 하단에 원문을 포함합니다. 이 기본 입력은 같은 턴의 도구 후속 모델 호출에서도 유지합니다. 노트 작성 판단 → 파일 수정 → 도구 결과를 참고해 상담 답변 → 다음 상담사 턴의 새 기본 입력에 수정된 파일 반영 순서입니다. 내담자의 비공개 프로필·내면상태·요약을 상담사에 주지 않습니다.

노트 추가·수정·삭제가 필요한지는 P1 모델이 결정하고 `update_notes(edits)`를 호출합니다. 읽기 도구나 별도 노트 작성 LLM은 없습니다. `old_text`가 빈 문자열이면 끝에 추가하고, `new_text`가 빈 문자열이면 해당 원문을 삭제합니다. 기존 원문은 정확히 한 번 일치해야 합니다. 여러 변경은 모두 검증한 뒤 원자적으로 저장하며 입력 이후 외부 파일 변경이 있으면 덮어쓰지 않습니다. 의미상 중복 여부는 모델이 판단합니다.

노트는 현재 저장 루트의 `paired/<session_id>/notes.md`에 분리합니다. 이미 실행된 파일 변경은 후속 생성 실패·중단 시에도 유지하며 원문·diff·도구 오류를 실행 로그에 남깁니다. 도구 결과에는 저장 확인과 변경 인자만 반환하고 전체 노트는 다음 기본 입력에서 읽습니다.

상담사 버전에서 P1을 선택하면 지침 편집과 노트 원문·추가(초록)·삭제(빨강)를 표시합니다. 수정은 삭제와 추가의 쌍으로 표시합니다. Reasoning은 별도 공통 영역에 호출별 원문을 스트리밍합니다. reasoning/응답/노트는 서로 다른 데이터입니다.

같은 턴에서 도구를 호출한 assistant 메시지는 `reasoning`을 함께 보존해 후속 모델 호출에 전달합니다. Raw의 도구 호출 스텝과 후속 요청 스텝에도 실제 필드를 표시합니다. 다음 상담사 턴은 공개 대화와 최신 노트로 다시 구성하므로 이전 턴 reasoning을 주입하지 않습니다. 기존 로그는 당시 전송된 내용을 그대로 표시합니다. 현재 연결된 vLLM은 입력 메시지의 `reasoning` 필드를 템플릿에 전달하는 것으로 확인했습니다. 출력의 `reasoning_content` 별칭도 수신 후 이 필드로 정규화합니다.

## 버전 확장

새 실습 버전은 `counselors/<version>/`에 모듈을 만들고 `catalog.PRACTICE_VERSIONS`에 등록합니다. 모듈은 `specification()`(id/label/view/description/system_prompt 등)과 `run()`을 제공하고 필요에 따라 `initialize()`·`view_state()`를 구현합니다. UI의 공통 표시 공간은 유지하며 `LabVersionViews.register(view, renderer)`로 버전별 렌더러를 연결합니다. 실행 중 데이터는 `version_event`의 version/section/action/data로 전달하며 원본 이벤트와 단계별 스냅샷을 보존합니다. 알려지지 않은 view는 JSON 원문으로 표시합니다.
