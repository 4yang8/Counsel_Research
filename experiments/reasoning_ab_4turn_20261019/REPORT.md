# Reasoning 켜기/끄기 · 4턴 대조 실험

## 결론

- 이번 4턴에서는 reasoning을 꺼도 자문·노트 수정·상담 발화를 수행했다. 켠 조건의 전반적인 품질 우위는 확인하지 못했다.
- 켠 조건은 더 간결하고 호출 수도 적었지만, 생성 시간과 출력 토큰이 증가했다. 피로에 대한 방향 전환은 끈 조건이 더 직접적이었다.
- reasoning은 판단·자문·발화의 연결을 분석하는 데 유용했다. 올바른 계획이 최종 발화와 노트의 정확성을 보장하지는 않았다.

## 설계와 검증

- 원본 상담사 P3a, Qwen/Qwen3.8-27B-FP8. 원본 프롬프트·가이드·도구·코드는 변경하지 않았다.
- 각 조건 새 세션에서 같은 내담자 발화 4개를 수동 입력했다. Q1은 발화를 생성하지 않았다.
- 발화 소재: 교수 미팅 이후 자기비난 → 사실과 자기평가 구분 → 반복 분석의 피로 → 오늘 밤 휴식 필요.
- 메인과 가이드 서브에이전트에 enable_thinking=true 또는 false를 함께 적용했다. 각 역할의 효과를 따로 분리한 실험은 아니다.
- temperature .7, top_p .95, seed 20261019, max_tokens 8192. 별도 thinking budget 없음. 노트는 같은 빈 양식으로 시작했다.
- 첫 메인 요청은 enable_thinking 외 모든 필드가 동일함을 확인했다. 실제 요청 24개/27개의 모드와 추론 채널을 검사했다.
- 2턴부터 공개 응답·노트는 조건별로 달라진다. 고정 내담자 입력을 사용하는 독립적인 두 궤적 비교이며, 매 턴 동일한 전체 컨텍스트 비교는 아니다.
- 순서를 번갈아 실행했지만 서버 부하·프리필 캐시는 완전히 통제하지 못했다. 시간은 요청부터 전체 도구 루프 완료까지의 실측이다.
- 한 조건당 1세션·4응답. 아래 품질 평가는 전체 발화·자문·노트·관련 reasoning을 직접 읽은 정성 분석이며 통계적 우위나 임상 효과 평정은 아니다.
- 설정 확인용 예비 실행은 기존 thinking_mode=on을 물려받은 것을 발견해 중단했다. excluded_pilot에 보존했으며 모든 집계에서 제외했다.

- 두 조건 모두 3턴에 old_text의 정확한 일치가 필요한 수정 도구에서 오류를 겪었고, 모델이 스스로 복구했다. 실패 횟수는 2회/3회지만, 오류가 발생한 상담 턴은 각각 1/4이다.

| 턴 | 켜기 | 끄기 | 판단 |

| 4 | Common 자문으로 전환해 짧게 휴식 지지 | CBT 유지, 기존 연습 목적 재확인과 휴식·마무리 | 둘 다 휴식 요청 반영. 끄기는 길고, 켜기는 근거 없는 원인 단정 추가 |

## 관찰된 이점과 한계

### 켠 조건의 이점

- 간결성: 4개 응답 모두 끈 조건보다 짧았다. 마지막 휴식 요청에서 추가 질문을 멈췄다.
- 자문을 다음 행동으로 연결하는 판단이 명시적이었다. 2턴 자문은 이미 아는 사실/해석 구분을 반복하지 말고 생각의 영향을 확인하도록 제안했고, 메인 reasoning과 발화가 그 방향을 따랐다.
- 이 실행에서는 routing·수정 재시도가 덜 발생해 총 모델 호출이 3회 적었다. 단일 실행이므로 안정적인 도구 효율 개선이라고 확정하지 않는다.

### 켠 조건의 한계

- 3턴에 피로를 인식하고도 두 차례 자문 뒤 추가 관찰 질문으로 이어졌다. 오래 판단하는 것이 요청에 더 직접 응답하는 결과로 이어지지는 않았다.
- 4턴 가이드와 마지막 reasoning은 새 설명을 추가하지 말고 짧게 반영하도록 정리했다. 그러나 실제 발화에는 “그건 생각의 무게가 커진 게 아니라 그냥 피로한 상태일 뿐이에요”라는 확인되지 않은 원인 단정이 추가됐다. 계획과 최종 표현의 불일치다.
- 3턴 상담사 노트의 보류 작업에는 “내담자가 지칠 때 재개”가 남았고 4턴에도 유지됐다. 피로 때문에 보류한 작업의 재개 조건이 뒤집힌 기록이다.
- 노트 수정 오류는 reasoning이 있어도 발생했다. 추론 분량 중에는 기존 판단·가이드 요지·답변 계획을 여러 호출에서 다시 정리하는 내용도 있었다.

### 끈 조건의 이점과 한계

- 추론 채널 없이도 기법 선택, 자문 요청, 노트 수정과 복구, 피로 이후 방향 전환을 수행했다.
- 3턴에 추가 분석을 멈추고 구체적 연습으로 전환했다. 실제 내담자가 이를 수용하거나 도움이 됐는지는 고정 입력 실험으로 평가할 수 없다.
- 더 빠르고 출력 토큰이 적었지만, 발화는 더 길었다. 4턴에는 쉬고 싶다는 요청 뒤에도 연습 목적과 마무리를 길게 설명했다.
- 3턴 수정 오류 3회, 첫 두 턴의 routing 추가 조회가 있었다. 1턴 서브에이전트 출력에는 일본어 조각이 섞였으나 최종 상담 발화에는 전파되지 않았다.
- 서브에이전트도 메인의 방향을 받아 반복했다. 3턴 메인이 먼저 defusion을 제안하자 자문이 그 방향을 지지했다. 해당 상세 가이드에 defusion이라는 기법 자체가 명시돼 있지는 않아, 상황별 조언과 원문에 명시된 기법을 구분할 필요가 있다.

## 해석과 다음 실험

- 이번 결과로는 reasoning을 끄면 핵심 기능이 무너지거나, 켜면 대화 품질이 전반적으로 좋아진다고 말할 수 없다.
- OFF도 상담사 생각 노트와 자문에 판단·계획을 작성한다. 전용 추론 채널의 유무 비교이며, 판단 과정 전체가 사라지는 조건은 아니다. 외부 노트가 추론을 대체했다는 효과까지 검증한 것은 아니다.
- 기존 노션 사례에서 확인한 자문→발화 연결은 OFF에서도 가능했다. 관찰 가능한 reasoning의 장점과 성능에 필수적인 요소인지는 구분해야 한다.
- 다음 후보: 같은 체크포인트 반복 비교, 메인만/서브에이전트만 켜는 분리 조건, 길이가 제한된 reasoning 조건. 현재 결과만으로 기본 설정은 변경하지 않는다.
