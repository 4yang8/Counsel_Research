# 30턴 긴 비공개 기록 선별 실험 — 실행 전 계획

## 범위

앞선 60턴 인공 사례에서 모든 필수 원본과 주요 혼동 사건을 포함한 30턴을 선택한다. 시간순 1~30으로 재번호화하며 mapping은 turn_mapping.json에 저장한다. 같은 후보의 짧은 기록과 긴 기록을 비교한다. 기존 60턴 실험은 보존한다. 길이 변경만으로 실제 상담 효과를 입증하지 않는다.

## 조건

- short: 기존의 scene/reason/withheld를 유지한 30개 후보.
- long: 같은 공개 발화·사건·핵심 이유를 유지하며 해석, 감정, 검토 과정, 불확실성, 발화 목표, 표현 계획을 직접 작성한 기록. 앱의 Q3 내면 기록과 유사한 appraisal/turn_goal/response_plan 구조를 사용한다.
- 공개 대화는 선택된 30턴을 시간순으로 묶은 공통 과거 대화다. 생략된 상담 구간이 있으므로 실제 연속 생성 궤적을 뜻하지 않는다. 두 조건의 공개 대화·현재 질문은 완전히 같다.
- 비공개 기록 평균 문자 수는 short 약137자, long 약1114자(JSON 키 포함). 단순 반복 문자열을 붙인 자료는 아니며 부연된 심리 설명과 스키마 변경도 포함된다. 따라서 엄밀한 순수 토큰 길이 효과 실험이 아니라 현실적인 장문 기억 표현 조건 비교다.
- 질문 10개는 기존과 동일하다. 사전 정답은 기존 기준을 선택된 ID에 투영하여 고정한다. 어떤 모델에도 gold를 제공하지 않는다.

## 실행

각 길이 조건에서 RAG/LLM 전체 읽기 × 질문10 × seed1104/1105 = 40회, 총80회.

RAG는 공개 대화·현재 질문으로 검색어를 1회 작성하고 Qwen3-Embedding-4B로 턴 단위 cosine Top-3를 가져온다. 길어진 턴도 분할·요약하지 않는다. LLM은 동일 후보30개 원본 전체를 읽고 0~3개 ID를 반환한다. 기존 selector.md와 검색어 프롬프트는 앞선 실험과 동일하다. 검색 호출 여부 선택은 제외하고 항상 검색한다.

생성 모델은 Qwen/Qwen3.8-Flash-Next-FP8, temperature0.7, top_p0.95, max_tokens4096, reasoning_effort low. 생성 서버192.168.0.94:8002/v1, 임베딩 서버192.168.0.84:18002/v1. 선별 순서는 질문·반복별 RAG/LLM을 번갈아 한다. short 조건을 먼저 완료하고 long 조건을 실행하므로 길이 조건 간 시간 비교에는 서버 부하·캐시 영향이 남는다.

생성 서버의 실제 /tokenize로 문맥 한도를 사전 확인하며 입력을 자동으로 자르지 않는다. 전체 입력과 출력4096 토큰 예약이 32768 한도 안에 있어야 한다. 실제 응답 usage로 입력 토큰 수를 최종 보고한다.

## 평가

정답이 있는 질문8개×2회: 모든 core 원본 확보 수, core recall, 선택 중 core/supporting 비율, 혼동 기록 개수. 없는 사건2개×2회: 빈 선택 여부 별도 보고. 임계값 없이 Top-3를 채우는 현재 RAG의 반환 정책과 LLM의 빈 목록 선택 가능성이 다름을 명시한다.

시간은 RAG 검색어 생성+실제 검색, LLM은 전체 읽기 선별. 생성 서버 입력/출력 토큰을 보고하며 임베딩 GPU 비용과 후속 발화 비용은 포함하지 않는다. 최초 색인과 이후 캐시 상태는 개별 결과에 저장한다.

## 해석

같은 사건을 짧게/길게 표현한 통제는 앞선 60턴과 새 30턴을 바로 비교하는 것보다 유용하지만, 부연 정보·스키마·기록 길이 변화가 함께 일어난다. 한 인공 내담자와 두 번 호출에서 일반 우열·통계적 유의성·상담 타당성을 단정하지 않는다. 모델 출력의 비공개 기록 생성 길이를 실제로 추정한 데이터도 아니다. 질문에 맞춰 정답을 수정하거나 결과가 좋을 때까지 프롬프트를 고치지 않는다.
