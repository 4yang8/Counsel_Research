# 인공 기록 60개: RAG와 전체 기록 LLM 선별 비교

## 실험 범위

직접 작성한 한 내담자의 60개 후보 기록, 10개 질문, 질문별 2회 반복이다. 기존 Q3select 선별 프롬프트와 Q3ragtool의 임베딩·검색 함수를 사용했다. RAG는 검색 여부 선택을 제외하고 검색어를 항상 한 번 생성했다. 실제 후속 발화나 상담 결과는 평가하지 않았다. 자세한 설정은 [사전 계획](PROTOCOL.md), [원본 기록](RECORDS.md), [질문](QUESTIONS.md), [사전 정답](GOLD.md)을 참고한다.

## 전체 결과

| 항목 | RAG | 전체 기록 LLM 선별 |
|---|---:|---:|
| 정상 실행 | 20/20 | 20/20 |
| 정답 있는 질문: 모든 핵심 원본 확보 | 14/16 | 16/16 |
| 정답 있는 질문: 핵심 원본 하나 이상 확보 | 16/16 | 16/16 |
| 핵심 원본 평균 재현율 | 93.8% | 100.0% |
| 선택 기록 중 관련 기록 비율 평균 | 77.1% | 100.0% |
| 기록에 없는 사건: 빈 선택 | 0/4 | 4/4 |
| 평균 선별 지연시간 | 3.11초 | 5.13초 |
| 평균 생성 모델 입력 토큰 | 2850 | 7944 |
| 평균 생성 모델 출력 토큰 | 309 | 557 |

재현율·관련성은 정답 있는 8개 질문 × 2회에서 산출했다. 빈 선택 4회는 별도 지표다. 평균 관련성은 각 호출의 선택 중 core 또는 supporting의 비율을 평균한 값이며, 후속 응답의 정확도가 아니다. RAG는 Top-3를 항상 채우고 LLM은 0~3개를 선택할 수 있어 선택 개수 정책도 정밀도 차이에 영향을 준다.

RAG 지연시간에는 검색어 LLM 호출과 실제 임베딩 검색이 모두 포함된다. 토큰은 생성 모델만 집계하며 임베딩 및 후속 발화 비용은 제외한다. RAG는 첫 문서 임베딩 이후 캐시를 사용한다. 단일 서버·소수 반복의 관측값이며 동시 부하·프롬프트 캐시를 통제한 성능 벤치마크가 아니다.

## 해석 한계

- 필수 원본과 보조 회고를 구별한 연구 목적별 기준이다. 회고만으로도 답할 수 있는 질문에서는 일반 검색 품질과 원본 확보 성능이 다를 수 있다.
- 사전 정답은 독립 평가자가 검증하지 않았다. 질문과 기록을 같은 분석자가 만들었다.
- 두 번 호출은 두 개의 독립 사례가 아니다. 이 결과로 유의성·보편적 우열을 주장할 수 없다.
- 사건·시점을 명시한 단서가 많고 60개 기록은 모델 전체 문맥에 들어간다. 더 긴 기록·모호한 질문에서 결과가 달라질 수 있다.
- 검색된 기록을 잘 활용하는지, 응답이 왜곡되는지, 상담 개입 효과가 개선되는지는 검증하지 않았다.

## 관측 결과의 해석과 사후 진단

이 구성에서는 전체 기록 LLM 선별이 필수 원본 확보와 불필요한 선택 억제에서 더 정확했다. 하지만 검색된 3개 중 불필요한 기록이 섞였다고 곧바로 상담 답변이 왜곡됐다고 해석해서는 안 된다.

- RAG가 필수 원본을 놓친 것은 첫 반복의 `blue_change`와 `overtime_delay`였다. 두 질문 모두 두 상황을 비교해야 한다.
- `blue_change` 검색어는 “민수 파란 카드 연락 과제 처음 동의했을 때”로, 선택권을 준 이후라는 두 번째 시점이 빠졌다. 결과는 [3, 41, 51]이었고 원본21을 놓쳤다.
- `overtime_delay` 검색어도 팀장의 근무 부탁에만 초점을 맞춰 어머니의 모임 권유를 누락했다. 결과 [47, 15, 20]에서 비교 대상55가 빠졌다.
- 원래 질문 전체를 그대로 검색하는 **사후 진단**을 전체 10개 질문에 1회 적용했다. 정답 있는 8개 질문 모두 필수 원본을 확보했다(8/8). 위 두 질문은 각각 [3, 21, 11], [15, 47, 55]로 회복됐다. 이 결과는 두 누락에 검색어 작성 단계가 기여했다는 근거이며, 임베딩 모델 자체의 한계로만 해석할 수 없다. 사전 비교의 2회 반복 결과와 합산하지 않는다.
- 원문 질문을 써도 팀장 사건 질문에 아버지 이야기13이 섞이는 등 일부 비관련 선택은 남았다. 없는 사건 질문에서도 3개를 채워 반환했다.
- 현재 LLM 선별은 0~3개를 반환하고 RAG는 최소 유사도 없이 3개를 반환한다. 따라서 불필요한 기록 및 빈 결과 차이는 검색 모델 능력뿐 아니라 반환 정책 차이도 반영한다.

## 이번 결과로 가능한 판단

60개 기록이 모두 문맥에 들어가는 이번 인공 사례에서는 LLM 전체 읽기가 정확성 측면에서 더 안정적이었다. RAG는 평균 지연시간이 더 짧고 생성 모델 입력 토큰이 적었다. 이 차이는 후속 발화 비용이나 임베딩 GPU 비용을 포함한 총 운영비 절감 증명은 아니다. 다음 판단은 “RAG를 폐기”하기보다, 검색어가 질문의 비교 대상과 시점을 보존하는지 및 검색 결과의 관련성을 별도로 확인해야 한다는 것이다. 본 실험은 현재 시스템을 변경하지 않았다.
