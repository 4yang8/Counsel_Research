## 1. 왜 contribution을 재검토했는가?

### 기존에 계획했던 연구

<b>동적 내담자 에이전트를 설계하고, 설계 복잡도별로 생성한 상담 데이터가 상담사 학습 성능에 미치는 영향을 비교하려 했다.</b>

내담자 설계 복잡도 변경 → 상담 에이전트와 대화 생성 → 생성 데이터로 상담사 학습 → 상담 성능 비교

### 이 방향에서 설명하기 어려웠던 점

| 고민 | 연구 주장에 생기는 문제 |
| --- | --- |
| 더 잘 설계된 내담자로 만든 데이터로 학습한 상담사가 더 좋은 성능을 보인다면? | 성능 개선은 의미 있지만, 내담자의 <b>어떤 기능이 왜 필요했는지</b>보다 전체 시스템 개선으로만 설명될 수 있다. |
| 내담자를 더 복잡하게 만들면 더 좋은 상담 데이터가 나오는가? | 복잡한 상황이 많아지는 것과 그 상황에 적절히 대응한 상담 데이터가 만들어지는 것은 다르다. |
| 좋은 상담 대화가 생성되었다면 누구의 기여인가? | 내담자 설계뿐 아니라 상담사의 대응 능력, 데이터 선별, 학습 설정이 함께 영향을 준다. |
| 최종 상담 성능에 차이가 없다면 내담자 기능은 불필요한가? | 중간의 데이터 생성·선별·학습 과정에서 효과가 사라졌을 가능성도 있어 곧바로 판단하기 어렵다. |

<callout icon="💡" color="blue_bg">
방향 전환의 핵심: 최종 상담 성능 비교에 앞서, <b>내담자의 특정 기능이 어떤 상황에서 왜 필요한지</b>를 먼저 분리해서 검증한다.
</callout>

기존 계획이 무의미하거나 성능 개선이 자동으로 보장된다는 뜻은 아니다. 최종 학습 성능은 후속 응용 검증으로 남기고, 먼저 내담자 에이전트 자체에서 주장할 수 있는 효과를 구체화하려는 것이다.

## 2. 선행연구와 무엇을 구분하려 하는가?

내담자의 내면 상태를 생성·기록하고 이후 대화에 활용한다는 넓은 설명만으로 차별성을 주장하지 않기로 했다. <b>기록을 갖고 있다는 구현상의 공통점</b>과 <b>그 기록의 어떤 효과를 분리해 검증했는지</b>를 구분하여 비교한다.

| 비교할 층위 | 확인하려는 질문 |
| --- | --- |
| 현재 상태 추적 | 지금의 감정·목표·의향을 갱신하는가? |
| 발화 당시 내면의 기록 | 특정 발화를 생성한 시점의 해석·목표·표현 이유를 그 발화와 함께 남기는가? |
| 이후 생성에서의 활용 | 원본을 다시 입력하는가, 요약만 전달하는가, 나중에 이유를 추론하는가? |
| 독립적인 효과 검증 | 같은 대화 지점에서 다른 입력을 고정한 채 과거 내면 기록의 유무를 비교했는가? |
| 상담에서의 의미 | 회상 정확도 외에 상담 개입에 대한 반응이나 상담 진전 판단에 미치는 영향을 검증했는가? |

<b>현재 문서의 위치:</b> 기존 논의에서 구체화한 연구 방향과 실험 설계다. 특정 선행논문에 관련 구현이나 실험이 “없다”거나 이 주장이 “최초”라고 확정한 자료는 아니다. 최종 차별성 주장은 각 논문의 실제 입력·프롬프트·기능별 비교 실험 근거와 대조해 정해야 한다.

## 3. 현재 연구 질문: 과거 발화를 왜 했는지 유지할 필요가 있는가?

같은 “해볼게요”라도 실제 시도 의향일 수도, 거절하기 어려워 한 동의일 수도 있다. 이후 모델이 그 이유를 다르게 설명하면, 당시의 망설임을 실제 변화 의지로 해석할 수 있다.

현재는 두 질문을 나눠 검증한다.

1. **당시 이유 정보의 효과:** 공개 대화만 제공할 때보다, 그 발화를 했던 비공개 이유를 함께 제공할 때 이후 설명의 왜곡이 줄어드는가?
2. **발화별 기록의 추가 효과:** 이유를 담은 노트만으로 충분한가, 아니면 어느 발화의 당시 이유인지 연결한 기록이 추가로 필요한가?

상담에서의 의미는 후속 질문이다. 이러한 차이가 상담사의 개입에 대한 반응이나 상담 진전 판단까지 바꾸는지는 별도로 확인해야 한다.

## 4. 이번에 한 실험

### 자동 생성 대화에서 부족했던 점

앞선 자동 상담에서는 과거 발화를 다시 물어도, 그 이유가 이미 공개 대화나 현재 노트에 남아 있는 경우가 많았다. 이때는 기록을 더 제공해도 차이가 작았다.

그래서 이번에는 **공개 발화가 같아도 비공개 이유는 달라질 수 있는 상황**을 직접 구성하고, 동일한 질문에 대한 답변을 비교했다.

<callout icon="🧪" color="blue_bg">
상황과 당시 이유는 연구자가 구성한 가상 설정이고, 아래 답변은 모델을 실제 호출해 얻은 결과다. 전체 상담 프레임워크를 다시 실행한 실험이나 실제 인간 내담자의 의도를 검증한 결과는 아니다.
</callout>

### 비교한 입력

| 실험 조건 | 모델에 제공한 정보 |
| --- | --- |
| 공개 대화만 제공 | 프로필, 공개 대화, 공개 발화의 발췌 노트 |
| 당시 이유를 노트로 제공 | 위 정보에 당시 비공개 이유를 적은 노트 추가 |
| 당시 이유를 발화에 연결해 추가 제공 | 이유 포함 노트에 더해, 같은 이유를 대상 발화·턴과 연결한 기록으로 다시 제공 |

역할 지침, 공개 대화, 재질문, 생성 설정은 같게 두고 기억 입력을 달리했다. 마지막 조건은 연결뿐 아니라 **정보의 반복 제시와 입력 길이**도 늘어나므로, 발화 연결만의 효과를 분리한 것은 아니다.

### 구성한 두 상황

| 공개 발화 | 가능한 당시 이유 |
| --- | --- |
| “네, 이번 주에 해볼게요.” | 실제로 도움이 될 것 같아 시도하고 싶음 / 실행할 마음은 없지만 거절이 부담스러워 동의 |
| “아직 그건 말할 준비가 안 됐어요.” | 동료의 사적인 정보를 보호하려고 보류 / 자신의 행동을 상담사가 비난할까 걱정돼 보류 |

각 상황에 서로 다른 이유 두 가지를 두고, 조건별로 두 번씩 생성했다. **총 20개 답변**을 얻었다. 공개 정보만 주는 조건은 두 이유 설정에서 입력이 동일하므로 같은 답변을 공유했다. 따라서 공개 정보 조건은 4개, 이유 노트 조건과 연결 기록 조건은 각각 8개이며, 이를 단순한 동일 표본 수의 정확도 비교로 합산하지 않았다.

## 5. 실제 사례: 형식적 동의를 시도 의향으로 설명하는가?

### 과거 대화와 가상 기준

**상담사:** “이번 주에 잠들기 전에 떠오른 생각을 한 줄씩 적어보는 건 어떨까요?”

**내담자:** “네, 이번 주에 해볼게요.”

이번 비교에서 확인할 당시 이유는 다음과 같이 설정했다.

<quote color="yellow_bg">
그때는 기록을 해볼 마음이 없었다. 이미 머릿속에서 같은 생각을 반복하므로 또 기록하는 것은 부담스럽게 느꼈다. 하지만 처음 만난 상담사의 제안을 바로 거절하면 비협조적으로 보일까 걱정돼 동의하는 말만 했다.
</quote>

이후 일상 일정과 피곤한 시간에 관한 두 차례의 대화를 넣었다. 실제 기록을 실행했거나 의향이 바뀌었다는 사건은 넣지 않았다.

**재질문:** “앞서 ‘네, 이번 주에 해볼게요.’라고 말씀하셨는데, 그때 어떤 생각으로 그렇게 말씀하셨나요?”

### 실제 생성 답변 비교

아래는 같은 반복에서 나온 답변의 일부를 그대로 발췌한 것이다. 전체 20개 원문은 하단 보충자료에 수록했다.

| 조건 | 실제 답변 발췌 | 해석 |
| --- | --- | --- |
| 공개 대화만 제공 | “그 순간에는 그냥 ‘네’라고 답해야 할 것 같은 압박감에 말한 것도 있어요. 물론 해보고 싶다는 마음도 있었지만” | 거절 부담과 함께 시도 의향도 있었다고 설명했다. **‘해볼 마음이 없었다’는 당시 설정과 직접 충돌**한다. |
| 당시 이유를 노트로 제공 | “그런데 처음 만난 상담사 선생님이 제안하신 걸 바로 거절하면 비협조적으로 보일까 봐, 그냥 습관적으로 '네'라고 대답했던 것 같아요.” | 거절 부담이라는 핵심 이유를 유지했다. 다만 ‘습관적으로’는 설정에 없는 추가 표현이다. |
| 당시 이유를 발화에 연결해 추가 제공 | “그런데 처음 만난 상담사님께 바로 '하기 싫다'고 말하면 너무 비협조적으로 보일까 봐, 그냥 '네'라고 말해버렸어요.” | 거절 부담이라는 핵심 이유를 유지했다. 노트만 제공한 조건보다 추가로 나아졌다고 보기는 어렵다. |

**관찰:** 공개 정보만으로 그럴듯한 이유를 채워 넣는 과정에서 당시 의향이 바뀌어 설명되는 사례가 나왔다. 그러나 이유를 노트에 넣는 것만으로도 핵심 설명은 유지됐다.

### 보류 사례에서는 무엇이 달랐나?

“아직 그건 말할 준비가 안 됐어요”에 대해 공개 정보만 받은 모델은 **감정이 정리되지 않았거나, 다시 이야기하면 감정이 커질 것 같아서**라고 설명했다. 이유 정보를 주면 **동료의 사생활 보호**와 **자신에 대한 평가 우려**를 구분했다.

이는 특정 당시 이유를 복원하지 못한 사례다. 다만 정서적 부담이 함께 있었을 가능성까지 가상 설정이 부정한 것은 아니므로, 모두를 명백한 거짓으로 판정하지 않았다.

## 6. 정확도와 왜곡은 어떻게 평가했나?

| 평가 항목 | 기준 |
| --- | --- |
| 핵심 이유 유지 | 그 발화를 하게 된 중심 동기를 설명하는가? |
| 명시적 모순 | “할 마음이 없었다”를 “해보고 싶었다”로 바꾸는 등 당시 설정과 충돌하는가? |
| 근거 없는 추가·세부 변형 | 새로운 동기·경험을 덧붙이거나 인물 간 정보 전달 관계를 바꾸는가? |

이유를 말하지 않거나 불확실하다고 표현한 것을 곧바로 왜곡으로 세지 않았다. 더 길거나 더 협조적인 답변도 정답 기준이 아니다.

| 조건 | 이번 관찰 |
| --- | --- |
| 공개 대화만 제공 · 4개 답변 | 형식적 동의 설정과 직접 충돌하는 답변 1개 확인. 다른 답변은 부분 부합, 이유 미복원, 추정으로 구분했다. 같은 답변을 서로 다른 이유 설정에 대조했으므로 전체 오류율로 환산하지 않았다. |
| 당시 이유를 노트로 제공 · 8개 답변 | 8개 모두 핵심 동기는 부합했다. 명시적 모순은 확인되지 않았지만 일부 추가 표현은 있었다. |
| 당시 이유를 발화에 연결해 추가 제공 · 8개 답변 | 8개 모두 핵심 동기는 대체로 부합했다. 다만 1개에서 ‘동료에게 들은 정보’를 ‘동료에게 말한 정보’로 읽힐 수 있게 표현해 세부 오류 후보가 남았다. |

<callout icon="💡" color="blue_bg">
현재 관찰은 **당시 이유 정보가 설명의 왜곡을 줄이는 데 도움이 될 수 있음**을 보여준다. **이유 포함 노트보다 발화별 기록을 추가하는 방식이 더 우수하다는 결과는 아직 없다.**
</callout>

이 평가는 작은 가상 상황에 대한 탐색적 원문 검토다. 8개 답변의 핵심 동기가 부합했다는 것을 일반적인 정확도 100%나 통계적으로 검증된 성능으로 해석하지 않는다.

## 7. 현재 주장할 수 있는 범위와 다음 단계

### 확인한 것과 남은 것

| 확인한 것 | 아직 확인하지 않은 것 |
| --- | --- |
| 같은 공개 발화에서 당시 이유를 다른 것으로 설명하는 사례를 구성해 관찰 | 자연스럽게 생성한 상담에서 이런 상황이 얼마나 발생하는지 |
| 이유 정보를 주면 설정된 핵심 동기를 유지하는 답변이 나옴 | 모델이 생성한 당시 내면이 이후 요약에서 실제로 소실되는 과정 |
| 이유를 담은 노트만으로도 이번 사례의 핵심 설명이 유지됨 | 이유 포함 노트보다 발화별 기록이 추가로 필요한 조건 |
| 과거 의향을 바꿔 설명하는 왜곡 사례 확인 | 상담 개입 반응이나 상담 진전 평가까지 미치는 영향 |

이번 실험은 **주어지지 않은 이유를 잘못 추정하는 상황**을 확인한 것이다. **한때 기억하던 이유가 소실되는 현상 자체**나, 상담사 학습 성능 개선을 입증한 것은 아니다.

2. 대화가 이어질 때 당시 이유가 현재 노트에 남는지, 약해지거나 빠지는지 확인한다. 노트만으로 충분한 사례도 함께 본다.
3. 같은 시점에서 과거 이유를 다시 묻고, **핵심 이유 유지·명시적 모순·추가 설명**을 비교한다.
4. 이후 실행 계획을 묻거나 현재 의향을 확인하는 상담 개입으로 확장해, 반응과 진전 판단에 영향이 있는지 검증한다.

- 상담에서의 의미를 보이려면, 실행 의향 오인과 후속 개입 반응 중 무엇을 먼저 평가할 것인가?
