# Q3b · 선택적 계획과 기록 최적화

Q3a를 복제한 독립 비교 버전이다. 과잉 분석·기록의 원인 중 모든 턴의 명시적 계획 강제와 기록 역할의 중복을 줄여 본다. Q3/Q3a 파일과 기존 세션은 변경하지 않는다.

## 변경점

| 항목 | Q3a | Q3b |
|---|---|---|
| 첫 판단 | 계획 등록 필수 | 반응 판단, 기억 조회, 계획 등록 중 선택 |
| 계획 필요성 | 모든 턴에 수행 | 미해결 판단들이 연결되어 앞선 결과에 따라 다음 작업이 달라질 때 |
| 단일 조회 | 진행 중인 계획 단계 필요 | 계획 없이도 발화 확정 전에 조회 가능 |
| 계획 내용 | 발화 생성 작업을 단계로 구성 | 아직 해결하지 못한 질문만 계획, 이미 얻은 결론은 재사용 |
| 판단 기록 | 항목별 내용 작성 | 각 항목의 결론·핵심 근거를 기록하도록 설명 보강 |
| 노트 | 현재 마음과 조건 | 이번 상호작용에서 형성·구체화·변화하여 다음 반응에 필요한 마음을 선별 |

직접 판단 경로도 프로필·관련 특성·노트·공개 대화·궤적을 읽는다. 판단을 생략하는 것이 아니라 별도의 작업 계획 등록·시작·완료 호출을 생략한다. 첫 턴이나 짧은 발화라는 이유로 계획을 자동 생략하지 않는다. 모델이 현재 판단의 복잡도와 의존 관계로 선택한다.

## 실행 경로

- 직접 판단: 라우터 → `stage_client_update` → `commit_client_utterance` → `update_client_notes` → `update_trajectory_progress`.
- 조회 후 판단: 계획 없이 `retrieve_client_memory`로 필요한 근거를 확인하고 직접 판단 경로로 진행할 수 있다.
- 계획 사용: `update_turn_plan`으로 필요한 단계를 등록·시작하고 판단 또는 조회를 수행한다. 결과 기록·재계획 후 필요한 단계가 완료/생략되면 반응을 종합한다.
- 반응 판단 이후에도 새로운 문제를 발견하면 계획을 시작할 수 있다. 계획을 시작한 뒤에는 미완료 단계를 건너뛰어 발화를 확정할 수 없다.
- 판단 이후 추가 조회나 계획 변경이 있으면 `stage_client_update`를 다시 수행해야 발화를 확정할 수 있다. Python은 최신 계획 revision과 조회 횟수를 검증한다.

조회·계획·반응의 한도와 최종 발화·노트·궤적의 일괄 저장은 Q3a와 같다. 기록 실패 시 완료된 턴으로 저장하지 않는다. 같은 턴의 reasoning과 도구 호출 이력은 보존한다. 컨텍스트 한도 관리나 잘못된 JSON 복구는 이번 변경에 포함하지 않는다.

## 기록과 모델 입력

- 계획 도구는 성공 여부·revision·단계 상태·판단 가능 여부·남은 갱신 횟수만 반환한다. 전체 계획과 이력은 이벤트·저장 파일에 보존한다.
- 계획을 사용한 턴에는 `planning_mode: planned`, 별도 계획을 사용하지 않은 턴에는 `planning_mode: direct`를 저장한다. direct에도 조회가 있을 수 있다.
- 계획이 없는 경우 `local_plan`은 빈 객체, `local_plan_history`는 빈 배열이다. 다음 턴에 이전 작업 계획을 자동 주입하지 않는다.
- appraisal·궤적 계획·대화 의도·표현 계획의 기존 스키마는 유지한다. 항목별 결론과 연결에 필요한 근거를 간결하게 쓰도록 지침을 바꾼다.
- 노트는 자유 글머리와 항목별 add/update/delete를 유지한다. 새로 이어갈 마음이나 변화가 없으면 빈 operations를 허용하며, 근거와 작업 과정은 턴 기록에 남긴다. 길이를 강제로 자르거나 항목 수를 제한하지 않는다.
- 라우터, 프로필 입력, 사전 신뢰 궤적, 조회 대상, 내담자 생성 모델은 Q3a와 동일한 구성이다.

## UI

실험 설정의 내담자 버전에서 `Q3b · 선택적 계획·기록 최적화`를 선택한다. 메인/라우터의 system·user 프롬프트와 사전 궤적은 Q3b 파일로 독립 편집한다. reasoning, Raw context, Workflow, Activation context, 전체 노트와 계획 이력을 조회할 수 있다. 계획 생략 시 화면에 직접 판단한 턴임을 표시한다.

코드 변경을 적용하려면 UI 서버를 재시작하고 브라우저를 새로고침한다. vLLM 서버 재시작은 필요하지 않다.

## 검증과 비교

`tests/test_q3b.py`는 직접 판단·조회·계획·재계획, 추가 정보 이후 낡은 판단으로 확정하는 것을 차단하는지, 실패 시 롤백, 다음 턴 분리, Q3a 프롬프트 격리를 모의 모델로 검증한다. `tests/browser_q3b.cjs`는 버전 선택·편집·저장·실행취소·직접 판단·노트·컨텍스트·새로고침·모바일을 확인한다.

실제 모델의 발화 품질이나 토큰 절감은 아직 확정하지 않는다. 같은 프로필·상담사 입력·생성 설정에서 계획 선택 여부, 호출 수, 토큰, 반복 기록, 내면/발화 일관성을 함께 비교한다. 여러 변경을 묶은 버전이므로 개선되어도 개별 변경의 인과효과를 분리한 결과는 아니다.

## 2026-10-30 공통 기록 원칙 수정

Q3·Q3a·Q3sk와 동일하게 내면 판단·표현 선택·기록의 역할과 자료별 근거 범위를 구분했다. 노트와 궤적은 이미 생성된 내면·선택·발화를 선별·요약하며 대상·의미·시점·확실성을 보존한다. 기록 중 새 심리 해석이나 상호작용 결과를 추가하지 않도록 메인 지침과 도구 설명을 맞췄다. Q3b의 선택적 계획과 다음 턴에 필요한 노트 선별 기준, 호출 순서와 스키마는 유지한다.

메인 지침은 새 대화에 적용한다. 기존 세션의 시작 지침과 과거 기록은 소급 변경하지 않는다. 수정 전후 파일과 검증 결과는 `experiments/recording_fidelity_20261030T141212/q3b_extension/`에 보존한다.
