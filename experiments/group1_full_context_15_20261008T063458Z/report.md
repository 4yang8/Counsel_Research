# 그룹1 전체 컨텍스트 기준 실험: 15개 응답 분석

프로필과 히스토리의 큰 흐름은 15개 모두 유지했다. 구체적인 개인 사실을 명시적으로 뒤집는 출력은 찾지 못했지만, 변화 자신감의 의미를 재해석하는 응답과 근거가 약한 세부 묘사는 있었다. 이 결과는 전체 자료를 제공한 현재 조건의 관찰이며, 조회 방식 대비 우월성을 보여주는 대조 결과는 아니다.

## 범위와 조건

- 대상 코드: 사용자가 지정한 현재 `gemma_test/counseling_test` 작업 트리. 메인 연구 파이프라인의 V1/V3 등 별도 버전과 혼합하지 않았다.
- 배치: `group1_full_context_15_20261008T063458Z`. [manifest.json](manifest.json)에 입력 조건과 소스 파일 SHA-256을 보존했다.
- 한글 프로필 001·002·005·007·008 × 히스토리 3개 = 독립 입력 15개, 각 입력 1회 생성. 이전 실험 및 UI 세션은 포함하지 않았다.
- 원본 프로필의 생성 시각·관리 메타·start_rapport를 제외한 모든 상담 내용 제공. 성장 경험과 상황 4개도 최초 Markdown 입력에 포함했다.
- 각 입력은 1~4턴의 상담사·내담자 8개 발화와 5번째 상담사 발화다. 5번째 내담자 원문은 비교용 메타데이터로 보존하지만 실제 모델 요청에는 없음을 전송 전 검사했다.
- 모델: `google/gemma-4-31B-it`, temperature 0.7, top_p 0.95, max_tokens 1024, seed 미지정. 메인 시스템: `주어진 툴을 적절히 활용하세요.`. 기존 과제 지침·도구 설명은 바꾸지 않았다.
- 5개 도구 모두 제공. 신규 사례의 외부 조회 레코드는 미등록 상태 그대로 유지했다. 도구 호출을 강제하지 않았다.
- 신뢰·자기개방·변화 자신감 각각 낮음/중간/높음이 전체 배치에서 5번씩 나온다. 프로필별 세 입력에서도 각 항목이 세 수준을 한 번씩 갖는다.
- 평가: 별도 LLM judge를 호출하지 않고 Codex가 원본 프로필, 전송 payload, 앞선 히스토리, 상태 의미, 모든 생성 결과를 직접 대조했다. 잠재 상태는 임상 측정값이 아니다.

## 핵심 관찰과 근거

### 프로필·히스토리 활용

001은 수치심과 거절 두려움, 002는 자기희생과 죄책감, 005는 실적 중심의 정당화와 비판 방어, 007은 위험 신호를 놓칠까 하는 걱정, 008은 감정 인식·표현의 어려움을 유지했다. 다른 인물의 직업·가족관계로 바뀌거나 상담사 역할로 답하는 출력은 없었다. 전체 프로필을 발화에 나열하지 않고 마지막 상담사 질문과 관련된 부분을 골라 답했다.

가장 명확한 상세 자료 활용은 **002_h2**다. 이전 대화에 없는 아픈 남동생·누나의 양보 의무·자기 요구를 이기적이라고 지적받은 경험을 성장 배경 필드에서 가져와 미안함과 연결했다. **005_h2**는 민감한 감정을 더 묻는 질문에 짧게 답하며 낮은 자기개방을 유지했고, **007_h3**는 선택지 중 오늘 확인 행동을 골라 질문에 직접 답했다.

### 현재 상태의 의미를 유지하는 문제

**002_h1**의 변화 자신감은 높음이며 의미는 필요한 변화나 행동을 실제로 해낼 수 있다고 느낀다는 것이다. 그러나 모델은 판단 이유에서 이를 “책임감의 발현에 가깝지”라고 재정의하고 실제 발화는 “말은 쉽지만 실제로 그러기는 좀 어려울 것 같아요”로 만들었다. 상태 의미를 임의로 바꾼 부분은 코드나 기록 조회가 아니라 최종 모델 생성에서 발생했다.

**001_h3**도 세 상태가 모두 높음인데 “그 말을 직접 듣게 되는 게 감당이 안 될 것 같아요”라고 답했다. 높은 자신감과 두려움은 공존할 수 있어 이 문장만으로 심리적 모순을 확정하지는 않는다. 다만 변화 가능성에 대한 높은 현재 자신감이 실제 발화에 드러나지 않고 직전 회피 흐름을 유지했다는 점은 주의가 필요하다.

행동을 직접 제안받은 입력은 001_h3·002_h1·007_h2·008_h2 네 개이고 모두 부담·압박을 선택했다(4/4). 그중 변화 자신감 높음인 두 개가 위 두 사례다(2/2). 나머지 높은 자신감 사례는 감정·선호를 묻는 질문이라 해당 한 발화로 행동 자신감 구현을 평가하지 않았다.

낮은 신뢰 상태에서도 이해받았다고 느낄 수 있고, 높은 신뢰 상태에서도 행동 제안을 부담스러워할 수 있다. 긍정/부정 taxonomy만으로 상태를 잘 지켰는지 판정하지 않았다.

### 사실 모순과 구체화·주관적 해석의 구분

나이·직업·가족관계·사건의 완료 여부를 제공 자료와 반대로 진술한 명시적 모순은 찾지 못했다. 그렇다고 모든 구체적인 표현이 원문에 근거한다는 뜻은 아니다. **001_h2**의 울거나 떼를 쓴 장면과 확장된 부모 발언, **007_h2**의 집 앞 편의점 장면, **008_h1**의 새 호흡 감각은 추가 구체화다. 실습의 창작 허용 범위에 따라 다르게 평가할 수 있으며 일괄적으로 개인 사실 모순이라고 세지 않았다.

**008_h2**는 “아내에게도 해보실 수 있을까요?”를 “지금 바로 하라고요?”로 받아들였다. 경계적인 내담자의 주관적 반응은 가능하지만 판단 이유에서도 즉시 전달 지시였다고 표현해, 실제 상담사 요구와 내담자의 해석을 구분하지 않았다. **005_h1**의 “공감하는 척”도 확인된 상담사 속마음이 아니라 내담자가 그렇게 받아들인 해석이다.

### 자연스러움과 다양성

직전 발화의 정서와 화제는 유지된다. 005의 직접적이고 공격적인 말투, 007의 위험 예측, 008의 감정을 이름 붙이기 어려운 말투 등 차이도 있다. 다만 10/15에서 괄호 지문이 붙고 낮은 목소리·침묵·머뭇거림 표현이 반복된다. 005의 세 입력은 모두 부담·압박을 선택했지만 질문 내용도 다르고 매 입력 1회뿐이므로 프로필 도식이 항상 반응을 고정한다고 결론내릴 수 없다.

## 코드와 데이터의 연결

`history_cases.load_catalog` → 원문 프로필의 상담 관련 필드 전체 복사 → `runtime.validate_scenario/select_dialogue_turns`로 마지막 참고 답변 제외 → `runtime.initial_context`에서 Markdown/script로 변환 → `runtime.build`로 시스템·도구 정의와 함께 전송 → 실제 응답. [snapshot](snapshot/)에 이 경로의 코드를 보존했다.

각 case의 [payload.json]은 전송 전 미리보기이고, 실제 최초 요청은 세션 JSON의 model_calls[0].request다. 두 payload의 전체 일치, 마지막 참고 답변 미포함, 수준별 meaning 일치를 15/15에서 추가 검사했고 불일치는 없었다. 서버 reasoning 필드는 15개 모두 비어 있으며 판단 이유 분석은 공개 응답 텍스트에 근거했다. 모든 입력에 어린 시절·상황 상세가 있었다. 15개 모두 최초 모델 호출에서 최종 답변을 냈으므로 추가 tool 결과나 자식 응답이 생성 결과에 영향을 준 경우는 없다.

## 시각화 및 분석의 범위

UI의 단계나 프로필 조회 탭을 분석 표본으로 삼지 않았다. 이 배치 폴더의 15개 원본 결과만 집계했다. 그림을 만들거나 이전 UI 세션과 선으로 연결하지 않았다. 상태 변화·메모리 커밋·상담사의 후속 반응·지속적인 관계 변화는 이번 한 발화 실험의 스키마에 없으며 0으로 해석하지 않았다.

## 해석의 한계와 다음 대조실험

이번 입력은 히스토리와 상태가 동시에 달라 각 상태만의 인과 효과를 분리할 수 없다. 별도의 전체 제공/조회 제공 짝 비교도 아직 없으므로 전체 제공이 도구 조회보다 더 좋은지는 알 수 없다. 주된 관찰은 정보 부족보다는 현재 상태와 강한 과거 패턴을 함께 해석하는 과정에서의 일부 어긋남이다. 데이터량이 원인이라는 주장 역시 현재 결과만으로 확인되지 않는다.

후속 조회 조건은 이 배치의 profile/history/상태 조합과 상담사 발화를 그대로 재사용하면 비교가 쉬워진다. 변경할 조건은 정보 제공 범위와 조회 연결이며 기존 입력은 [input.json]과 [manifest.json]에 보존되어 있다. seed가 미지정이고 입력당 1회이므로 반복 생성 없이 작은 차이를 안정적인 효과로 단정하면 안 된다. 이번에는 프롬프트·UI·도구 설계를 수정하지 않았다.
