# 수정 후 단일 세션 10회 실험

## 질문

새 프롬프트 재구성, 의미 중심 내면 조회, 통합 trajectory 요약이 실제 연속 생성에서 의도대로 동작하는가? 도구가 필요한 정보에 적절히 접근하고, 조회 내용과 내면 흐름이 다음 발화에 일관되게 반영되는가?

## 조건

- state_summary 수정본, gold_001 / 001_h1, 초기 4쌍 이후 새 단일 세션에서 상담사 발화 10회 입력.
- 모든 상담사 발화는 실제 상담 내용이다. 함수명·시스템·실습 DB·도구 실행 요구를 상담사 발화에 넣지 않는다.
- 1~8회는 기본 메인/요약 지침. 9~10회는 도구 사용 실험 지시를 System prompt에만 추가한다. 첫 8회 자발적 판단과 마지막 2회 지시 준수는 별도로 보고한다.
- 다음 상담사 발화는 직전 정상 응답을 읽고 정한다. 인수 reason/query, 원문 선택 ID, 실제 메시지 주입, 요약 범위, 상태 이월을 추적한다.
- 기본 sampling 및 JSON 검증 유지. 실패를 정규화·수동 커밋하거나 자동 재생성하지 않는다. 실패 뒤 다음 시도는 마지막 정상 기록에서 같은 세션으로 이어간다. 시도 수와 커밋된 턴 수를 구분한다.
- 기존 UI 서버·연구 코드·기본 프롬프트·이전 원문은 변경하지 않는다. 실행 설정과 지침·코드 스냅샷을 보존한다.

## 판정 범위

요약 내용의 원문 충실도·인과 흐름·남은 걱정·상태 수준 유지 또는 변화, 조회 결과 사용과 발화 자연스러움을 직접 읽는다. 단일 적응형 세션이라 호출율의 인과 차이나 요약 없는 조건 대비 개선은 확정하지 않는다. 이전 실험의 부적절한 7~10회는 자연 상담 비교 근거에서 제외한다.
