# 수정 후 state_summary · 한 세션 10회 재실험

## 결과

실제 상담사 발화만으로 새 단일 세션에서 10회 시도했다. 처음 8회는 기본 지침에 따른 자발적 선택을 관찰했고, 마지막 2회는 도구 지시를 System prompt에만 넣었다. **도구 호출은 자발적 성장 경험 조회 1회, 지시형 내면·사건 조회 각각 1회였다.**

상담사 발화에 함수명·시스템·DB·조회 명령을 넣었던 이전 문제는 이번 입력에서 제거했다. 도구를 지시한 9·10회도 공개 내담자 발화에 도구나 시스템 이야기가 나오지 않았다. 실제 요청에서 역할 구분과 매 턴 새 프롬프트 구성, 원문 주입 및 상태 이월을 확인했다.

그러나 **10회 중 정상 반영된 것은 5턴**이다. 느낌을 숫자로 출력한 실패 1회, JSON을 코드블록으로 감싼 실패 4회가 있었다. 생성된 말은 분석할 수 있었지만 실패 출력은 다음 공개 히스토리·내면 DB에 넣지 않았다. 따라서 10턴 전체가 성공적으로 이어진 실험이나 자발적 도구 선택이 개선된 실험이라고 보고하지 않는다.

## 조건과 범위

- 버전: 수정 후 state_summary / integrated_trajectory.
- 프로필: gold_001 / 히스토리 001_h1, 초기 공개 4쌍 이후 새 세션.
- 초기 상태: 신뢰 중간 / 자기개방 낮음 / 변화 자신감 낮음.
- 모델: google/gemma-4-31B-it. 메인·요약·조회 담당 모두 동일 vLLM 모델.
- sampling: temperature 0.7, top_p 0.95, seed 없음. 메인 max_tokens 1024, 요약 512, 조회 담당 128.
- 제공 도구: retrieve_childhood, retrieve_situation, retrieve_inner_state.
- 1~8회 기본 System prompt, 9~10회 System prompt에만 조회 지시 추가. 실제 지시는 system_9.md/system_10.md 및 input_9.json/input_10.json에 보존했다.
- 입력은 직전 정상 발화를 읽고 작성했다. 실패 응답에 대답하는 질문으로 이어가지 않았다. 자동 재생성, 출력 보정, 수동 커밋을 하지 않았다.
- 기존 UI 프로세스와 연구 코드·기본 프롬프트는 변경하지 않았다. 임시 로컬 서버로 실행하고 설정·코드·DB 스냅샷을 보존했다.
- 이전 부적절한 실험 7~10회는 자연 상담 비교 근거에서 제외한다. 프로필·질문 순서·히스토리 길이·sampling 경로가 완전히 동일한 대조실험이 아니므로 전후 인과 차이를 계산하지 않는다.

## 도구 호출과 발화에 준 정보

### 2회 · 자발적 성장 경험 조회

상담사는 가족이 실제로 어떤 말을 했는지와 그 말을 어떻게 받아들였는지를 구분해 물었다. 메인은 retrieve_childhood를 선택했으며 reason에 실제 경험을 확인해 발화에 반영하려 한다고 적었다. 조회 담당은 childhood_1을 선택했다.

반환된 원문:

> 내담자는 어릴 적 부모가 성취나 겉으로 보이는 모습에 대해서만 칭찬하고, 힘들어하거나 실수하는 모습을 보이면 '남들 앞에서 그러지 말라'며 감추도록 요구받았습니다.

메인은 부모의 시선을 우선하며 실수를 숨기려 했다는 발화를 만들고 response_basis에 childhood_1을 명시했다. 정보 활용은 확인됐다. 하지만 feelings가 문자열 이름 배열이 아닌 `[3]`이어서 최종 검증에 실패했다. 이 경험은 다음 히스토리나 내면 요약에 반영되지 않았다.

원문에 없던 “빨리 정리하라” 등 구체적인 말을 덧붙였다. 핵심 경험과 해석의 연결은 있었지만 모든 세부가 조회 원문 그대로였다는 뜻은 아니다.

### 9회 · System prompt로 지시한 의미 중심 내면 조회

실제 상담사 발화는 “제안을 처음 들었을 때, 말을 꺼내는 순간과 이후 어떤 답을 들을지가 각각 얼마나 두려웠는지”를 물었다. 함수 이름과 원문 조회 요구는 System prompt에만 있었다.

메인이 작성한 arguments:

```json
{
  "query": "동료에게 자료 실수를 직접 물어보자는 제안을 처음 들었을 때 내담자가 느낀 해석과 주저한 이유",
  "reason": "상담사가 제안 당시 가장 두려웠던 점을 구체적으로 묻고 있으므로, 이전 턴에서 내담자가 속으로 느꼈던 구체적인 공포와 해석의 원문을 확인하여 일관성 있는 답변을 하기 위함입니다.",
  "state": "all"
}
```

조회 담당은 정상 생성 3턴(6회 행동 제안)의 실제 기록을 선택했다. 턴 번호 인자를 전달하지 않았고, 질문의 내용으로 ID를 선택했다. 선택 기록은 당시 가장 최근 정상 기록이기도 해서, 여러 비슷한 장면이나 오래된 기억을 구분하는 일반 성능까지 검증한 것은 아니다.

공개 발화:

> 음... 사실 둘 다 무섭긴 한데... 특히 그 뒤에 어떤 답을 듣게 될지가 더 두려운 것 같아요. 말을 꺼내는 순간의 어색함보다, 만약에 정말로 제가 생각했던 것처럼 실망했다거나 허술해 보였다는 말을 듣게 되면... 그걸 견딜 자신이 없거든요. 그냥 제가 상상하는 게 틀렸길 바라는 마음이 커서, 확인하는 것 자체가 너무 위험하게 느껴져요.

“이런 답을 들으면 견딜 자신이 없다”는 근거는 6회 원문과 일치했고, 현재 질문에 맞춰 두려움의 지점을 설명했다. 공개 발화에는 내부 조회나 기록을 읽는다는 표현이 없었다. 내면 해석은 “막막함을 단순한 거절로 치부하지 않고 이해하려 한다”였으며 이해받음을 선택했다.

다만 6회 공개 발화에도 이미 부정적인 답을 듣는 두려움이 있었고 요약에도 거부감이 있었다. 조회는 당시 원문을 확인하는 가치가 있었지만 새 정보가 반드시 필요했는지, 조회 없이도 같은 발화를 만들 수 있었는지는 이번 실험에서 분리하지 못했다. System prompt의 직접 지시에 따른 호출이며 자발적 필요성 판단으로 집계하지 않는다.

### 10회 · System prompt로 지시한 사건 조회

상담사는 당시 몸의 느낌·행동과 자기평가를 나눠 살펴보자고 물었다. 조회 담당은 situation_1을 반환했다. 핵심 정보인 얼굴·귀의 화끈거림, 손끝 차가워짐, 회의 뒤 모니터 응시가 실제 발화에 들어갔다.

> 이해해 주셔서 감사해요... 음, 그때 자리에 돌아와서도 한동안은 얼굴이랑 귀가 계속 화끈거렸던 것 같아요. 손끝은 오히려 차가워져서 타이핑하는 게 힘들 정도였고요. 그냥... 멍하게 모니터만 보면서 '너 진짜 한심하다', '어떻게 그런 기초적인 실수를 하니'라고 계속 생각했어요. 그래서 일부러 더 아무렇지 않은 척, 정말 바쁘게 일하는 것처럼 보이려고 애썼던 것 같아요. 다른 사람들이 제가 당황한 걸 눈치채지 못하게 하려고요.

1회가 조회 없이 일반적인 신체 반응을 생성했던 것에 비해, 10회는 해당 DB 사건의 구체적인 반응을 사용했다. 동시에 1회 생성의 “일에 집중하는 모습만 보이려 했다”는 표현과 “타이핑이 힘들 정도”, 자기비난의 구체 문구 같은 확장도 함께 넣었다. 조회 결과를 모두 문자 그대로만 사용한 것은 아니다.

이전 잘못된 실험처럼 “처음 설명과 다르면 정정하라”는 명령을 넣지 않았다. 이번에는 스스로를 거짓말·방어적 기억 왜곡의 당사자로 규정하는 말이 생성되지 않았다. 이 차이는 입력을 바로잡은 관찰이며 모델이나 프레임워크의 일반적인 정정 능력이 개선됐다는 증거는 아니다.

## 자발적 호출이 없던 구간

1·3·4·5·6·7·8회에는 호출이 없었다. 모두 같은 성격의 미호출은 아니다.

- 1회 몸 반응·행동 질문과 3회 가족 비교·칭찬 질문은 초기 자료에 없는 과거 상세를 요구했다. 조회 없이 내용을 구성하거나 모호한 기억으로 답했다.
- 3회는 이전 실험의 단정적인 “비교했다기보다는…”보다 “생각나는 게 없기도 하고 떠올리기 어렵다”는 표현을 썼다. DB의 비교 경험이 부정되었다고 단정하기보다, 낮은 자기개방에 따른 회피인지 실제 근거 부족에 따른 구성인지 구분하기 어렵다. 다만 자료에 없는 공부·순종에 대한 구체적인 칭찬 경험을 만들었다.
- 4·5회도 관계 사건 상세를 조회하지 않았다. 실제 이야기의 핵심 회피 패턴은 프로필과 부합했지만 피곤해서 잔다고 했다는 설명이나 단톡방 사례 등은 원기록 확인 없이 구성됐다. 두 출력은 형식 실패로 이월되지 않았다.
- 6회 행동 제안과 7회 수용 질문은 현재 프로필·상태·대화만으로 반응을 만들 수 있었다. 도구가 없다고 곧바로 실패로 보지 않는다.
- 8회는 처음과 현재의 마음을 비교하는 질문이었으나 요약에 이미 이해받는 느낌과 경계감의 공존이 있어, 재조회가 꼭 필요했다고 판단할 근거가 부족하다.

처음 8회의 자발적 호출은 1/8회였다. 이전 수정 전 정상 상담 구간도 성장 경험 질문에서 1회 호출했다. 독립 반복이나 같은 히스토리 대조가 아니므로 자발적 선택이 좋아졌다거나 나빠졌다는 결론을 내리지 않는다.

### 보존한 내용

- 1회 공감에 안도하지만 상세를 드러내는 것은 부담스럽다는 양가 반응.
- 3회 가족사로 너무 빨리 들어간다는 경계와 낮은 자기개방.
- 6회 배려에는 감사하지만 동료에게 직접 확인하는 행동은 위험하다는 해석.
- 9회 두려움의 지점을 세심하게 묻는 상담사에게 다시 이해받으며 경계심이 완화된 반응.

10회 전에 전달된 실제 통합 요약:

> 상담사가 내담자의 불안과 방어 기제를 정확히 짚어내고 어려움을 세심하게 이해하려 노력하는 모습에 신뢰감을 느끼며 안도하지만, 자신의 허술함이나 결함이 드러나는 것에 대한 근본적인 두려움과 수치심이 커서 자기개방 의향과 변화 자신감은 계속해서 낮은 상태로 유지되고 있습니다. 특히 상담사가 구체적인 신체 반응이나 과거 가족사, 혹은 동료에게 직접 확인하는 행동을 제안했을 때 이를 자신의 치부를 드러내야 하는 위험한 상황으로 인식하여 강한 부담감과 경계심을 느꼈으며, 상담사의 배려와 공감으로 서운함이 완화되더라도 타인에게 부정적인 평가를 확인받는 것에 대한 공포가 여전히 크게 남아 있습니다.

원문에 있던 안도와 경계, 위험한 행동 제안에 대한 거부, 이후 이해받는 느낌의 완화를 함께 담았다. 상태 수준은 그대로인데 낮음/높음 사이의 변화를 지어내지는 않았다. 턴별 목록 대신 한 문단으로 출력했다.

### 효과의 판정 범위

9회의 “내가 얼마나 무서워하는지 모르는 것 같다”는 이전 서운함이 완화됐다는 내면 근거는 6회 기록에 연결된다. 10회에서는 두려움을 몰아세우지 않는다는 안도를 표현하면서도 조심스러움을 유지해, 요약에 담긴 남은 걱정과 대체로 이어졌다.

그러나 메인은 전체 공개 대화와 프로필도 받는다. 요약 없이 같은 입력을 실행하지 않았으므로 이 연결을 요약의 인과적인 도움으로 단정하지 않는다. 특히 9·10회는 도구 지시라는 조건도 달라졌으므로 감정 변화나 발화 구체성이 도구만의 영향이라고 주장하지 않는다.

요약은 여전히 구체적인 심리 이유들을 “결함 노출 → 수치심·경계 → 낮은 자신감”이라는 공통 패턴으로 압축한다. 가족 비교·인정 경험의 구체 사실은 조회하지 않으면 요약만으로 보완되지 않는다. 요약의 잘못과 원 생성·조회의 부족은 구분해야 한다.

### 형식 실패가 trajectory에 주는 영향

4·5·7·8회 실패 원문은 이해받음·선택권 존중을 선택했고, 특히 7·8회는 사과·거절 수용에 안도하는 발화였다. 하지만 이 출력들은 저장되지 않아 이후 요약에 들어가지 않았다. 그래서 9회 전의 요약은 행동 제안에 대한 경계까지 읽지만, 실패한 사과·수용 경험 뒤의 회복을 읽지 못한다.

이것은 요약 담당이 긍정적인 기록을 누락한 오류가 아니다. **정상 기록으로 입력되지 않았기 때문이다.** 연속 실험에서 출력 형식 실패는 단순히 화면에 오류가 뜨는 것 이상으로, 기록과 이후 심리 흐름을 바꾼다.

## 발화·상태의 관찰

도구나 내부 시스템 이야기가 내담자의 공개 발화로 흘러나오는 현상은 이번 10개 출력에서 보이지 않았다. 9·10회의 실행 지시는 System prompt에 있었으며 상담 내용은 별도로 유지됐다. 하지만 반복한 독립 검증이 아니므로 완전한 방지를 입증했다고 말하지 않는다.

말투와 대화 연결은 대체로 자연스러웠다. “음…”, “그냥…”, “사실…” 등의 표현은 반복됐다. 9회는 두려움의 지점을 더 구체적으로 말하고, 10회는 당시 신체 반응과 자기비난을 설명했다. 낮은 자기개방을 망설임과 조심스러운 말투로 표현하면서도 상당히 구체적인 내용을 제공했으므로, 발화의 공개 정도와 상태 수준 사이의 기준은 추가 관찰이 필요하다.

정상 저장 5턴과 실패 원문 5개의 출력 수준은 모두 신뢰 중간 / 자기개방 낮음 / 변화 자신감 낮음이었다. 근거에서는 안도·경계·서운함의 완화가 변했지만 범주 수준은 변하지 않았다. 상태 수준이 거친 구간이거나 원래 프로필·초기 상태의 영향이 클 수 있어 한 세션으로 원인을 확정하지 않는다.

정상 저장된 5턴의 다중 선택 빈도는 이해받음 4회, 부담·압박 2회, 선택권 존중 2회다. 실패 원문 중 올바른 문자열 이름까지 포함하면 이해받음 8회, 부담·압박 2회, 선택권 존중 6회다. 2회의 `[3]`은 잘못된 출력 타입으로 별도 기록했고, 숫자를 이름으로 자동 치환하거나 정상 느낌 집계에 넣지 않았다.

## 실행과 사용량

- 정상 저장: 1·3·6·9·10회, 총 5턴.
- 실패: 2회 느낌 숫자 출력; 4·5·7·8회 JSON 코드블록 출력. 모두 stop으로 완료됐으나 최종 형식 검증에 실패했다.
- 도구: 3회 모두 실제 결과 found, 실행 오류 없음. 이 중 2회는 최종 내담자 출력 검증에 실패했다.
- 생성 호출: 메인 13 + 조회 담당 3 + 자동 요약 9 = 25회. 자동 요약은 Python이 실행하며 자발적 tool_call 수에 포함하지 않는다.
- 전체 사용량: 77,837토큰, 실패 출력 사용량 포함.
- 응답 대기: 약 24~45초. 9회 내면 선택은 조회 담당 입력 3,085토큰을 추가로 사용했다. 이미 요약에 충분한 정보가 있는 경우 원문 확인의 이득과 비용을 함께 봐야 한다.
- 같은 턴의 role:tool 실제 주입, 다음 상담 턴의 system+user 재구성, 실제 공개 발화만의 히스토리 복원, 최신 상태 이월, 지침/상담사 발화 분리는 모두 검증 통과했다.

## 이번 결과로 판단할 수 있는 것

1. 프롬프트 재구성과 역할 구분은 실제 요청에서 의도대로 동작했다. 잘못된 상담사 발화 지시를 제거해 도구 사용 실험을 올바른 입력 영역에서 수행했다.
2. 의미 중심 내면 조회는 질문으로 관련 원문을 선택했고, 결과는 실제 발화의 근거로 사용됐다. 이번 선택은 가장 최근 정상 기록이기도 해서 원격·모호한 장면 구분 능력은 별도 검증해야 한다.
3. 자발적 조회는 여전히 성장 경험 1회였으며 미조회 질문이 많았다. 호출 필요성 판단의 개선은 입증되지 않았다.
4. 요약은 정상 원문의 전체 흐름과 남은 걱정을 유지했지만, 5회 형식 실패로 긴 연속 trajectory 검증은 제한됐다.
5. 현재 가장 명확한 실행 장애는 출력 계약이다. 이 부분을 별도로 정리한 뒤 정상적으로 더 길게 이어지는 세션에서 도구와 요약 효과를 관찰할 필요가 있다. 이번에는 실행 중 코드·출력 보정을 변경하지 않았다.
