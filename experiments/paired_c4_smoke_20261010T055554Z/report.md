# C4 양방향 UI 실제 연결 검증

- 모델: google/gemma-4-31B-it, 현재 config의 로컬 vLLM.
- 조건: group1_001_h1, state_summary, 프로필 selective, 내담자 기본 생성 설정, C4 원본 프롬프트·검증·재시도.
- 범위: 새 세션에서 내담자 1개와 상담사 1개 발화 생성 시도. 품질 비교나 대량 실험이 아니다.

내담자는 정상 JSON으로 내면 상태와 공개 발화를 생성했다. 공개 발화는 “그렇게 말씀해 주시니까 조금 마음이 놓이네요... 사실 이런 얘기를 하는 것 자체가 저한테는 좀 낯설고 어려운 일이라서요.”였다.

C4는 이 공개 대화를 입력으로 관찰을 완료했다. 이후 상담 행동 선택에서 `task_board`에 T1이 존재하는데도 `task_focus.task_id`와 `task_link.task_id`를 `none`으로 생성했다. C4 원본 검증에서 허용되지 않는 참조로 판정했고, 원본의 단계 재시도 4회(최초 포함) 후 오류로 종료했다. 모델의 C4 출력은 코드 펜스가 있었지만 C4 원본 파서가 처리했고, 실패 이유는 펜스가 아니라 과제 참조 규약이었다.

내담자 모델 호출은 1회, C4는 관찰 1회와 행동 선택 4회로 총 5회였다. C4의 발화 생성 단계에는 도달하지 않았다. 따라서 이 실제 실행은 성공적인 상담사 최종 발화 생성 검증으로 해석할 수 없다. 모의 HTTP 모델 테스트에서는 실제 C4 코드를 사용해 관찰→선택→발화, 6개 교대 발화와 ledger 복원을 별도로 검증했다.

C4 실제 요청에는 공개 대화와 상담사 작업 기록만 있었으며 내담자 비공개 profile/states/taxonomy/inner_state/summary 입력 키는 없었다. 실패한 C4 발화는 공개 대화에 추가되지 않았고 다음 차례는 counselor, C4 체크포인트는 생성 전 값(null)을 유지했다. 실제 요청·출력·단계 재시도·오류는 각 events 파일과 sessions/paired/logs에 보존했다.

C4 프롬프트·과제 참조 검증은 이번 UI 구현에서 임의로 수정하지 않았다. UI는 이러한 모델/검증 실패를 표시하고 자동 실행을 멈춘다.
