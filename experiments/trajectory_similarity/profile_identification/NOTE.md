# 후반 발화로 프로필 맞추기 (탐색, 2026-11-08)

## 목적

가설: 과거 내면을 다시 제공하지 않으면 궤적이 LLM 편향 쪽으로 수렴해 프로필별 다양성이 줄어든다.

지금까지 쓴 "서로 다른 프로필끼리의 유사도"는 다양성만 잴 뿐, 그 다양성이 각 프로필에 붙어 있는지는 재지 못한다. 그래서 후반 발화만 보고 10개 프로필 중 누구인지 맞힐 수 있는지(식별 정확도)를 주 지표로 쓴다. 가설이 맞다면 미제공 조건의 식별 정확도가 더 낮아야 한다.

## 공통 조건

- 입력: 배치 4개(`28cf48`, `0d9d6d`, `c9c8c4`, `08f865`). 프로필 gold_001~010, 조건당 20턴. 배치·조건·프로필마다 대화 1개씩, 조건당 40개다.
- 발화 정리: 공개 발화에 남은 도구 호출 태그(`</utterance>` 등)를 지운다(`data.py`). 중국어 토큰은 그대로 둔다.
- 프로필 카드: `data.py`의 `card_text()`. id, 메타, 작성일을 빼고, 인구학 정보·호소 문제·핵심 신념·어린 시절·중간 신념·대처·상황 예시를 넣는다. 네 배치의 프로필 내용이 같은지 검사한다.
- 조건 비교: (배치, 프로필) 짝 40개에서 조건 이름을 바꾸는 쌍대 순열검정을 쓴다.
- 생성 모델은 호출하지 않는다.

## 1. 임베딩 식별 (`identify.py`)

실행:

```bash
python identify.py --embedding-url http://192.168.0.32:8002/v1
```

결과는 `results/20261108_201151_c128b5/`에 있다.

방법:

- 5턴 구간(1~5, 6~10, 11~15, 16~20)마다 카드 10개와의 코사인 유사도로 순위를 매긴다.
- 지표는 top-1, MRR, margin(자기 카드 유사도 − 다른 카드 평균)이다.
- 쿼리 방식은 두 가지다.
  - `centroid`: 발화별 임베딩의 평균(지시문 없음)
  - `instruct`: 5발화를 이은 텍스트에 검색 지시문을 붙인 것
- `_centered`는 카드별 평균 유사도를 빼서, 모든 쿼리를 끌어당기는 카드(허브)의 영향을 없앤 것이다.

pooled top-1 결과 (기억 / 미제공, 우연 수준 0.10):

| 구간 | centroid_centered | instruct_centered |
|---|---|---|
| 1~5 | 0.78 / 0.88 | 0.78 / 0.80 |
| 6~10 | 0.58 / 0.70 | 0.70 / 0.70 |
| 11~15 | 0.40 / 0.33 | 0.43 / 0.40 |
| 16~20 | 0.35 / 0.30 (p=0.81) | 0.53 / 0.40 (p=0.36) |

- 두 조건 모두 턴이 지날수록 식별 정확도와 margin이 크게 떨어진다. instruct margin은 0.15에서 0.05~0.06으로 줄었다.
- 모든 구간과 방식에서 조건 차이는 우연 범위 안이다.
- 16~20턴 instruct_centered의 배치별 방향은 엇갈린다. 08f865는 기억 쪽(0.7 / 0.2), 나머지는 비슷하거나 반대다.

## 2. LLM 블라인드 식별 (`build_blind.py`, `score_blind.py`)

방법:

- 발췌: 16~20턴 내담자 발화 5개. 상담사 발화는 뺐다.
- 네 배치의 두 조건 발췌 80개를 한 묶음으로 섞었다.
- 카드는 P1~P10으로 이름을 다시 붙이고 순서를 섞었다.
- 평가자는 서로 다르게 섞은 묶음 2개(seed 1108, 2026)를 맡은 하위 에이전트 2개(Claude, general-purpose)다. 묶음 파일만 읽도록 지시했다.
  - 평가 중에는 정답표를 평가자의 작업 폴더 밖(세션 임시 폴더)에 두었다가, 채점 직전에 `blind/`로 옮겼다.
- 답변 형식: 발췌마다 top-1, top-2, 확신도(3 = 고유한 인물·사건, 2 = 주제·말투, 1 = 거의 추측), 근거 한 줄. 프로필별 개수는 알려 주지 않았고, 소거법을 쓰지 말라고 지시했다.
- 원본은 `blind/packet_*.md`, `answers_*.json`, `key_*.json`이고 채점 결과는 `blind/score.json`이다.

| | 기억 유지 | 미제공 | 차이 p |
|---|---|---|---|
| top-1 (평가자 평균) | 0.85 | 0.875 | 0.84 |
| top-2 | 0.90 | 0.95 | 0.50 |
| 확신도 3 비율 (평가자 1108 / 2026) | 21 / 21 (40개 중) | 22 / 22 | |

- 두 평가자의 정오(맞음/틀림)는 95% 일치했다.
- 확신도 3은 두 평가자 모두 100% 맞았다. 틀린 사례는 거의 모두 확신도 1이었다.
- 틀린 사례는 두 조건에서 비슷하게 나왔다. 대부분 주제가 겹치는 프로필(001, 002, 003, 009)이었다. 근거로는 "~라는 말 처음 들어요", "명치", "그냥 옆에 있어주기" 같은 일반적 과정 대화가 적혀 있었다.

## 판단

- 후반 5턴 내담자 발화로 프로필을 맞히는 정확도는 기억 유무와 관계없이 같다. 가설 방향의 차이는 이 지표에서도 나오지 않았다.
- 임베딩과 LLM의 결과가 크게 다르다(16~20턴 0.3~0.5 vs 0.85).
  - 임베딩은 일반적 과정 대화(몸 감각, 머물기, 유보)에 지배된다. 발췌 안에 프로필 고유 사실(개, 도서관 자리, 인사팀 등)이 한두 개 있어도 반영하지 못한다.
  - 임베딩에서 보인 "수렴"은 일반 과정 대화의 비중이 커졌다는 뜻으로 읽어야 한다. 개인 정보가 사라졌다는 뜻은 아니다.
- LLM 식별은 천장에 가깝다. 10개 프로필이 서로 너무 달라서 고유 사실 하나로도 맞힐 수 있다. 차이를 보려면 다음이 필요하다.
  - 주제가 겹치는 프로필끼리 묶은 더 어려운 식별 과제
  - 고유 사실의 개수를 직접 세는 지표

## 한계

- 프로필 10개, 조건당 대화 1개(배치 4개 합산 40개)이고 상담사 경로가 통제되지 않았다.
- LLM 평가자 2개는 같은 모델이다.
- 카드에 있는 상황 예시를 그대로 다시 말하는 발췌는 맞히기 쉽다. 따라서 이 지표는 "카드 내용 재사용"도 함께 잰다.
