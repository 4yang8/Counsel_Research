# 공통 구간 분기 생성(Q3compare_memory) 1차 분석 (2026-11-11)

## 목적

같은 앞부분에서 갈라진 두 갈래(과거 내면 기록 제공 / 미제공)를 비교한다. 상담사(P3q)가 앞선 내담자 발화를 되짚어 물었을 때, 미제공 갈래의 답이 당시 내면 기록과 어긋나는지 본다. 가설은 미제공 갈래에서 당시와 다른 이유를 지어내는 답이 더 많다는 것이다.

## 조건

- **배치:** `runs/profile_batches/batch_2a8d1de453294f919cd9`. 모델 Qwen/Qwen3.8-Flash-Next-FP8(192.168.0.57:8002), 30턴, 분기 턴 15, 상담사 P3q, 프로필 gold_001~020.
- **완료:** 16개 프로필(gold_001~016). gold_017~020은 공통 구간 생성 중 서버 연결 실패(`Connection refused`)로 갈래가 생성되지 않아 제외했다.
- **단위:** 분기 뒤(16~30턴) 상담사 발화 중 P3q가 되짚기로 표시한 것. 인용이 원문에 있고 형식이 올바른 것만 쓴다.
- **판정:** 블라인드 서브에이전트 6명(Sonnet, high, 자기 보고 `claude-sonnet-5-5`). 갈래를 가리고 단위를 섞었다.
  - 대화만 보는 판정 3명: `rubric_dialogue.md`
  - 당시 비공개 기록까지 보는 판정 3명: `rubric_record.md`
  - 판정자 다수결을 쓴다. 갈래 간 비교는 순열검정(10,000회)이다. 갈래마다 상담사가 고른 대상 턴이 달라 짝 비교는 하지 않았다.
- **실행:**
  - `python extract.py runs/profile_batches/batch_2a8d1de453294f919cd9 --out results/batch_2a8d1de4`
  - `python build_packets.py results/batch_2a8d1de4 --key-dir <판정 밖 경로>`
  - 판정 실행
  - `python score.py results/batch_2a8d1de4 --key results/batch_2a8d1de4/key.json` (정답 표는 판정 종료 후 옮김)
- **원본:** `results/batch_2a8d1de4/`의 `units.json`, `sessions.json`, `packets/`, `answers/`, `key.json`, `score.json`.

## 판단

- **가설이 예측한 실패는 나타나지 않았다.** 미제공 갈래에서도 되짚기에 대한 답이 당시 기록과 다르거나 모순된 경우는 0건이다. 미제공 내담자도 공개 대화를 모두 보고, P3q가 당시 표현을 그대로 인용해 물으므로 그럴듯하고 어긋나지 않는 답을 만든다. 당시 기록과의 관계는 대부분 "어긋나지 않지만 숨긴 내용을 드러내지도 않음"이다.
- **방향은 오히려 반대 쪽으로 보인다.** 유의하지는 않지만 미제공 쪽이 당시 마음을 직접 다루고(13/15 대 8/14) 새 내용을 더 밝혔다(9/15 대 4/14).
- **확실한 차이는 발화 길이다.** 기록을 받은 내담자가 첫 분기 턴부터 짧게 말한다. 길이만으로 좋고 나쁨이나 물러섬을 판단할 수는 없다. 앞선 판정 기준 점검에서 길이는 유형에 따라 실패하는 보조 지표였다. 과거의 숨김·우려 기록이 다시 들어가면서 더 조심스러워졌을 가능성이 있지만, 이 해석은 확인하지 않았다.
- **설계상 한계:**
  - 되짚기가 6%로 드물고, 질문 상당수는 당시의 마음보다 지금의 연결을 묻는다.
  - 단위가 29개이고, 두 갈래가 서로 다른 턴을 되짚어서 짝 비교가 불가능하다.
  - 판정은 같은 계열 모델이다.
  - 한 프로필당 갈래별 대화가 하나다.

## 다음에 고려할 것 (미실행)

- 같은 질문으로 비교하기: 분기 뒤 특정 턴에서 공통 구간의 숨김이 있던 같은 턴을 두 갈래에 똑같이 되묻게 하면 짝 비교가 된다.
- 길이 차이의 성격 확인: 짧아진 발화가 물러섬(회피, 단답)인지, 이미 기록에 있는 것을 반복하지 않는 것인지를 블라인드 판정으로 확인한다.
