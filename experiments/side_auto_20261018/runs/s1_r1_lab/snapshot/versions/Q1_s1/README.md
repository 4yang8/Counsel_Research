# Q1 · 특성 라우팅과 비공개 내면 노트

## 실행

기존 `counseling_test/run.sh`로 UI 서버를 실행한다. 서버 재시작·브라우저 새로고침 후 **새 대화 → 실험 설정 → 내담자 → Q1**을 선택한다. 상담사 버전은 별도로 선택하며, 직접 입력할 역할은 기존 채팅 입력 영역의 체크박스로 설정한다.

## 한 턴의 흐름

1. Python이 특성 라우터를 매 턴 자동 실행한다. 메인과 같은 연결·모델·생성 설정을 쓰지만 별도 컨텍스트이며, 라우터에는 도구를 주지 않는다.
2. 라우터가 전체 특성에서 관련 항목의 ID와 선정 근거를 반환한다. 빈 배열을 허용한다. Python은 ID를 검증하고 선택된 **원본 특성**만 메인 입력에 넣는다.
3. 메인은 기본 정보·공개 대화·관련 특성·현재 내면 노트를 읽고 이번 appraisal를 판단한다.
4. `stage_client_update(appraisal, inner_notes)`로 변경안을 제출한다. appraisal는 매 턴 기록하며, 내면 노트는 전체 변경 원문 또는 `null`로 유지한다. 다시 제출하면 마지막 유효 변경안을 사용한다.
5. 공개 발화가 `stop`으로 정상 완료되고 변경안이 유효하면 appraisal 로그와 최신 내면 노트 파일을 저장한다. 생성 실패·중단 시 변경안을 폐기한다. 양방향 세션은 성공한 실행의 비공개 저장 경로만 다음 턴으로 인계한다.
6. 상담사에게는 내담자의 공개 발화만 전달한다. 라우팅·내면 노트·도구·reasoning은 전달하지 않는다.

## 입력 정보의 경계

- 기본 정보: `profile_id`, `name`, `age`, `gender`, `occupation`, `background`, `demographic_context`, `presenting_problem`, `recent_context`, `desired_help`.
- 특성: 위 기본 정보와 제외 필드를 뺀 프로필 항목. 중첩 객체·배열의 각 값을 ID가 있는 항목으로 펼친다. 기본 예제의 `traits`, `counseling_preferences`, 그룹1의 신념·대처 필드를 지원한다. 원본 프로필은 변경하지 않는다.
- 이번 버전 미사용: `childhood_data`, `situations`, `created_at`, `meta`, `start_rapport`.
- Q1은 기존 예제의 `task`, `states`, `taxonomy`를 모델 입력에 넣지 않는다. 해당 편집 영역은 Q1 선택 시 숨긴다. 구조화된 높음/중간/낮음 상태 대신 현재 내면 노트로 시작한다.
- 메인에게 이전 턴 reasoning·도구 기록·appraisal 로그 전체를 다시 넣지 않는다. 같은 턴의 도구 호출 전 reasoning은 기존 도구 루프가 보존한다.
- 이전 특성이 이번에 선정되지 않더라도 그때 생긴 감정은 내면 노트에 남아 이어질 수 있다.

## 파일과 저장

- `system.md`: 메인 내담자 지침. 새 세션 시작 시 고정된다.
- `trait_router.md`: 특성 라우터 지침. 매 호출 파일에서 읽는다.
- `inner_notes_template.md`: 아직 생성된 기록이 없는 세션의 초기 내면 노트.
- `runtime.py`: 프로필 분리, 라우팅 ID 검증, 도구 인자 검증, 저장과 이벤트.
- 세션 내부 `Q1/<session_id>/inner_notes.md`: 다음 턴 입력에 원문을 읽어 넣는 **하나의 현재 내면 노트 파일**.
- `appraisals/<turn>_<turn_id>.json`: appraisal·선정 특성·노트 변경 전후·실제 발화를 담는 성공 턴별 감사 로그. 자동으로 다음 모델 컨텍스트에 넣지 않는다.
- 추론·실패·중단과 임시 변경안도 기존 이벤트 저널에 기록된다. 임시 변경안은 현재 내면 노트가 아니다.

## UI

- 실험 설정 → 내담자에서 메인과 특성 라우터 프롬프트를 조회·편집·저장·실행취소한다. 원본 파일을 수정하며, 메인 변경은 새 세션부터, 라우터 변경은 다음 호출부터 적용한다.
- 내담자 추론 토큰 한도는 메인/라우터를 각각 켜서 설정한다. 기본값은 한도 미지정이며 두 한도를 상속하지 않는다. 설정은 세션에 저장한다.
- 채팅에는 라우터 reasoning·선정 결과, 메인 reasoning, 도구와 노트 추가·삭제, 최종 공개 발화를 순서대로 표시한다. 서브에이전트는 기존과 같은 별도 배경색이다.
- 발화의 `관련 특성 · appraisal · 내면 노트`에서 해당 턴 기록을 확인한다. Raw 컨텍스트의 에이전트 선택으로 메인/라우터 실제 입력을 각각 확인한다.
- Workflow에는 라우터 → 메인의 자동 선정 전달 화살표, 메인 → 기록 도구 → 후속 메인의 호출·결과 화살표를 표시한다.
- 새 대화·저장 세션 선택·생성 중단·재시도·양쪽 역할의 수동/모델 입력은 기존 UI를 공유한다. basic, state_summary, P1~P3a는 유지한다.

## 검증 범위

모의 HTTP 모델과 브라우저 검증은 호출 순서, 특성 정보 경계, 노트 유지·갱신·폐기, 공개/비공개 분리, 세션 이어가기, 프롬프트 저장과 화면 재생을 확인한다. 실제 모델의 관련성 판단이나 상담 반응의 자연스러움은 별도 실험으로 평가한다.
