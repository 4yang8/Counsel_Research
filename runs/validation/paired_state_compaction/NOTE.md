# Paired 상태 저장 정리 결과 — 2026-11-12

## 요청과 변경

발화마다 누적 상태 폴더를 보관하는 대신 최신 상태 파일을 갱신하도록 변경하고 기존 사본을 정리했다. 적용 대상은 `client.memory_access.VERSIONS`다. 과거 시점 체크포인트를 사용하는 Q3p6와 다른 저장 형식의 런타임은 변경하지 않았다.

생성 중에는 임시 작업본을 쓰며 공개 세션 저장과 함께 최신 상태를 확정한다. 실패 작업본은 압축 보관한다. 확정 도중 중단된 경우에는 저널로 이전 상태를 복구한다. 프롬프트, 제공/미제공 조건, 대화 내용, 모델 로그 저장 방식은 변경하지 않았다.

## 기존 데이터

- 612개 세션을 검사하고, 확정된 memory_state를 가진 367개 세션을 이전했다.
- 이전 상태 사본 4,640개 파일, 5,665,664,757 bytes를 정리했다.
- 최신 상태: 663,221,643 bytes.
- 모든 과거 시도의 압축 보관본: 956,607,133 bytes.
- 원래 session.json 백업과 매니페스트를 포함한 state_archive 전체: 983,939,851 bytes.
- 상태 사본 영역은 약 5.28 GiB에서 최신 상태와 보관본·백업을 포함해 약 1.53 GiB로 감소했다.
- 정리 후 runs/paired 전체 파일 내용 크기: 34,078,231,389 bytes (약 31.74 GiB). 요청·응답·추론 JSON 9,555개와 상세 이벤트 JSONL 9,555개는 그대로 보존했다.
- 정리 오류: 0. 확정 상태가 없는 세션, 다른 런타임, 정리할 시도 폴더가 없는 세션은 건너뛰었다.

각 세션의 `state_archive/`에 원래 session.json, 압축본, SHA-256과 용량 매니페스트가 있다. 압축본은 원본 모든 파일과 바이트 단위로 비교한 뒤 기존 사본 폴더를 정리했다. 완료 후 367개 세션 모두 최신 상태/압축본 SHA-256과 공개 세션의 의미적 동일성을 다시 확인했다. 세션의 상태 경로와 저장 트랜잭션 식별자만 변경됐다.
