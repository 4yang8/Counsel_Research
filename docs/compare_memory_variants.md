# 상담사·내담자 구조 비교 실험군

## 목적과 조건

맥락에 맞는 상담사 제안·해석에 대해 내담자가 느낀 것과 말한 것이 다를 수 있고, 이후 그 순간을 확인했을 때 과거 내면의 보존·활용이 어떤 차이를 만드는지 연구한다. 부정적 반응, 숨김, 공개, 제공 조건의 우위를 강제하지 않는다. 현실적·임상적 타당성이나 우수성을 이미 검증했다고 주장하지 않는다.

상담사 10개 설계 중 기존 `P3rs`, `P3rs_sub` 2개를 보존하고 8개를 추가했다. 내담자는 기존 긴 버전명을 보존하면서 새 `Q3cm` 실험군 7개 (`cm`은 소문자)를 추가했다.

- [상담사 구조·호출 수·기록](../src/counselor/rs_variants/README.md)
- [내담자 구조·호출 수·비공개 입력 경계](../src/client/memory_access/CM_VARIANTS.md)
- [평가 실행 안내](../eval/README.md)

## 실행

앱 서버를 재시작하고 브라우저를 새로고침한다. 대량생성 탭에서 `공통 생성 후 분기 · Q3cm...`와 상담사 버전을 선택한다. 프로필·최종 턴 수·분기 n을 같게 설정해 비교한다. 분기 단위는 기존 방식대로 내담자 n턴 답변부터다. 여러 배치를 별도 탭에서 시작할 수 있다. 이번 작업은 전체 조합을 자동 생성하지 않는다.

평가의 `config.json`에서 `counselors`, `clients`를 선택하거나 실행 옵션으로 지정한다. 예:

```bash
bash eval/run.sh --counselor P3rs --counselor P3rs_full --client Q3cm --client Q3cm_full
```

현재 모든 후보가 하나의 통제된 실험은 아니다. 사건 요약을 추가하면 정보량도 달라지고, 보조 호출을 늘리면 연산량도 달라진다. 후보 안의 제공/미제공 효과와 후보 간 구조 차이를 구분해야 한다. 프로필·모델·생성 설정·턴 수·분기 시점도 기록한다.

## 검증 범위

모의 서버의 실제 HTTP 생성 경로에서 모든 신규 내담자의 분기·기억 차단, 모든 신규 상담사의 단계 연결을 확인하는 테스트를 `tests/test_cm_rs_variants.py`에 추가했다. 단계별 구조·저장 성공은 가설 효과나 자연스러운 대화를 입증하지 않는다. 실제 생성 후 공개 대화와 내면 참조 평가를 통해 확인한다.

테스트 명령:

```bash
COUNSELING_PYTHON=/home2/sjyang114/miniconda3/envs/NLP/bin/python bash scripts/test.sh
PATH=/home2/sjyang114/miniconda3/envs/NLP/bin:$PATH node tests/browser_compare_branch.cjs
```

기존 프롬프트·대화·실험 결과를 덮어쓰거나 삭제하지 않는다. 새 단계 프롬프트는 배치/세션 생성 시 고정하며, 수정한 지침은 새 배치에 적용한다.

- 전체 Python 회귀검사: **362개 통과** (342.558초).

- 기존 평가 코드 검사: **8개 통과**.

- 과거 비공개 원본/파생 상태의 미제공 입력 차단, 상담사 입력의 비공개 정보 배제, 실패한 검토 초안의 미확정, 실제 반응 불변 및 단계별 실행·기록을 확인했다.

첫 전체 검사에서는 테스트 fixture가 모든 상담사 런타임을 기존 개별 모듈로 가정하여 새 공유 런타임의 경로를 바꾸지 못했다. 공유 런타임의 프롬프트 루트를 따로 격리하도록 테스트 환경을 수정한 뒤 위 전체 검사를 통과했다.

원본 검사 출력은 [검증 기록](../runs/validation/cm_rs_variants_20261112/NOTE.md)에 보존한다. 외부 생성 모델 호출이나 실제 배치 생성, 유료 LLM 평가는 실행하지 않았다. 위 결과는 구현·연결 검증이며 상담 행동의 자연스러움이나 연구 가설의 지지를 뜻하지 않는다.
