# 화면 안의 조합별 대량생성·평가

앱 서버 재시작 후 브라우저를 새로고침한다. 상단 작업 탭은 **대화 실험 / 조합별 대량생성 / 평가**다. 화면을 전환해도 기존 화면을 폐기하거나 새 브라우저 탭을 열지 않는다. 생성과 평가는 서버에서 계속 실행된다.

## 조합별 대량생성

1. 프로필 폴더를 조회하고 사용할 프로필을 선택한다.
2. 내담자 버전과 상담사 버전을 각각 복수 선택한다. 내담자 2종 × 상담사 3종이면 6개 배치를 만든다.
3. 모델 서버·모델, 동시생성 수, 분기 n, 전체 턴, 재시도, Temperature, Max tokens, Seed, Thinking, 입력 한도와 시작 발화를 설정한다. 선택한 상담사에 개입 조건이 있으면 해당 버전 옆에서 선택한다.
4. **모든 조합 생성 시작**을 누른다. 조합마다 고유한 프롬프트·프로필·설정을 고정하고, 기존 공통 생성/제공/미제공 분기 실행기를 사용한다.

**동시생성 수는 작업 묶음 전체의 프로필 흐름 상한**이다. 조합마다 이 수를 곱하지 않는다. 한 흐름은 공통 구간 → 제공 분기 → 미제공 분기를 처리한다. 보조 에이전트의 내부 병렬 요청 수는 별도다. 별도로 시작한 다른 작업 묶음에는 그 묶음의 상한이 적용된다.

각 조합의 배치를 독립적으로 저장하며, 진행률은 전체와 배치별로 표시한다. **배치 상세**를 누르면 같은 화면의 상세 창에서 대화·내면 기록을 확인한다. 중단·재개는 작업 묶음에서 수행한다. 완료된 세션은 재생성하지 않는다. 생성 서버가 재시작되면 중단 상태를 표시하고 저장된 턴부터 재개할 수 있다.

생성 전 모든 조합의 설정을 검증한다. 디스크 저장 중 실패하면 생성된 기록과 오류를 보존하며 불완전한 묶음을 성공으로 바꾸지 않는다.

## 이름과 저장 위치

- 새 배치·작업 묶음 이름: 한국 시간 `MMDD_HHMMSS`, 예: `1112_091123`.
- 같은 초의 충돌: `1112_091123_02`, `_03` 등. 디렉터리를 원자적으로 예약하며 기존 기록을 덮어쓰지 않는다. 연도와 정확한 생성 시각은 `created_at`에 남는다.
- 조합 묶음: 저장 루트의 `batch_groups/<이름>/job.json`.
- 각 조합 배치: 저장 루트의 `profile_batches/<이름>/job.json`.
- 대화·내면·원본 로그: 기존 paired/client 저장 구조 유지.
- 기존 `batch_<랜덤 ID>` 배치의 이름·내용은 바꾸지 않으며 계속 조회·평가할 수 있다.

## 평가 탭

대상 선택은 두 가지다.

- **버전 조합별 최신 완료 배치:** 내담자·상담사를 선택하면 각 조합의 최신 완료 compare 배치를 고른다. 누락된 조합이 있으면 알리고 시작을 막는다. 버전을 조정하거나 배치 직접 선택으로 전환할 수 있다.
- **배치 직접 선택:** 이전 배치를 포함해 여러 배치를 직접 지정한다. 미완료·실패·비분기 배치는 목록에서 이유를 표시하며 선택할 수 없다.

실행 시 선택한 배치 ID를 고정한다. 도중에 새 배치가 완료돼도 평가 대상이 바뀌지 않는다. 웹에서 선택한 저장 루트의 기록을 기존 평가 파서로 읽는다.

설정: `codex exec` 동시 실행 수, 반복 수, 재시도 수, 평가 1회 제한 시간, 배치당 프로필 상한. 모델·effort는 `eval/config.json`의 값으로 표시하며 현재 기본은 `gpt-6-luna` / `max`다. 대화 2조건 × 공개/내면 평가 2종 × 반복 수를 기준으로 예상 평가 횟수를 보여 준다. 첫 평가 한 건으로 모델·인증 오류를 확인한 뒤 나머지 작업을 설정한 병렬 수로 실행하는 기존 로직을 유지한다.

**입력 준비·코드 집계만 실행**을 선택하면 LLM 호출 없이 입력 스냅샷, 코드 지표, LLM 평가 미실행 표시가 있는 그래프를 생성한다. 준비 완료 후 **미완료 평가 재개**를 누르면 실제 LLM 평가를 수행한다.

진행률에는 성공·실패를 구분한다. 실행 로그에서 인증/모델/파싱 오류를 확인할 수 있다. 완료 후 PNG 그래프를 화면에 표시하고 보고서·CSV·JSON을 다운로드할 수 있다. 평가 실패를 0점으로 대체하지 않는다.

**중단**은 실행 중인 평가 CLI와 그 하위 `codex exec` 프로세스 그룹을 종료한다. 원본 응답·실패 시도·결과는 남는다. **재개**는 고정된 입력·모델·평가기준을 유지하고 실패/미완료 평가를 다시 수행하며, 동시 평가 수만 화면 값으로 바꿀 수 있다. 평가 코드·프롬프트가 바뀌었으면 기존 CLI가 재개를 거절하므로 새 평가를 만든다.

평가 작업: `eval/web_jobs/<시각>/` (설정, 프로세스 상태, 실행 로그).
평가 결과: `eval/results/web_<시각>/` (기존 CLI의 manifest, packets, judgments, CSV, 보고서, figures).
웹 서버 재시작에도 평가 worker가 살아 있으면 진행 중인 평가를 다시 조회·중단할 수 있다. worker가 사라졌으면 중단 상태를 표시한다.

## 마지막 설정 복원 (2026-11-12)

신규 내담자 선택 이름은 `Q3cm`, `Q3cm_split`, `Q3cm_temporal`, `Q3cm_state`, `Q3cm_tools`, `Q3cm_review`, `Q3cm_full`이다. 기존 `cm_*` 배치·세션은 원래 이름 그대로 열고 재개할 수 있다. 평가 목록에는 실제 배치에 기록된 이름을 표시한다.

조합별 대량생성, 기존 `/batch`, 평가 탭은 각자 마지막 입력을 브라우저 localStorage에 저장한다. 생성 버튼을 누르지 않은 입력도 저장한다. 프로필 폴더와 선택 파일, 버전·상담사별 조건, 서버·모델·생성 옵션, 평가 대상·병렬 수·반복·시간제한·준비만 옵션을 복원한다. 평가 모델/effort는 현재 서버 설정을 따른다. 저장된 프로필 폴더가 없어졌으면 오류를 표시하며 입력과 작업 목록은 유지한다. 프로필 선택은 확인된 폴더 경로에 연결한다.

저장은 같은 브라우저·같은 접속 주소 기준이다. 브라우저 저장소를 삭제하거나 다른 브라우저·주소로 접속하면 공유되지 않는다. 이미 만들어진 배치의 고정 설정은 변경하지 않는다. Python 변경 반영을 위해 서버 재시작 후 페이지를 새로고침한다.
