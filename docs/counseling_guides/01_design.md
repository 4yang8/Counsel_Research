# P3 상담 가이드: 접근 선택과 다음 행동 선택 설계

작성일: 2026-10-16

상태: 대화에서 합의한 방향과 검토할 사항의 기록. 이 문서는 모델에 주입하지 않는다. P3는 별도의 네 가이드 파일을 조회 도구로 읽는다.

## 1. 목적과 현재 위치

P3는 공개 대화와 두 Markdown 노트로 상담 상황을 파악하고, 같은 상담사 LLM이 Common / MI / CBT를 재평가하는 실습이다. `update_notes(target, edits)`로 내담자 정보와 상담사 생각·작업 기록을 수정한다. Python은 파일 저장과 기술적 검증을 담당한다.

현재 P3 모델에는 접근 선택 기준이 짧게 주어져 있으며, `read_counseling_guide(guide)`로 선택한 가이드 파일 전체를 조회한다. 근거 조사 내용은 기법 선택 및 Common / MI / CBT 활용 가이드 파일로 분리했으며, 관리 정보와 출처는 조사 문서에 보존한다.

## 2. 접근별 구분과 내용의 중첩

가이드 검색·호출을 위해 Common / MI / CBT로 나눈다. 이 구분은 프로젝트의 라우팅 단위이다. 공감, 반영, 요약, 협력처럼 여러 접근에서 사용하는 역량은 겹칠 수 있다.

- Common: 공통 상담 역량을 이용한 탐색·지지·명료화·방향 협의 등의 묶음.
- MI: 변화 동기·양가감정·자율성 등을 다루는 접근의 가이드.
- CBT: 합의된 인지·행동 작업을 수행하는 접근의 가이드.

공통 행동을 사용했다는 이유만으로 접근이 자동 변경되지는 않는다. 같은 행동도 현재 목적과 사용 방식에 따라 역할이 다를 수 있다.

## 3. 세 가지 판단 수준

| 수준 | 판단할 질문 | 산출물의 의미 |
|---|---|---|
| 접근 선택 | 지금 어떤 접근이 적절한가? | Common / MI / CBT 중 현재 중심 접근 |
| 다음 행동 선택 | 이 접근에서 이번 발화는 무엇을 할 것인가? | 반영, 정리, 명료화, 추가 탐색, 방향 협의 등 현재 필요한 행동 |
| 행동 수행 | 그 행동을 어떻게 실제 발화로 구현할 것인가? | 내담자에게 말할 자연스러운 상담 발화 |

세 수준은 구분해 관찰하되, 각각을 별도 에이전트나 도구로 분리해야 한다는 뜻은 아니다. 단일 상담사 LLM과 도구 호출 흐름 안에서 수행할 수 있다.

## 4. 컨텍스트와 가이드 조회의 역할

현재 P3 시스템 지침의 흐름:

```text
공개 대화 + 두 노트 + 짧은 접근별 설명·선택 기준
  → 선택 판단이 애매하면 routing 조회
  → 현재 중심 접근 선택
  → 해당 접근의 활용 가이드 조회
  → 기존 정보와 내담자 반응을 보고 다음 행동 선택
  → 필요하면 노트 수정
  → 상담 발화 생성
```

접근 선택에 필요한 최소한의 설명은 처음부터 제공한다. 모든 선택 기준을 조회 뒤에 숨기면 어떤 가이드를 읽어야 하는지 판단할 근거가 부족해진다. 상세 수행 방법·주의사항·예시는 필요할 때 불러오는 후보이다.

같은 턴에 읽은 가이드는 반복 조회하지 않고 결과를 참고하도록 안내한다. 가이드 결과는 같은 턴의 후속 호출에 누적하고 다음 턴에 자동 재주입하지 않는다. 같은 턴 reasoning 보존과 매 턴 노트 파일 재주입은 유지한다. 실제 도구 호출 여부·순서는 모델이 판단하며 Python이 강제하지 않는다.

## 5. 상세 가이드에 필요한 내용

| 항목 | 포함할 내용 |
|---|---|
| 목적과 적용 맥락 | 무엇을 돕기 위한 접근이고 어떤 상황에서 고려하는가 |
| 가능한 행동 | 해당 접근에서 할 수 있는 대응과 각 기능 |
| 다음 행동 선택 기준 | 현재 필요, 이미 확보한 정보, 이전 대응과 실제 반응에 따라 무엇을 선택하는가 |
| 수행 원칙 | 선택한 행동을 발화로 구현하는 방법과 피할 오용 |
| 반응에 따른 조정 | 유지·수정·명료화·보류·전환을 고려할 단서 |
| 근거와 범위 | 출처, 해당 절, 원래 적용 대상, 한계 |

상세 가이드를 단순한 기법 소개나 질문 예문 목록으로 만들지 않는다. Common을 유지해도 다음 행동은 달라질 수 있어야 한다. 기법을 바꿔도 동일한 질문 패턴을 반복한다면 현재 문제를 해결한 것으로 판단하지 않는다.

## 6. 예시: Common 안에서 행동 바꾸기

다음은 구조를 설명하는 실습 예시이며, 원문 매뉴얼에서 가져온 상담 예문은 아니다.

```text
확인된 내용: 발표에서 실수하면 타인에게 부정적으로 평가받을까 걱정함.
아직 확인하지 않은 내용: 오늘 어떤 도움을 원하는지.

접근 선택: Common을 유지.
다음 행동 선택: 같은 두려움을 더 세분화하기보다, 원하는 도움을 확인.
수행 예시: "발표에서 실수했을 때 사람들이 어떻게 볼지가 특히 걱정되시는군요.
            오늘은 이 걱정을 이야기하면서 어떤 도움을 받고 싶으세요?"
```

항상 이런 질문으로 이동하거나 일정한 탐색 횟수 뒤에 진행하도록 강제한다는 뜻은 아니다.

## 7. 원문 근거와 실험 설계 구분

상세 가이드의 내용을 다음과 같이 구분한다.

1. **원문 근거:** 공식 매뉴얼·전문기관 자료가 설명하는 원칙과 수행 방법.
2. **LLM 실습 적용안:** 원칙을 텍스트 기반 단일 세션·한 번의 발화 단위로 해석한 방법.
3. **프로젝트 실험 규칙:** 호출 시점, 기록 형식, 출력 길이, 예산 등 구현을 위해 추가한 규칙.

예를 들어 원문이 협력적 의제 설정을 설명하더라도, "탐색 질문 세 번 뒤 반드시 목표를 묻기" 같은 횟수 규칙은 별도 실험 설계이다. 근거 자료에 없는 임계값이나 전환 규칙을 공식 지침처럼 제시하지 않는다.

## 8. 확인할 효과와 미정 사항

- 같은 접근 안에서도 맥락에 맞게 행동을 바꾸는가?
- 이미 들은 정보를 사용하고, 추가 질문의 필요성을 구분하는가?
- 노트에 적힌 다음 방향이 실제 발화에서 수행되는가?
- 내담자의 실제 반응에 따라 작업을 유지·조정하는가?
- 접근 이름과 실제 행동을 따로 검토했을 때 가이드 활용이 드러나는가?

상세 가이드가 반복을 줄인다는 것은 아직 검증하지 않은 가설이다. 비교 실험에서는 기존 P3를 보존하고, 가이드 제공 이외의 변경을 최소화한다.

조사 결과는 [02_evidence_review.md](02_evidence_review.md)에 정리한다.
